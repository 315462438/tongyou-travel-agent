# Phase 70/71 — 邀请码注册 + 长任务等待体验

## 背景

用户反馈两件事：
1. 注册是开放的，任何人注册即拿到沙箱执行 + 深度研究（资源模型撑不住，见 Phase 68 审计）。
2. **深度研究要等 5-6 分钟，很多用户以为程序卡死就退出了**。

第 2 条是本期重点。诊断结论：**问题不是「久」，是「不知道还要多久」+「中间有静默空隙」**。
工具调用期间进度是有信息的（`🔎 搜索：xxx`），但模型长推理和写终稿时会静默一两分钟，
前端只能显示「已有 N 秒没有新消息」——这句话本身就在暗示「可能挂了」。

## Phase 70：邀请码注册

- `settings.register_invite_code`，留空=开放注册（本地开发/存量行为不变）；
  线上 `.env` 配 `REGISTER_INVITE_CODE` 开启。
- 只管注册，**登录不校验**——13 个现有用户不会被锁在外面（有测试保证）。
- 前端注册 tab 增加「邀请码 · INVITE」字段。

## Phase 71：等待体验四件套

### ① 快答先行（收益最大）
深度研究启动后立刻用 **v4-flash** 给一份 150 字内的初步判断（无浏览器、无来源），
用户 15 秒就有东西读；完整版随后照常产出。`meta.preliminary=true`，前端渲染橙色徽章
「💡 初步判断 · 正在查证实时资料，完整分析稍后送到」。

> ⚠️ **顺序不变式**：流式占位必须在快答**之前**建立。快答是一条非流式 assistant 消息，
> 若此时没有流式占位，`_is_running` 会判本轮完成 → 前端停止轮询 → 完整版永远收不到
> （同 Phase 14 那个坑）。双保险：`_is_running` 也显式把 `meta.preliminary` 排除在终稿之外。

纯增强：`deep_research_quick_take` 可关；生成失败/被停止都不影响主流程。

### ② 进度报「发现」而非「动作」
`research_tools._found()` + `_gist()`：工具每返回一批结果就播一条带实质内容的进度
（`🔎 搜到 6 条：成都三日游、重庆 vs 成都…`、`📕 宽窄巷子：人均 80 元，建议避开周末`）。
前端把历史进度渲染成**足迹列表**（`.thinking-trail`，最近 5 条、越旧越淡），
等待期从「干等」变成「阅读」，同时是「它还活着」的持续证据。

### ③ 预期管理
`interaction.ts` 新增 `THINKING_EXPECTED_SEC`（深度推理 330s / 手账 75s / 规划 140s）、
`thinkingProgressRatio()`（超时后不回退不满格，缓慢逼近 1）、`waitReassurance()`（分段文案）。
UI 显示「通常 4-6 分钟」+ 一条对照预期推进的进度条（超时变琥珀色）。

### ④ 明确可以离开
静默文案改为「正在深入思考中（这一步没有中间进度，属正常）。**可以关掉页面**，
任务在服务器继续跑，完成后回来在这条会话里就能看到。」触发阈值 30s → 45s。
早期安抚文案也带上「可以关掉页面，完成后在历史里查看」。
