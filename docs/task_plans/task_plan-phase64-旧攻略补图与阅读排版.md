# Phase 64：旧攻略补图与阅读排版

## 目标

1. 用户对旧攻略提出“补图、配图、图文版”等要求时，不能只改标题或文案，必须真正取得图片并写入正文。
2. 旧来源没有 `images` 时，按当前目的地刷新小红书公开笔记图片，并与已有来源安全合并。
3. 攻略从连续文字墙优化成易扫读的标题、每日路线、信息卡、表格和图片节奏。
4. 修复当前线上“吉隆坡 + 仙本那 + 亚庇”这条已经生成但仍为 0 图的回复。

## 方案

### 补图闭环

- 增加图片意图识别（图片/配图/图文/含图/补图/照片/实景）。
- 多轮修改命中图片意图且已有来源图片少于 3 张时，强制调用小红书图片采集，不走普通“直接复用旧来源”。
- 按 URL 合并刷新来源：同 URL 补齐 `images`，新命中的有图来源追加，原摘要与非小红书来源保留。
- 生成前检查图片上下文；模型漏放占位符时继续使用确定性的跨章节分散兜底。

### 阅读排版

- 收紧攻略 Markdown 输出结构：总览用引用卡，每天固定“路线概览 → 时段安排 → 当日提醒”，
  避免层层嵌套的长列表。
- 每日核心安排优先用四列表格（时段/地点与体验/交通与停留/参考花费），详细提示放在表格后。
- 前端 `GuideBody` 为攻略标题、Day 标题、普通章节、表格、图片增加专用语义类与响应式样式。
- 手机端表格可横向滚动，图片自适应，标题卡缩小边距。

## 验收标准

1. “补一下各个行程中的图片”可被确定识别为图片刷新意图。
2. 旧的 0 图小红书来源经刷新后至少形成 3 张图片上下文。
3. 同 URL 来源只补图片不重复；新有图来源可追加；无效空图不污染来源。
4. 终稿即使模型没有主动输出图片占位符，也能把图片分散插入不同 Day/章节。
5. 攻略标题、Day 标题、普通章节、表格和图片在桌面/手机均有清晰层级。
6. 当前线上目标回复回填图片后，正文 Markdown 图片数大于 0，图片代理返回 200。
7. 后端全量测试、前端测试、lint 与 production build 全部通过。
