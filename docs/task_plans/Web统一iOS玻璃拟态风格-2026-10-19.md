# Web 端统一为 iOS 玻璃拟态风格

- 日期：2026-10-19
- 目标：把 `frontend/`（Web）的视觉统一成 iOS App（`ios/Tongyou`）那套 **Liquid Glass + 三色光晕**风格；
  **只保留一套主题**（移除 Phase 107 的 modern/ink 双主题切换），与 iOS 端保持一致。
- 涉及：`frontend/src/index.css`、`frontend/src/pages/Home.tsx`、`frontend/src/Auth.tsx`、
  `frontend/src/interaction.ts`、`frontend/tests/visual-regressions.test.mjs`

## 背景

用户判断：iOS 端（原生 SwiftUI + Liquid Glass）的视觉是想要的方向，Web 端要跟它统一。
主色其实已经一致（Web `--x-sky` = `#2563EB` = iOS `Palette.sky`），缺的是三件东西：

| iOS 端 | Web 现状 |
| --- | --- |
| `Backdrop`：浅底 + 3 个大模糊彩色圆（sky `#2563EB` / dusk `#6B5CF2` / warm `#FA9E5C`，blur 90–100） | 只有局部 `.hero-soft-glow` |
| `glassEffect(.regular/.interactive)`：模糊 + 折射 + 内高光 | 实底卡片（142 处 `background: var(--x-n100)`） |
| 卡片圆角 24–30px、输入框胶囊 50px 高 | 圆角 6/10/16/999 四级，偏硬 |

用户决定：**只留一套主题**，不要切换按钮。

## 方案

### ① 材质层（新增 token，不动既有阶梯）

`index.css` `:root` 追加玻璃材质 token（保留 `--x-n*` 灰阶 / `--x-sky*` / `--x-day-*` /
间距字阶，它们已被 Phase 107 收敛好）：

```css
--x-aura-sky:  rgba(37, 99, 235, .22);
--x-aura-dusk: rgba(107, 92, 242, .16);
--x-aura-warm: rgba(250, 158, 92, .14);
--x-glass:      rgba(255, 255, 255, .62);
--x-glass-line: rgba(255, 255, 255, .55);
--x-glass-blur: 24px;
--x-glass-inner: inset 0 1px 0 rgba(255, 255, 255, .8);
--x-glass-shadow: 0 10px 34px -12px rgba(37, 99, 235, .18);
--x-r-xl: 24px;   /* iOS 卡片 24–30 */
--x-r-2xl: 30px;
```

并新增通用材质类：`.glass`（卡片）/`.glass-pill`（胶囊）/`.glass-input`（50px 高）/
`.glass-primary`（sky 渐主按钮），供组件逐步套用。

### ② 背景层

`.app` / `.auth-sky` 用**固定定位的 radial-gradient 光晕层**（比 3 个 `blur(90px)` div 省性能）：

```css
background:
  radial-gradient(420px 420px at 12% 6%, var(--x-aura-sky), transparent 70%),
  radial-gradient(360px 360px at 88% 34%, var(--x-aura-dusk), transparent 70%),
  radial-gradient(340px 340px at 72% 94%, var(--x-aura-warm), transparent 70%),
  var(--x-n96);
```

`.hero-soft-glow` 保留但降为辅助（避免破坏 `visual-regressions` 断言，见 ④）。

### ③ 移除双主题

删除：`themeMode` 状态与 localStorage、顶栏「现代主题/水墨主题」按钮、`interaction.ts` 的
`initialThemeMode`、`index.css` 里 `.theme-ink` 整段（8653 行起 ~700 行）、`ink-landscape.webp`
引用。`app` 根节点 class 只留 `view-{layoutMode}`。

### ④ 测试同步

`frontend/tests/visual-regressions.test.mjs` 用正则钉了 `.hero-soft-glow` 的
`radial-gradient`+`animation`、`.hero .hero-title` 的渐变文字等。改造后**逐条更新断言**，
并新增：玻璃 token 存在、`.glass-card` 带 `backdrop-filter`、`.theme-ink` 已不存在。

### ⑤ 降级与坑

- `@supports not (backdrop-filter: blur(1px))` → 实底（`--x-glass` 提到 .94 不透明）
- `prefers-reduced-transparency: reduce` → 减弱模糊/加实底
- **全屏 modal 必须 portal 到 body**（已有踩坑：`docs/pitfalls/backdrop-filter吞掉fixed定位与http下clipboard失效.md`）
- 性能：全站玻璃后低端机会掉帧，光晕用 radial-gradient 而非大 blur div

## 分阶段

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| 1 | 材质 token + 光晕背景 + 移除双主题 | 登录页/首页背景变光晕；主题按钮消失；构建通过 |
| 2 | 登录页（登机牌 → iOS 玻璃登录卡）+ 首页空态（hero/输入卡/城市胶囊/热门卡） | 与 iOS `LoginView`/`HomeView` 视觉对齐 |
| 3 | 会话页：消息气泡、composer、思考行、来源/记忆卡 | 玻璃材质统一 |
| 4 | 其余面板：协同行程、记账、同游圈、我的、管理、客服 | 逐块替换 + 回归 |

## 验收标准

1. Web 与 iOS 端视觉语言一致（光晕背景 + 玻璃卡 + 大圆角 + sky 蓝主色）；
2. 双主题开关与 `theme-ink` 代码全部移除，无残留引用；
3. `npm run build` 通过、前端测试全绿（含更新后的 visual-regressions）；
4. 关掉 backdrop-filter（用 `@supports` 模拟）时页面仍可读（实底降级）；
5. 登录页 / 首页 / 会话页在手机宽度（390px）下无横向滚动、无遮挡。

## 玻璃覆盖率（2026-10-19 收尾核对）

- `backdrop-filter` 规则：43 处 → **112 处**
- **有光晕可透的页面**：首页、会话页（`.app::before`）、登录页（`.auth-aura`）、社交全屏页 → 玻璃是真玻璃
- **有意保持实底**：协同行程工作台（`.trips-overlay` 白底 + 密集表格，玻璃化会伤害可读性）、
  记账明细表单、各处输入框与表格行。这些容器里的玻璃卡在白底上等价于白卡（无害但不出效果），
  后续若要出效果应先把容器底改成光晕或半透明，而不是给卡片加更多模糊。

## 评审问题修复（2026-10-19）

目标：保留现有单主题 iOS 风格，修复实际浏览器确认的五项回归：日期浮层铺满页面、桌面编辑抽屉压至 460px、SVG 图标解析失败、浅底白字、减少透明度未覆盖独立组件。
方案：日期编辑通过 body portal 独立定位，桌面锚定日期按钮、手机按视口边距展示，保持保存/取消/Escape；恢复抽屉桌面宽度、清理旧 max-width 及默认 padding，内部独立滚动；清理 SVG 非法注释；移除登录旧白字与阴影；系统减少透明度时统一关闭所有背景模糊并提升玻璃底色不透明度。
涉及：Auth/Trips/index.css/Ledger.css/favicon.svg 与浏览器测试。
验收：登录图标 naturalWidth > 0、标题副标题深色；日期浮层有底色、不溢出且桌面跟随按钮；编辑抽屉桌面宽度 ≥680px、手机贴边、控件完整可见；减少透明度下弹窗/导航/记账无模糊；前端单测、构建、双视口行程与记账回归通过。此次为网页修复，不涉及 iOS 原生或数据库变更。

评审修复完成：构建通过，100 项前端单测通过；登录玻璃样式、行程工作台、记账三组浏览器回归均在桌面/手机尺寸通过。补充修复抽屉费用单选尺寸、减少动效及底栏遮挡。截图人工核对通过。结果见 docs/test_cases/Web玻璃风格评审修复结果-2026-10-19.json。此次未部署或推送，保留原重构及其他未提交文件。
