# Task Plan — Phase 46：全前端交互体验优化

## 目标

在不改变现有产品信息架构和核心视觉语言的前提下，系统性优化登录、首页对话、侧栏、
消息输入、协同行程板和移动端的交互体验，使操作状态更明确、键盘和触屏使用更顺畅，
减少误操作、无反馈等待和小屏遮挡。

## 方案

### 1. 全局交互基础

- 统一按钮、输入框、卡片的 hover / active / focus-visible / disabled 状态；
- 增加可复用的轻量 Toast，成功、失败和提示不再依赖静默失败或浏览器弹窗；
- 尊重 `prefers-reduced-motion`，为键盘用户补齐可见焦点；
- 校正移动端安全区、点击热区和滚动容器。

### 2. 登录与首页

- 登录支持 Enter 提交、密码显示切换、忙碌态和清晰错误反馈；
- 侧栏补移动端打开/关闭、遮罩、Escape 关闭和更明确的当前会话状态；
- 对话输入区补快捷键提示、自动伸缩、字数/发送状态和不可发送原因；
- 空态快捷卡片改为可直接填入或发送的明确交互入口。

### 3. 消息与异步任务

- 统一复制、导出、停止、生成海报等动作的即时反馈；
- 加强流式生成、轮询、错误和空结果的视觉状态；
- 避免仅靠颜色表达状态，补充文本与无障碍属性。

### 4. 协同行程板

- 优化桌面三栏与移动端分区切换，减少横向挤压；
- 把删除等危险操作从表达式副作用改成明确流程，并提供操作反馈；
- 修正 Hook 依赖告警，改善加载、空态、拖拽/移动和保存反馈；
- 保持互动地图、Copilot、评论、记账、分享现有功能契约不变。

## 验收标准

- 登录可用键盘完整操作，提交、错误、密码可见性均有明确反馈；
- 桌面端与 390px 宽移动端无关键操作遮挡或不可达；
- 侧栏、弹层可通过遮罩和 Escape 关闭，焦点样式清晰；
- 异步操作有 loading / success / error 反馈，危险操作必须二次确认；
- `npm run lint` 无警告，TypeScript 检查和生产构建通过；
- 新增可运行的前端自动化测试，并在 `docs/test_cases/` 留存验收用例；
- 后端既有测试保持全绿。
