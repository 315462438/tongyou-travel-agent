# iOS / Android 简版分享与同行邀请

用户补充：拥挤与不全的是 Android 攻略长图，空白的是 iOS；Android 的交互也需要变得更流畅。本计划同步覆盖两端，以此处为准。

## 目标

修复 iOS 攻略导出空白、Android 长图过长拥挤与截断的问题；两端参考用户提供的短计划单，以标题、逐日地点和时间为主。协同行程成员邀请改为有行程卡片、清晰权限说明与轻量反馈的邀请面板。

## 方案与模块

- `GuideExporter`：分享长图独立于聊天 Markdown 排版，确定性本地提取逐日表格/路线/时间，不额外调用模型，不编造时间；先预览，再系统分享或保存相册。内容多时分为多张卡，显示完整页数；完整 PDF 保留独立导出。
- 新增可测试的分享摘要模型、固定宽度静态卡片；逐日条目不静默丢弃，非行程正文提供可读摘要及完整 PDF 入口。
- 检查离屏渲染的尺寸与颜色，限制单张像素面积，验证图片实际非空白。
- `MembersSheet`：行程邀请卡、成员概览、用户名输入与单一发送入口；发送中防重复、失败保留输入、成功反馈，仍复用原有接受后授权协议。无需创建新公开链接或模拟微信专属分享。
- 动效采用原生弹簧入场、卡片轻微拖动回弹、按钮按压与成功图标反馈；Reduce Motion 下关闭位移和倾斜。
- Android：共享前端新增简版分享卡与预览，替换 Android 的全文截图导出；协同行程邀请浮层与原生壳内按压/弹层/切换动画，兼容 Reduce Motion。保留完整文字/PDF获取途径。
- 邀请链接复用现有后端 `/trips/{id}/share`，仅用户点击时创建/分享，明确持链接者可加入编辑，不伪造 24 小时有效期；提供关闭入口。用户名邀请仍待对方接受。
- 分别构建发布 iOS 与 Android，更新发布记录；不隐式部署 Web 或业务后端。

## 验收

1. 自动化覆盖多日/表格/无时间/无结构/超长内容，保留末日与最后地点，输出无 Markdown 图片 URL 噪声。
2. 模拟器渲染图片尺寸与非白像素验证，检查短卡和多页卡最后一页；完整 PDF 有效。
3. 预览可滚动、分享/保存有错误提示，导出失败不静默结束。
4. 邀请页深浅色、发送前/成功/失败、减少动态及输入去空格/防重复覆盖；测试数据不请求生产接口。
5. iOS 构建、相关自动化测试全部通过，检查截图后覆盖安装真机并验证启动。
