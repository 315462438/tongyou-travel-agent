# Task Plan · 新用户开口率改造（2026-08-05）

## 问题（来自 08-04 新用户群的真实数据）

12 个新注册用户里 **4 个（33%）一个字都没问就走了**。这是整条漏斗里唯一的**纯损失**——
不是攻略不好，是他们**根本没开口**。

其余 8 个提问的用户**全部**拿到了 3000-10000 字的完整攻略，没有报错、卡死或空回复。
所以问题不在产出质量，在**第一步的门槛**。

两个具体的诊断：

1. **示例全是成都**。首页 4 张 chip（筛选酒店 / 规划路线 / 生成攻略 / 帮我做选择）
   写死了成都，而这批用户全是合肥、武汉的。示例离自己越远，越像「别人的产品」。
   真实数据佐证：他们实际问的是平潭岛、武功山、皖南、天堂寨、随县——没有一个是成都。
2. **空状态要求「想好了再问」**。输入框是一片空白 + 一句 placeholder，
   用户得自己组织出「从哪出发、几天、几个人、什么偏好」的完整句子才敢发。
   已提问用户的首问平均只有 29 个字，且 3/8 是「合肥周边」这种半成品——
   说明大家**不想也不会**一次说清。

## 方案

### 后端 `GET /api/onboarding`（登录）

```json
{
  "home_city": "合肥",              // 来自 memory key='常驻城市'，无则 null
  "trending": ["平潭岛", "武功山"],  // 平台最近 30 天真实用户规划最多的目的地
  "has_history": false               // 该用户是否已有过会话（决定空状态文案）
}
```

- `trending` 取自 `travel_conversation.destination`（finalize 时落盘），
  **必须排除 admin/evalbot/test\* 这些内部账号**，否则会被评估跑测刷成「成都」。
- 多城目的地（`武汉,开封,洛阳`）拆开取首城，避免出现一张念不出来的 chip。
- 任何一步失败都返回空数组 —— 空状态回退到静态示例，绝不因为它白屏。

### 前端空状态

1. **示例本地化**：有 `trending` 时用它生成 chip（「平潭岛 3 天怎么玩」），
   并在有 `home_city` 时带上出发地（「合肥出发去平潭岛」）。无数据回退现有静态 chip。
2. **「不知道去哪」三下起步**：一行快捷选择（出发地 / 玩几天 / 和谁），
   点完自动在输入框组装成一句完整的话，用户可直接发或继续改。
   目的是把「憋一句完整需求」降级成「点三下」。

纯函数（`interaction.ts`）：`buildQuickPrompt()` / `buildTrendingChips()`，可单测。

## 边界

- **不做**定位/IP 归属地推断（要权限、易出错、且本批用户高度集中在合肥武汉，
  平台热门榜已经足够本地化）。
- 热门榜是**平台级**而非个人级：新用户本来就没有个人数据，这里要的是「别人在查什么」
  的社会证明，顺带把示例拉到本地。
- 不改攻略生成链路，只改入口。

## 验收

- `tests/test_onboarding_api.py`：内部账号被排除、多城拆首城、无数据返回空、需登录。
- 前端：`buildQuickPrompt` / `buildTrendingChips` 单测；空状态回退不白屏。
- 人工：新账号首屏能看到本地化示例与三下起步。
