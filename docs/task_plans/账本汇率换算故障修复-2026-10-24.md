# 账本汇率换算故障修复

## 目标

修复用户截图中账本以 SGD 汇总 CNY 支出却提示缺失汇率的问题，确保原币金额与可追溯的最新参考汇率能正确换算。

## 方案与范围

1. 对照 Frankfurter 官方接口，检查当前服务端请求、返回解析、行情日期、缓存及异常行为；从本地与生产服务环境复现。
2. 根据实际故障修复共享后端的汇率读取或缓存逻辑，保持 conversion 接口与三端已安装版本兼容。除非证据表明必要，不修改客户端。
3. 金额使用 Decimal 与整数分，缺失汇率不伪造总额；保留来源、行情日期、查询时间及缓存降级说明。
4. 通过针对性自动化测试后，按最小范围更新共享后端，核对线上文件与真实汇率返回、健康检查，留存回退与验收记录。

## 验收

- CNY → SGD 与 SGD → CNY 能取得真实汇率并正确换算；验证多币种、同币种、空账本。
- 非法数值、异常记录、过期行情、接口失败和部分缺失不产生误导性的完整总额。
- 缓存命中、手动刷新、短时故障使用有效缓存与失败后恢复均有自动化测试。
- 既有账本接口测试通过，旧版 iOS / Android / Web 字段兼容，生产环境复核通过。

## 定位与最终方案

生产 UTC 日期为 2026-10-24；Frankfurter 对 SGD/CNY 正常返回 HTTP 200、行情日期 2026-10-25。原实现仅允许非未来日期，导致正常记录被全部过滤。本地与生产环境均复现；官方 2.4.0 变更说明明确允许提前一天发布的观察值。

统一新请求与缓存的行情日期检查：仅接受 UTC 当日前 7 天至后 1 天，不改写上游真实日期，继续拒绝更远未来与过期值。逐条隔离异常币种记录，防止一个坏值丢弃其他有效汇率。仅修改 `backend/app/tools/ledger_fx.py`；接口、客户端和整数分换算保持兼容。

先加回归用例，旧实现 9 失败 / 13 通过，随后修复；最终账本四组后端测试共 69 项通过。

## 完成与发布

已完成本地及生产各 3 组真实汇率验证，单文件部署上线、后端与公开 HTTPS 健康检查通过，未登录账本仍返回 401。上线前确认近期在途 Agent / 导入任务为零，保留原模块备份与失败回退流程。没有修改或重装客户端。
