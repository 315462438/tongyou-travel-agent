# Phase 62：海外行程坐标修复

## 背景

协同行程板当前统一通过高德国内 POI 搜索补坐标。海外目的地（例如吉隆坡、仙本那、亚庇）
在当前 Key 未开通高德海外 Web Service 权限时，会把中文地名误匹配到中国境内同名或近似
地点。错误结果随后写入 `travel_geocode`，导致地图散落全国、逐段里程和检查中心结论全部失真。

高德底图本身可以展示海外；本阶段修复的是地理编码、结果校验和海外路径能力降级，不替换地图组件。

## 目标

1. 国内行程继续使用高德，保持现有效率和数据质量。
2. 海外城市先解析国家与城市锚点，再使用全球地理编码，并以国家和城市距离约束候选结果。
3. 国内高德候选必须校验其行政区与查询城市一致，禁止把不相关的国内同名结果写入缓存。
4. 缓存按版本、数据源、国家、城市隔离，海外请求不读取 Phase 55 的旧国内缓存。
5. 为已存在的错误坐标提供“重新定位全部地点”能力；新结果找不到时清除旧的可疑坐标，
   宁可显示“未定位”也不继续展示错误路线。
6. 海外地点不调用只适用于国内 Key 的高德路径规划；回退为直线距离估算并明确标注。
7. 对一天内多个异常超长跳点给出专门的坐标告警和修复入口。

## 方案

### 1. 全球地理编码适配

- 新增 `app/tools/geocode.py`：
  - 使用 Open-Meteo/GeoNames 解析城市上下文，使用 Photon/OSM 搜索海外 POI；
  - Photon 只索引 default/de/en/fr，攻略抽取同时生成英文/当地官方 `search_name`，
    已有常见中文地点走确定性别名；
  - 请求携带可识别的 `User-Agent`，全进程串行并限制为最多 1 req/s；
  - 城市上下文记录 ISO 3166-1 alpha-2 国家码、城市锚点；
  - POI 查询通过 `countrycodes` 限定国家，并要求候选距城市锚点不超过合理阈值；
  - 服务 URL 与 User-Agent 可通过环境变量覆盖，以便后续切到自托管或商业实例。

### 2. 国内/海外路由与缓存

- `geocode_names` 先解析城市上下文：
  - `country_code == cn`：高德 POI；
  - 其他国家：全球地理编码；
  - 城市上下文暂时解析失败：高德结果仍需行政区文本匹配才可采纳。
- 新缓存键使用 `v2|provider|country|city|name`，避免读取旧的海外误命中。
- 城市上下文用独立缓存键保存，降低公共服务请求量。
- `overnight_city` 只作为每天的首选城市；转移日主城市未命中的地点会在本行程其他城市
  中依次受 country + 120km 约束重试，覆盖“上午吉隆坡、下午飞仙本那”这类跨城日。
- 地点名本身就是城市/城镇时直接使用已验证城市锚点，避免搜索服务返回郊外同名点。

### 3. 已有数据修复

- 新增 `POST /api/trips/{trip_id}/geocode/repair`：
  - 复用逐日城市提示，按天/城市重新定位；
  - 强制绕过地点缓存；
  - 成功则覆盖坐标；失败且旧坐标可疑则清空；
  - 返回更新、清除、未解析数量，并写协作事件。
- 前端地图工具区增加“重新定位”按钮；检查中心发现异常坐标跨度时可直接触发修复。

### 4. 海外路径降级

- `segment-times` 仅在同一日地点明确属于国内时调用高德路径接口。
- 海外或数据源不确定时返回 haversine × 经验系数的估算距离、按交通方式估算时长，
  并带 `estimated=true`/说明，前端展示“估算”而不是伪装成高德真实路线。

## 验收标准

1. “吉隆坡 / 仙本那 / 亚庇”被识别为马来西亚城市，不再使用高德国内 POI 候选。
2. 海外 POI 候选必须在马来西亚且距对应城市锚点处于阈值内。
3. 国内“成都 + 宽窄巷子”仍命中高德并正常缓存。
4. 海外与国内缓存键完全隔离；旧 `城市|地点` 缓存不会污染海外结果。
5. 修复接口能覆盖错误坐标，无法重新解析的条目会清除旧可疑坐标。
6. 截图中的多次跨省跳点会产生 `geocode` 告警，而不是仅被解释为长途驾驶。
7. 海外逐段时间明确标为估算，且不调用高德 direction API。
8. 后端新增自动化测试、前端交互测试与全量现有测试通过。
