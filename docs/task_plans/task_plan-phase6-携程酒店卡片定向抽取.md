## 背景

Phase 3-5 后携程列表页已能正确按城市打开，但酒店卡片是异步渲染的，
`take_snapshot` 抓到的主要是页面框架文字，具体酒店名/实时价格抓不全，
导致生成的酒店推荐仍是"经验值"而非真实数据。

## 方案

1. **等待渲染**：打开列表页后轮询（最长 ~12s），直到页面出现价格特征（¥+数字）。
2. **DOM 定向抽取**：`evaluate_script` 直读酒店卡片 DOM，返回结构化 JSON：
   `[{name, price, score, desc(位置/商圈)}]`，选择器以线上实测为准并做多重兜底
   （携程改版时退化为旧的整页快照路径，不报错）。
3. **来源构造**：抽取成功（≥3 家）时，来源 summary 直接用结构化清单
   （「全季酒店(春熙路) ¥450起 4.7分 锦江区…」），不再走 LLM 摘要——
   生成环节即可引用真实酒店名与价格；失败则回退 scroll_and_read + summarize。
4. 复用现有守卫与相关性校验，不改变登录墙/回退逻辑。

## 涉及模块

- `app/tools/browser_tool.py`：`extract_ctrip_hotels(top_n)`（含渲染等待与 JS 抽取）。
- `app/agent/site_router.py`：ctrip 分支优先走结构化抽取，失败回退原路径。
- 测试：JS 返回值解析/格式化、空结果回退（fake browser）；线上冒烟验证真实数据。

## 验收标准

1. 线上查「成都市中心的酒店」→ 携程来源 summary 含 ≥3 家真实酒店名和价格；
   生成的推荐引用这些酒店而非"无法引用资料"。
2. 抽取失败（DOM 改版/风控）时优雅回退，不阻塞、不报错。
3. 单测通过、存量不回归。
