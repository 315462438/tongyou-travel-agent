# Task Plan · 退役「当前行程」记忆槽，换确定性最近规划提示（2026-07-31）

## 背景与判断

线上 8 条 `trip_state` 记忆里 5 条 hit_count=0（从未注入），两条活跃的正是当日两个 bug 的
污染源（「国庆」「预算5000」泄漏进无关行程）。评估结论：

- **唯一不可替代的用途**：跨会话指代消解（新对话里说「帮我加一天」「那边冷不冷」而不报地名）。
  会话内有近 5 轮历史 + history_summary，不需要它；`recall_past_chats` 需要先知道目的地，也替代不了。
- **它干这活很差**：单槽即遗忘（只留最新一次）；时点事实伪装成长期偏好，日期/预算/人数
  会被生成端当成本次约束；5 个注入点里 4 个传 `destination=""`，目的地过滤在那 4 处不生效；
  而「最近一次规划的目的地」本来就能从会话数据**确定性推导**（`meta.preference.destination`）。
- 职责重叠：`旅行足迹`(fact) 已经在累积「去过/规划过的城市」，那才是跨行程复用的部分。

## 方案

| 项 | 改动 |
| --- | --- |
| 记忆槽 | `CANONICAL_KEYS` 删 `当前行程`；`EXTRACT_SYSTEM` 删单槽说明，改为「不要记具体某次行程」，并把「旧目的地并入旅行足迹」的表述改成不依赖当前行程槽 |
| 硬护栏 | `gather_context` 无条件剔除 `type == "trip_state"`（存量行/模型偶发新造都挡掉），删掉临时的 `filter_foreign_trip_memories` |
| 注入块 | `format_memories_block` 去掉 trip_state 过期警告分支；保留「记忆使用纪律」（日期/目的地/预算除非本轮重申不得写进回答）——`旅行足迹`/`预算偏好` 仍可能带地名与金额 |
| 新机制 | `recent_plan_hint(db, user_id, exclude_cid)`：查该用户**其它会话**里最近一条带 sources 的 assistant 消息，取 `meta.preference.destination` + 天数；超过 `recent_plan_hint_days`(14) 不给。输出**待确认指代**措辞，不是事实断言 |
| 注入点 | 仅 `parse_request`（决定 destination 的地方）与 `run_direct_answer`（「那边冷不冷」类）追加该提示；guide 生成端、deep research **不注入**（目的地已定，旧行程零增量、纯污染面） |
| 迁移 | `migrate.py` 幂等删除存量 `travel_memory` 里 `type='trip_state'` 的行 |

## 验收结果（2026-07-31 已上线）

- 后端 **587 例全绿**（新增 `tests/test_trip_memory_retire.py` 10 例；
  `test_memory_triplet`/`test_memory_upgrade` 里依赖 trip_state 的 4 例已改写为旅行足迹/explicit 语义）。
- 线上存量 `trip_state` 已清零（迁移执行后只剩 fact 8 / preference 16）。
- 指代消解实测：全新对话仅说「帮我在原来的行程上再加一天，多留一晚」（无任何地名）
  → 直接按「武汉」开始规划、不反问、搜索词为「武汉 旅游攻略」。
- 顺带清理：`settings.memory_trip_stale_days` 已删（随过期警告一起退役）。
- 设计记录见 `docs/dev_docs/记忆系统-行程类信息的归属决策.md`。

## 验收标准

- `tests/test_trip_memory_retire.py`：槽已移除、trip_state 被硬过滤、hint 生成/时限/跨会话
  排除/无数据返回空、措辞含「未指明目的地」限定语。
- 现有 580 例不回归（`filter_foreign_trip_memories` 的两条测试同步替换）。
- 线上：存量 trip_state 清零；新会话问「合肥→武汉沿途」不再出现国庆/5000；
  新对话说「帮我加一天」仍能接上最近一次规划的目的地。
