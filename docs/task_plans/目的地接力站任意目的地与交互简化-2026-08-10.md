# Phase 82 · 目的地接力站任意目的地与交互简化

日期：2026-08-10

## 问题

Phase 81 首版把天堂寨、杭州等目的地做成固定标签，虽然接口本身支持任意目的地，但界面没有自由
输入入口，用户会理解成“只能接力天堂寨”。页面同时展示大幅标题、三张统计卡、目的地标签、四个
阶段筛选和两个发布下拉框，首屏存在重复信息，主任务不清楚。

## 目标

把接力站收敛为一条无需学习的流程：

1. 输入或搜索任意目的地；
2. 浏览该目的地的公开动态；
3. 用“提问题 / 报现场 / 分享路线”三选一发布。

## 方案

- 用一个醒目的目的地搜索框替代固定目的地标签，保留少量“最近目的地”快捷项；
- 输入框按 Enter 或点击“进入”加载任意目的地，空值不请求；
- 去掉大幅统计 Hero 和三张重复统计卡，改成紧凑标题、当前目的地和总动态数；
- 阶段筛选默认只显示“全部 / 准备去 / 正在玩 / 刚回来”，移除解释性副标题；
- 发布器不再要求用户理解“阶段 + 类型”两套概念：
  - 提问题 → 自动归为准备去；
  - 报现场 → 自动归为正在玩，并保留 72 小时有效期；
  - 分享路线 → 自动归为刚回来；
- 发布器允许再次修改目的地，避免先切站后发错地方；
- 好友和个人主页保持不变；移动端把搜索、筛选和发布按钮保持在第一屏。

## 涉及模块

- `frontend/src/components/SocialHub.tsx`
- `frontend/src/index.css`
- `frontend/tests/visual-regressions.test.mjs`
- Phase 82 对应测试与踩坑文档

后端 `GET /api/social/station?destination=` 和 `POST /api/social/posts` 已支持任意目的地，本次不新增表。

## 验收标准

1. 用户能输入“黄山”等非预设目的地并进入对应接力站；
2. 点击快捷目的地仍可立即切换；
3. 首页核心控件顺序为目的地搜索、三类发布入口、动态列表；
4. 发布三类内容时阶段映射正确，现场情报仍为 72 小时；
5. 桌面和移动端无横向溢出，键盘 Enter 可搜索；
6. 前端测试、lint、生产构建与后端全量回归通过后部署。

## 实施结果

- 已用任意目的地搜索框替换固定目的地入口，支持 Enter 和按钮加载；
- 已把固定城市降级为快捷入口，不再暗示功能边界；
- 已删除重复的大幅统计 Hero，首屏按“搜索 → 发布 → 动态”排序；
- 已将“阶段 + 类型”两个下拉框合并为三种自然语言动作，并自动映射阶段；
- 发布器可独立修改目的地，避免内容误发到当前浏览站点；
- 已完成移动端单列与横滑快捷入口适配；
- 前端 58 项测试、lint、生产构建通过；后端 781 项回归通过。
