# Phase 65：移动端 UI 重构

## 目标

1. 手机端不再是桌面界面的简单压缩版，而是拥有独立导航、内容层级和触控交互的移动工作台。
2. 右上角提供“网页端 / 移动端”布局切换，手机首次访问默认移动端，偏好本地持久化。
3. 对话、长攻略、输入框、历史会话、协同行程与管理抽屉在常见手机宽度下均可用。
4. 桌面端保持现有三栏/侧栏体验，不因移动版重构产生回归。

## 信息架构

### 移动端

- 顶部：菜单、当前会话标题、网页端/移动端切换。
- 主内容：单列消息流；长攻略使用紧凑标题卡、Day 卡、可横滑表格和全宽图片。
- 底部：新对话、协同行程、历史、记忆四个主入口。
- 输入：贴底编辑器，模式开关横向滚动，避开 iPhone safe-area 与底部导航。
- 历史：左侧全高抽屉；关闭状态使用位移而不是宽度归零，减少闪烁和布局抖动。
- 二级管理：记忆/技能/调用链使用底部 Sheet 或全屏抽屉。

### 网页端

- 保留左侧会话栏 + 中间内容工作区。
- 顶部右侧显示布局切换；选择移动端时进入居中的手机预览宽度。

## 适配范围

- 360 / 390 / 430 px 手机宽度。
- iOS `safe-area-inset-top/bottom`。
- 软键盘弹出时输入区可见、消息区可滚动。
- 长标题、长表格、图片、来源列表、思考状态和消息操作按钮不横向溢出。
- 协同行程继续使用“行程 / 地图 / 助手”单面板切换。

## 验收标准

1. 页面右上角可切换“网页端 / 移动端”，当前状态有明确选中态并写入 localStorage。
2. 手机首次访问默认移动端；桌面首次访问默认网页端。
3. 移动端有固定顶部栏与四项底部导航，触控目标至少约 40px。
4. 移动端侧栏是可关闭的全高抽屉，不占据正文宽度。
5. 消息区、攻略图片和输入框均不产生页面级横向滚动。
6. 底部输入框与导航不互相遮挡，并支持安全区。
7. 协同行程、记忆、技能、调用链入口在移动端可达。
8. 前端 Node 测试、lint、TypeScript 与 production build 全部通过。

## 实施结果

- 已增加 `desktop / mobile` 视图状态和 localStorage 持久化；窄屏或粗指针设备首次访问强制使用移动端，防止桌面偏好污染手机。
- 已增加顶部上下文栏、右上角双模式切换、移动端四项底部导航。
- 已把历史会话栏改为 transform 驱动的移动抽屉，并增加遮罩、Safe Area 和触控尺寸。
- 已重排移动端首页卡片、消息、攻略标题、Day 章节、图片、横滑表格、来源、思考工作台及两层输入框。
- 协同行程接收布局模式；桌面预览移动端时也强制使用“行程 / 地图 / 助手”单面板结构。
- 已补充 3 类纯函数/结构/视觉回归自动化检查，前端 19 个测试全部通过。
- 已部署至 `http://42.194.202.233/travel/`，线上服务和 `/api/health` 正常。
- 真机反馈发现底栏“新对话”未关闭协同行程全屏层；已将四项底栏改为互斥导航并重新部署。
