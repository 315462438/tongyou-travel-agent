# Phase 80 · 互动旅行电影样片优化

日期：2026-08-10

## 背景与目标

Phase 79 已完成天堂寨六幕预演、路线分支和转行程闭环，但线上截图暴露出体验仍接近
“全屏图片 + 大字 + HUD”的幻灯片：POI 图片被过度放大后清晰度不足，常驻数值面板抢夺注意力，
用户仅点击按钮推进，缺少身体参与感。

本次在不推翻后端场景包的前提下，把前端升级为一版可验证的“互动旅行电影”样片：让图片像
电影取景而非壁纸，让推进动作产生参与感，让路线、体力和花费在需要时出现，而非伪装成游戏后台。

## 方案

1. 全屏背景改为“氛围演绎层 + 中央电影取景框”：第三方 POI 图只作为真实地点参考，限制放大，
   周围使用同图模糊环境延展，降低低分辨率素材的像素感。
2. 移除右上角常驻 HUD；时间、地点和环境改成轻量电影字幕，体力/花费只在场景切换提示与结算出现。
3. 增加鼠标/触控视差：用户移动指针时取景框和图片产生小幅反向位移，营造 2.5D 景深。
4. 普通场景使用“按住前行”完成推进，展示环形/横向进度；键盘可使用空格键，移动端支持长按。
5. 分岔场景保留两条路线，但改为场景内电影选项，明确轻松/挑战的实际差异。
6. 场景顶部只保留当前章节与四段旅程轨道；六幕数据仍完整参与结算，展示上压缩为四个叙事章节。
7. 天堂寨首场景增加一张明确标注“氛围演绎”的项目内高质量主视觉，真实 POI 图继续展示地点参考。
8. 保留 Escape/关闭、错误降级、reduced-motion、移动端和最终转真实行程逻辑。

## 验收标准

1. 页面不再出现常驻四格 HUD，主视觉有清晰的电影取景层级；
2. 鼠标或触控移动会产生有限视差，离开后平滑归位；
3. 普通场景必须按住才能前进，短按不会误触；空格键具备等价能力；
4. 分岔选择仍改变后续文案、体力和最终路线；
5. “氛围演绎”与“真实地点参考”标注清楚，不把生成素材冒充实拍；
6. 移动端、安全区和 reduced-motion 可正常使用；
7. 自动化测试、前端测试、lint 与生产构建全部通过后部署。

## 实施结果

- 体验层已升级为环境延展 + 电影取景框 + 轻量视差，第三方图片不再无边界铺满 2K 屏幕；
- 常驻 HUD 已移除，时间/环境进入字幕，“行程感受”按需展开；
- 普通场景改为 900ms 长按推进，Pointer Events、空格键、短按取消均已接线；
- 新增 1672×941 氛围主视觉并压缩为 361KB WebP，页面明确标注其为“氛围演绎”；
- 路线分支、结算、重新体验、转真实行程和图片失败降级继续复用原有逻辑；
- 对应自动化契约与人工验收用例已补充。
- 前端 58 项测试、lint（仅 2 条历史 Fast Refresh warning）和生产构建通过；线上主包、体验懒加载
  代码包、361KB WebP 主视觉与 `/travel/api/health` 均返回 200，版本已部署。
