# 思考区改为轻量单行（Phase 112）— 2026-09-02

## 缘起

用户看着线上的 `ThinkingWorkspace` 说「这个加载的太重了」，要求「直接模仿 deepseek harness
或者 codex 的小图标动态显示加载中，包括思维链即可」。

Phase 60 那版工作台是**一整块卡片**：毛玻璃容器 + 呼吸光晕 + 三层轨道动画的球 + 进度条 +
五阶段步骤条 + 当前动作卡 + 波形 + 足迹列表 + 停止按钮。`index.css` 里 111 行、9 个
`@keyframes`。它在「等 4 分钟」这个场景下是解决问题的，但视觉重量远超它承载的信息量，
而且**每轮对话都要占掉整屏**。

## 参照实现

`~/Desktop/deepseek/deepseek-harness/packages/client/ui-conversation/src/client/chat/ReasoningRow.tsx`
+ `ui-primitives/src/DisclosureRow.tsx`：

- **一行 24px**：16px 图标 + 6px 间距 + 14px/24 标题 + 2px 分隔点 + 尾随摘要。
- `summary = running ? latestLine(text) : firstLine(text)`——跑动时显示**最新一行**，
  结束后显示**第一行**当标签。
- 跑动时 `scrollLeft = scrollWidth - clientWidth` **跟随尾部**，且 `text-overflow: clip`
  （跟随时不要省略号，否则每帧都在闪）。
- 运行态用 `::after` 一道 300px 渐变**扫光**（2.6s）表示「活着」，`prefers-reduced-motion`
  下关掉。
- 图标 hover 时换成 chevron（`.iconIdle` / `.chevronHover` 互相淡入淡出）。
- 一条 `visuallyHidden` 的 "running" 供读屏。
- `useThrottledVisualUpdate`：`requestAnimationFrame` 隔 3 帧合并一次 DOM 对齐，
  流式每 800ms 来一次也不会每次都动 DOM。

## ⚠️ 不能顺手丢掉的东西

Phase 71 的结论是**实测**得出的：长任务流失的原因不是「久」，是「不知道还要多久」+
「静默空隙」。以下四项是那次改造的**功能**，不是装饰，压缩视觉不等于删掉它们：

1. **已用时间**（`formatThinkingElapsed`）
2. **预期时长**（`expectedHintFor`，「通常 3-4 分钟」）
3. **足迹**（Phase 71 ③ 的 `_found()` 播的实质进度，等待期变阅读期）
4. **45s 静默后的「可以关掉页面」**——很多人不是没耐心，是怕关了白等

所以本次是**压缩呈现、保留信息**：把 1、2 收进同一行的次要位；3 收进展开区；4 降级为
一条极细的次行，仍然只在 45s 后出现。

**明确放弃**：五阶段步骤条与进度条。理由是它们占了最多像素却携带最少信息——阶段是
`inferThinkingProgress` 从进度文案**猜**出来的，进度条是按 `THINKING_EXPECTED_SEC` 线性
逼近的，两者都不反映真实完成度。`inferThinkingStage` 等纯函数**保留不删**（它仍用于判定
「阶段只前进不倒退」，且有单测），只是不再渲染成步骤条。

## 方案

新组件 `ThinkingRow`（替换 `ThinkingWorkspace`）：

```
[✦ 旋转小图标] 思考中 · 00:47 · 通常 3-4 分钟   ｜  正在小红书搜索：成都美食…        ▸
└ 展开后：足迹列表（最近 5 条）
```

- **收起态**：一行。图标 + `思考中`/`深度研究中`/`绘制手账中` + 时间 + 预期 + 分隔点 +
  尾随的当前动作（跟随尾部、不省略号）。
- **展开态**：足迹列表（最近 5 条，越旧越淡，沿用现有 `.thinking-trail` 语义）。
- **扫光**：整行 `::after` 渐变，`prefers-reduced-motion` 关。
- **静默 ≥45s**：行下方追加一条 12px 次行，文案沿用现有的（含加粗的「可以关掉页面」）。
- **停止**：**不在这一行里放停止按钮**。Phase 71 已经把 composer 的发送键在 running 时变成
  黑色停止方块，那是主入口；这里再放一个是重复。（这是本次唯一减少的交互入口，
  需在验收里确认 composer 那个仍然可用。）

同时把助手消息里的 `Reasoning`（「已深度思考 ▸」）改成**同一套行样式**，让「思考中的那一行」
和「思考完折叠起来的那一行」看起来是同一个东西——这正是用户说的「包括思维链」。

## 验收标准

1. 收起态高度为**单行**，不再出现步骤条、进度条、轨道球。
2. 同一行同时可见：模式标签、已用时间、预期时长、当前动作。
3. 当前动作文本跟随尾部（`data-follow-end`），且跟随时无省略号。
4. 点击整行可展开足迹；展开后仍显示当前动作（`keepContentWhenOpen` 语义）。
5. 静默 ≥45s 出现「可以关掉页面」次行；<45s 不出现。
6. `prefers-reduced-motion: reduce` 下扫光与图标旋转均 `animation: none`。
7. 移动端不横向溢出（尾随摘要自己 `overflow: hidden`，父级不产生横向滚动）。
8. `Reasoning` 与 `ThinkingRow` 使用同一套类名前缀，视觉一致。
9. 旧的 `.thinking-*` 类名在 `index.css` 与 `Home.tsx` 中**不再有残留**
   （否则是死 CSS，且会误导下次改动）。
10. `inferThinkingStage` / `inferThinkingProgress` 等纯函数及其单测**保持通过**——
    它们没有被删，只是不再驱动步骤条。

## 刻意不做

- **不引入组件库**。参照实现依赖 `@deepseek-ai/dsh-client-ui-primitives`，我们只需要
  其中一个 24px 行的形状，照抄形状不照抄依赖。
- **不做 hover 换 chevron 的图标互换**。在我们这里图标是「运行中」的唯一动态指示，
  hover 时把它换掉会让人以为停了。改成 chevron 常驻在行尾。
- **不删 `THINKING_STAGES` 与阶段推断**。见上。
