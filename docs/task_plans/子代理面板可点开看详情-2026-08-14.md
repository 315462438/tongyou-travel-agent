# 子代理面板可点开看详情

> 2026-08-14　Phase 94

## 问题

子代理面板（Phase 88）只显示 title / 60 字摘要 / tokens / 时长 / 状态——
看得出「谁在跑」，看不出「派了什么给它、它回了什么」。dsh 的对应面板可以点进
每个子代理看完整会话，我们缺这一层。

## 落法

### 数据

`SubagentRun` 增加两个字段：

| 字段 | 内容 | 上限 |
| --- | --- | --- |
| `prompt_full` | 派发给子代理的完整 description | 8000 字 |
| `output` | 子代理的完整回复（失败时是异常文本） | 12000 字 |

截断时**追加一句「已截断，共 N 字」**——不说明的话，读的人会以为子代理就回了这么多。

`output` 的来源是 `on_tool_end(output)`。deepagents 的子代理返回形态不固定
（纯字符串 / `{"messages": [...]}` 子图状态 / `ToolMessage` 对象），
`_as_text()` 逐种形态取，取不出来回空——**观测代码抛异常绝不可接受**。

### 传输：存全的，发轻的

全文存进那条 progress 消息的 `meta_json`，但 `/messages` 返回前经
`chat_api._light_meta()` 把 `prompt_full` / `output` 剥掉。

理由是接口性质：`/messages` 是 **800ms 一轮的轮询**，4 个子代理 × 两万字
每次都拖上就是几十 KB 的纯浪费。详情改走
`GET /api/chat/{cid}/subagents/{run_id}`，点开某一条时才取一次。

这和调用链抽屉（`/trace`）、轨迹详情（`inputFull`/`outputFull`）是同一个模式：
**列表轻、详情按需**。

不另建表：子代理详情的生命周期与那条 progress 消息完全一致（会话删了它也就没了），
单独存一张表只会多一处要同步删除的地方。

### 界面

面板每行变成整行按钮，点开是详情抽屉——**复用轨迹详情的骨架**
（`.traj-detail-mask` / `.traj-detail` / `.traj-detail-tabs` / `.traj-pre`），
同一类「看原始输入输出」的东西不该有两套长得不一样的壳。

两个标签：**派发内容** / **回复**。运行中的子代理还没有回复，
回复页给一句「这个子代理还在跑，回复要等它结束」，而不是一个空白页。

`.subagent-row` 清掉了 button 的原生外观（`appearance: none` + 背景/边框/字体继承），
否则深色模式和移动端会露出系统按钮底色。

## 测试

`tests/test_subagent_trace.py` 新增 10 条：全文保留、成功/失败都要有 output、
deepagents 四种返回形态、超长截断带说明、轮询剥离重字段且**不就地改坏原对象**、
无关 meta 原样透传。

`tests/test_agent_api_auth.py` 的 AST 全量路由扫描自动覆盖新接口（需登录）。
