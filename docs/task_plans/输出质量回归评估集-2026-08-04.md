# Task Plan · 输出质量回归评估集（2026-08-04）

## 问题

这一周改了攻略 prompt、记忆注入纪律、跨会话来源复用、截断续写……每一项都**直接影响
输出质量**，但验证方式只有「跑一条看看，眼睛扫一遍」。单测覆盖的全是纯函数
（表格不被劈开、城市拆分对不对），没有任何东西能回答：

> 加了来源复用之后，攻略质量掉了吗？
> 记忆纪律那段 prompt 会不会让模型变得畏手畏脚？

尤其来源复用——文档里自己写了「复用的资料是上次那个问法抓的，本轮角度可能不同」，
然后靠「必应最多降到 light」对冲。**这个对冲有没有用，无从判断。**

对应 `ai-agent-book/chapter8` 的**机制① 轨迹评价与结构化诊断** + **机制⑦** 里的
「版本化评估集」。它同时是机制③（系统提示学习）的前提——没有评估集，
「进化」和「漂移」分不出来。

## 方案

`backend/evals/`：

| 文件 | 职责 |
| --- | --- |
| `queries.yaml` | 固定 query 集（单城/多城/沿途/酒店/海外/延续追问），每条带期望属性 |
| `checks.py` | **规则化**检查器（纯函数）。不做 LLM 打分——贵且会漂移 |
| `metrics.py` | 过程指标：耗时、来源数、各站点命中、是否复用、图片数 |
| `runner.py` | 登录 → 逐条发问 → 轮询完成 → 跑检查 → 落 JSON 快照 + Markdown 报告 |
| `compare.py` | 两次快照对照，标出新增/修复的问题与指标变化 |

## 边界

- **不做 LLM 打分**：规则化检查确定、可复现、零成本；主观质量仍靠人看。
- **全量跑一次约 1 小时**（20+ 条 × 2-3 分钟，浏览器池串行），定位是
  「大改动前后的对照闸门」，不是 CI 每次跑。支持 `--only` / `--limit` 跑子集。
- 用专用测试账号，跑完可选清理会话。

## 验收

- `tests/test_evals_checks.py`：每个检查器对「本周真实翻车样本」判阳、对正常样本判阴。
- `python -m evals.runner --limit 3` 能跑通并产出报告。
- `compare.py` 能对两份快照给出差异表。
- `tests/test_evals_verify.py`：三层验证器各自判阳判阴 + 闸门一致性（见下）。

## 补充：三层验证（当天下午追加）

原方案是**扁平**的——一层规则检查 + 一组过程指标。后按 chapter8 机制① 的
「结果验证 → 过程验证 → 质量验证」重构为 `evals/verify.py`：

| 层 | 函数 | 问的问题 | 码前缀 |
| --- | --- | --- | --- |
| 结果 | `verify_result` | 用户要的东西拿到没有（天数/城市/截断/来源数） | `res_` |
| 过程 | `verify_process` | 有没有守住我们自己定的纪律（复用降级、来源类型、归因、反问、沿途） | `proc_` |
| 质量 | `verify_quality` | 6 维 Rubric，**维度化 PASS/FAIL，不折单一总分** | `qual_` |

坚持的两条：不做 LLM 打分；evidence 必须是可核对的事实（正文/meta/进度轨迹）。

### 接入时踩的三个坑（已修）

1. **闸门只认一层**：控制台文案与退出码用 `findings`（仅质量层）另算一套，而报告表格用
   `verified`（真三层）。结果是过程层挂了照样打印「✓ 三层验证通过」且退出码 0。
   → 收敛到唯一判据 `runner.passed()`，三处共用。
2. **对照不含过程层**：`compare.py` 的 `_codes()` 只读 `findings`，过程层回归进不了前后
   对照——而复用降级恰恰是这套评估集最想守的东西。→ 快照新增结构化 `verification` 字段，
   `_codes()` 并入 `res_*`/`proc_*`；`qual_*` 有意排除（它是 findings 的重新归类，
   纳入会把同一问题数两遍）。
3. **过程层会静默失效**：`tool_sequence` 靠进度气泡文案正则还原调用序列，文案一改就全落空，
   而依赖 seq 的规则会一条都打不着 → 整层退化成无条件通过。→ 加元规则
   `proc_unrecognized_trail`（≥3 条轨迹却零匹配即判失败）+ 缺 `generate_guide` 的 warn。

### 已知边界（未做）

- 快照只存 `excerpt`（正文前 400 字）与 `progress`，**不存完整正文与 meta**，因此无法对历史
  快照事后重算三层结果。改了检查器想回看老数据只能重跑。
- 三层之间有重叠：`truncated`/`missing_days` 同时属结果层与质量层「内容完整性」，
  同一问题在报告里会出现两次（对照闸门已去重，报告未去重）。
