# 记忆变更三态通知（2026-08-22）

移植自 Codex（`openai/codex`）`codex-rs/core/src/context/world_state/` 的
`PreviousSectionState`。**只搬这一格，不搬整套 World State**——理由见下。

## 为什么不整套搬

Codex 的 World State 解决的是「系统上下文每轮重拼 → 前缀缓存全废」。它的做法是把
系统上下文变成**追加进对话历史的增量消息**，只在变化时追加一条。

这套机制我们**用不上，且已有等价物**：

| | Codex | 本项目 |
| --- | --- | --- |
| prompt 与日志的关系 | prompt **就是**日志 | prompt 是日志的**投影**（`derive_surface`） |
| 记忆呈现 | 增量追加，历史里留着所有旧副本 | 每轮从库现算，只有当前值 |
| 冲突消歧 | 必须显式 `REPLACEMENT_NOTICE` | **不需要，没有旧副本** |
| 前缀缓存 | 靠增量注入保住 | 靠 Phase 58「易变项末置到 user」保住 |

把记忆从末尾挪进历史前缀，只省下约 800 token 的缓存折扣（一轮一次 guide 调用），
却要引入旧副本、失效通知、压缩时的 baseline 重置。**不划算，不做。**

## 但有一格必须搬：删除通知

Codex `agents_md.rs` 的 `render_diff` 是个四格真值表，其中
`(instructions=None, previous_may_contain_instructions=true)` 那格发的是：

> The previously provided AGENTS.md instructions no longer apply.

对应到我们这里的真实场景：

1. 第 3 轮：记忆里有「忌口=素食」→ 模型推荐了一堆素食馆，**这段回复逐字留在历史里**
2. 第 8 轮：用户说「我现在不忌口了」→ `DeleteMemory`，记忆块里那条消失
3. 第 8 轮的 prompt = 历史（满屏素食推荐）+ 记忆块（没有忌口这条）

模型**没有任何信号**知道约束解除了，只看到自己过去言之凿凿的输出。
投影架构消灭了「记忆块的旧副本」，但消灭不了**对话历史本身承载的旧状态**。
这一格是真缺口。

## 三态从哪来

需要「上一轮实际注入了什么」——此前完全没记录（`meta.memories_used` 只有
`type/content`，没有 `key`，无法比对）。

- `None`（**Absent**）：本会话还没有过终稿回复 → 历史里没有冲突表述 → 静默
- `_UNKNOWN`（**Unknown**）：有过回复但没记下注入了什么（改造前的老消息 / 老格式
  `memories_used` 不带 key）→ 比不出差异 → **发一句整体重申**
- `dict`（**Known**）：`{key: content}` → 精确 diff

### 代价不对称（同 Phase 104 的境内外判定）

- 多发一句「这条已更新」= 几十 token
- 漏发 = 模型继续按历史里那条**已被用户推翻**的约束作答，且用户看不出它为什么固执

所以 **Unknown 一律往「通知」这边倒**。

## 三条设计约束

1. **新增不通知**。新增记忆不与历史里任何表述矛盾，说了纯是噪声。
   （对应 Codex `(Some, previous_absent)` 那格：原样发，不加 notice。）
2. **「本轮没被选中」≠「被删除」**。`select_relevant_memories`（Phase 30）会按相关性
   筛掉一部分记忆。判据必须是「库里还有没有」（`all_keys`，在筛选**之前**捕获），
   不是「这轮注没注入」。写错的话，一次相关性筛选就会让模型以为用户撤回了偏好——
   这是**主动误导**，比不通知更糟。
3. **读失败保持静默**，不发 Unknown 那句。DB 抖动是基础设施问题，不是「拿不准说过
   什么」；否则一次故障就给每轮都挂一段噪声。

## 落点

- `app/agent/memory.py`：`_UNKNOWN` / `previous_injected_memories(cid)` /
  `format_memory_changes(previous, injected, all_keys)`
- `gather_context()`：`used` 补 `key` 字段（这就是快照）；变更块拼进 `block`；
  返回值多一个 `changes` 便于观测
- 整块包 try/except——变更通知是增强，绝不能拖垮上下文收集

## 验收

`backend/tests/test_memory_tristate.py`（14 条），见
`docs/test_cases/记忆变更三态通知-验收用例.md`。

# 补丁：快照必须跨全会话聚合（2026-08-24）

## 漏发的洞

首版 `previous_injected_memories` 只读**最近一条**真回合的 `memories_used`。但陈旧
状态是**逐轮累积**的：

```
第 1 轮  注入 {忌口:吃素, 预算:3000}  →  模型写下一堆素食推荐   ← 病灶从此留在历史里
第 2 轮  用户问"机场怎么走"，忌口被 select_relevant_memories 筛掉
         → memories_used = {预算:3000}
第 3 轮  忌口被删
         previous = 第 2 轮的 {预算}  →  忌口 ∉ previous  →  不发通知 ❌
```

第 1 轮那段素食推荐还在历史里，但因为第 2 轮"没提"，第 3 轮就查不到了。**静默漏发，
无日志。**只影响记忆超过 `memory_select_threshold`(12) 条、会走相关性筛选的用户。

## 改法

`previous` 从「上一条的快照」改成 `InjectionHistory`：

| 字段 | 含义 |
| --- | --- |
| `shown: dict[key, set[value]]` | 全会话展示过的**每个** (key, value) |
| `announced: dict[key, value \| None]` | 上次通知的新值；`None` = 已通知它被移除 |

判据随之变成「历史里有没有基于**别的值**写下的内容」：

```python
updated  ← key ∈ current 且 ∃ v ∈ shown[key], v ≠ current[key]
removed  ← key ∈ shown 且 key ∉ all_keys
```

## 「恰好一次」改由账本保证

聚合之后旧值永远留在 `shown` 里，diff 不会自然消失，所以**通知这个动作本身也要记账**：
`format_memory_changes` 返回 `(文本, 新通知的 {key: 值})`，调用方写进
`meta.memories_changed`（guide / direct / research 三处），下一轮据此跳过。

⚠️ 账本记的是**上次通知的新值**而不是"这个 key 通知过了"——否则「预算 3000→8000」
通知过之后，再改成 12000 就永远不会再通知。有回归测试钉住
（`test_second_change_is_announced_again`、`test_readded_memory_after_removal_is_announced`）。

⚠️ 落库失败 / 本轮被取消 → `memories_changed` 没写成 → 下一轮**重发一次**。
方向安全：重复一句 vs 永久漏发。

## Unknown 只看最近一条

聚合了不代表 Unknown 也要聚合：只用**最近**那条真回合判 Unknown，更早的老消息只是
不贡献数据。否则会话里有一条改造前的老消息，就会让它**永远**停在 Unknown、每轮都发
那句兜底重申。

## 线上验证（2026-08-24）

跨会话 + 上一轮被筛掉，正是修之前会漏的组合：

```
B 本轮 changes = '⚠️ …「忌口」已被移除，不再适用'      ← 修之前这里是空
B 本轮 announced = {'忌口': None}
B 下一轮 changes = ''                                  ← 恰好一次
A 本轮 changes = ''                                    ← A 没展示过忌口，不误发
RESULT: PASS
```
