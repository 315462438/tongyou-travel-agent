# Task Plan — Phase 44：快/慢思考语义重排（深度推理开关名副其实）

## 背景（用户反馈）

现状开关语义是拧的：
- 开关**关** → guide 流水线照跑：联网抓页（open_page）、插图、DeepSeek 长思考链
  （前端「已深度思考」）——用户关了开关还是在「深度思考」；
- 开关**开** → research 却没有思考过程展示、没有图片——开了反倒「看不见思考」。

用户拍板对齐行业标准语义：**关 = 快思考**（直觉秒回）；**开 = 慢思考**
（联网、拆解、推理链、图片等全部归入）。

## 新路由表

| 开关 | 分类结果 | 走向 |
| --- | --- | --- |
| 关（快思考） | 任意 | **一律 direct 快速直答**（快模型、不联网、无长推理）；分类为 guide/research 时挂「适合深度推理」提示卡 |
| 开（慢思考） | direct（闲聊/追问） | 仍秒回（开着开关问「谢谢」不该跑重流水线） |
| 开 | guide（规划/攻略/酒店） | guide 流水线（联网+图片+反思+思考链） |
| 开 | research（开放对比/研究） | deepagents 深研（服务器未启用退 guide） |

## 改动

1. `decide_route` 改为**纯三分类**（不做开关门控，失败/未知 → guide）；
   门控逻辑全部上移到 `resolve_route`（按上表）；
2. `run_direct_answer` 换**快模型**：新配置 `model_direct`（空 = 用 v4-flash）——
   快思考真正秒回、无 reasoning 链（前端自然不出现「已深度思考」折叠）；
3. 提示卡文案更新（覆盖 guide/research 两类）：「已用快速模式作答（未联网）。想要
   联网检索、真实来源与配图的完整攻略，请打开『深度推理』重新提问」；
4. 更新 resolve_route/decide_route 全部单测。

## 风险

- 快思考用 v4-flash 答规划类问题质量有限——**这正是快/慢分层的定义**（提示卡引导
  升级）；`MODEL_DIRECT` 可随时在 .env 调回 v4-pro；
- 存量用户习惯「不开开关也能出攻略」会变化——提示卡承担教育成本。
