# xhs 部分收成 + 抽取思考纪律（Phase 102）

2026-08-21　两个小改动打包：一个治首页攻略的 collect 尾延迟，一个治导入行程板的抽取长考。
（跨用户目的地缓存是更大的杠杆，但**本轮刻意不做**——要建共享表 + 迁移，单独立项。）

## A. xhs 部分收成 + 压预算（首页攻略提速）

### 问题

`collect_xhs_sources` 的总预算是 `xhs_collect_timeout_s=150`，且超时行为是**全丢**：

```python
except asyncio.TimeoutError:
    ...
    return []
```

线上实测一轮 xhs 各段合计 149.9s——**差 0.1 秒就白等两分半、一篇不剩**。这不是假想的
悬崖，是差点掉进去的悬崖。而 xhs 串行加速已实测否掉（容器内部串行，并发 38.2s ≈
串行 41.6s），所以只剩「等多久」和「超时后留不留」两个旋钮。

### 改法

1. **超时改为交回已抓到的**：内层循环往调用方传入的 `sink` 里逐篇追加（每篇是完整 dict，
   取消只发生在 await 点，不会留半截），外层超时后返回 sink 现有内容。抓了 2 篇就用 2 篇。
2. **预算 150 → 75**：搜索实测 16–27s，75s 够搜索 + 2–3 篇详情。晚到的不等——必应+高德
   已经足够生成，xhs 是增味不是主料。

效果：collect 从「最坏 150s 且可能得 0」变成「**封顶 ~75s 且必有部分收成**」。
整轮 P50 预期 ~200s → ~130-150s。

### 边角

- **用户停止（CancelledError）照旧向上冒**，绝不能被部分收成的逻辑吞掉（既有注释明令）。
- 服务器 `.env` 若显式配了 `XHS_COLLECT_TIMEOUT_S`，改 config 默认值不生效——部署后必须查。
- 部分收成会改变 `_web_search_mode(xhs_count)` 的档位判断——这是**正确的联动**（收成少
  就多搜必应），不是副作用。

## B. 抽取思考纪律（导入行程板提速）

### 问题

Langfuse 实测「导入行程板」的分块抽取（`IMPORT_DAYS_SYSTEM`）：

```
118.6s  正文  971  思考 13124   ← 思考是正文的 13 倍
 99.0s  正文  704  思考 10663
 78.5s  正文  837  思考  8971
```

一个「从 Markdown 里挑出地点名填 schema」的任务，模型长考两分钟。7 天攻略 × 每天一块。
全局抽取（`IMPORT_SUMMARY_SYSTEM`）同样中招（思考 4598–6081）。

这是 quick_take（Phase 101）、ITINERARY（Phase 11）之后**第三次**撞同一类问题：
DeepSeek 思考模式对结构化抽取任务过度推理。治法也还是那一味药。

### 改法

新增共享常量 `EXTRACT_THINKING_DISCIPLINE`（放 `app/llm/client.py`——三处模块都要用，
不再各写一份漂移），append 到**五个**抽取 system：

| 模块 | prompt | 实测思考 |
| --- | --- | --- |
| `trip_api.py` | `IMPORT_DAYS_SYSTEM` | 4667–13124 |
| `trip_api.py` | `IMPORT_SUMMARY_SYSTEM` | 4598–6081 |
| `ontology/extract.py` | `EXTRACT_SYSTEM` | 同类任务，顺手治 |
| `poster.py` | `EXTRACT_SYSTEM` | 同上 |
| `budget.py` | `EXTRACT_SYSTEM` | 同上 |

`max_tokens` **不动**——16000 的余量是 config 里写明的有意设计（截断重试一次 140s，
比多想几步贵得多），纪律负责省时间，预算负责兜安全，各管各的。

## 验收标准

1. 超时中途返回**已抓到的部分**（打桩：第一篇成功、第二篇永久阻塞、预算调小）
2. 用户取消仍向上冒 CancelledError
3. 预算默认值 = 75
4. 五个抽取 system 都含「思考纪律」（防后人重构时删掉——删了不报错只悄悄变慢）
5. 全量回归无新增失败
6. 部署后：确认服务器 .env 无 `XHS_COLLECT_TIMEOUT_S` 覆盖；下次真实导入在 Langfuse
   里看 reason token 是否从五位数掉到三位数

## 刻意不做

- **跨用户缓存**（本轮范围外，单独立项）
- **不减 `xhs_notes_per_turn`**：篇数是质量旋钮，服务器已设 3；部分收成落地后它自然被
  预算封顶，无需再压
- **不动 max_tokens**，理由见上
- **不给 LLMClient 加关闭思考的开关**：动所有调用方，且纪律已三次验证有效
