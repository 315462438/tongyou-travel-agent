# 地图主视图与景点详情

## 目标
修复 iOS 记账页系统 TabBar 与自定义底栏叠加；参考用户提供的图片，将手机行程升级为地图主视图 + 可收起/展开的底部行程面板，点击地点进入图文详情。沿用现有配色、字号、协作编辑和账本权限。

## 方案
1. iOS 主导航使用唯一的自定义底栏容器，保留各页状态，彻底移除系统 TabView 底栏来源；新增跨三个根页面及记账详情返回的回归。
2. 手机地图铺满工作区；底部三档行程面板支持拖动把手和明确展开/收起按钮，日期和地点在面板内。横屏做地图/列表分栏。桌面保留左右布局。
3. 地点名称打开详情面板：照片横滑、原行程介绍、地点实用信息、数据来源、编辑/导航。地图标记仍与地点联动；返回详情后不丢日期/列表位置。
4. 新增只读 `GET /api/trips/{trip_id}/stops/{stop_id}/details`，先校验已接受的行程成员及地点归属。按需查询高德 POI，名称与坐标同时校验，海外/无坐标不误配国内同名点。仅信任白名单图片；复用图片代理。公开 POI 有界 TTL 缓存，私密行程说明不进入公共缓存。超时/无图仍可展示已有行程内容，不编造评价、热度或 AI 介绍。
5. 介绍第一版使用已导入/用户编写的行程说明，明确标为行程内容；地图数据展示地址、分类、联系电话（如有）。资料来源明确，不能把计划描述成已发生经历。
6. 三端验证后，先部署向后兼容的后端接口和网页，再安装 iOS、发布新的 Android 版本（不覆盖已发布的 0.7.0）。

## 验收
- 所有 iOS 根页面及记账详情返回只出现一套导航。
- 地图不被面板完整遮挡；拖动/按钮切档不抢列表滚动，窄屏/横屏和减少动态可用。
- 地点详情有加载、照片失败、无资料、请求失败重试，导航和编辑仍可达。
- 后端鉴权、跨行程地点、同名远距离拒绝、海外拒配、缓存和失败降级有自动化测试。
- 浏览器与原生 UI 回归、构建、安装与更新清单验证通过，结果写入 docs/test_cases。
