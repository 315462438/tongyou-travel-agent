# 安卓原生界面改造方案（2026-11-10）

状态：**阶段 0 + 1 的代码重构已完成**。其余页面保留网页兜底；地图与游游继续使用已有网页能力。阶段 2–4 为后续迁移，不宣称本轮全部原生化。27 项 JVM 与 6 项脚本测试通过，lint/Release/测试包编译通过；设备验收按用户后续要求停止，详见对应测试文档。

## 本轮实施与验收记录

- 入口使用 Kotlin / Compose；原 Java Activity 改名为 WebFallbackActivity，保留文件、分享、App Updates、链接策略和网页回退测试。
- 增加 data（OkHttp / serialization）、session（Keystore AES-GCM 与旧 WebView origin 一次性迁移）、ui（主题 / 首页 / 登录）、chat（轮询与原生 Markdown）分层。
- 登录迁移使用同 origin 的本地空 HTML 读取 localStorage，不加载远程页面；加密落盘成功后才登记完成。原生退出/401 与兜底退出双向同步，网络错误不清 token。不同账号的异步返回不得写回当前会话。
- 首页及 AI 对话原生实现；行程、账本、我的高级工具、海报/预算/分享/扫码沿用 APK 网页快照。Android 独立 Vite 插件注入兜底路由，不修改共享网页源码和线上资源。
- 原生会话每 800ms 串行轮询，仅前台页面轮询；重复发送互斥、失败保留草稿、409 追踪已有任务、停止失败可重试、切换会话取消过期请求。
- 确保标题/列表/表格/图片/引用/代码的原生 Markdown 阅读、追问/候选/地点/来源、上传与按需定位完整可用。
- 锁定与现有 AGP 8.9.1 / SDK 35 兼容的依赖版本。Haze 仅 API 31+ 且系统允许动态效果时开启，其他情况使用高对比半透明材质。必须记录实际测试平台，不将 API 35 模拟器结果当作 Android 8/11/12 或真机验收。
- 自动化：协议与发送状态单测、Markdown/路由单测、Compose 仪器测试、Keystore/旧 localStorage 迁移与退出测试、兜底回归、lint、debug/release 构建。APK 只在本地生成，不发布线上。
- 覆盖升级验收使用正式签名旧包 0.11.1 (28) → 新版本，测试 token 为本地假值，不使用真实账号数据；保留包名、签名、App Links 与应用内更新。

### 2026-11-10 用户补充约束

用户明确：「不需要模拟器，重构完了告诉我一声即可」。因此停止设备测试并关闭已启动的模拟器；本轮以代码实现、可运行单元/脚本测试、lint 和 APK 构建为验收范围。不再执行覆盖安装、设备视觉或模拟器测试；相关用例保留供以后自选执行。不能把测试包编译成功写成设备测试通过。

### 实际实现边界

- 已实现阶段 0 + 1 的主体：登录/邀请码注册、迁移与退出、首页今日行程/旅行卡/灵感、原生会话历史/对话、800ms 串行轮询、停止、思考/流式/Markdown、追问/候选/地点与来源、图片上传、粗略位置。
- 地点卡「加入行程」与攻略的行程/预算/海报/分享入口定位到同一会话的网页兜底；行程管理、账本、通知和账户高级工具保留全部原网页能力，未纳入本轮原生化。

- 文档和本地构建版本为 0.12.0 (29)，未发布线上；版本与签名校验由原 package-release.py 执行。

## 1. 为什么做、做完是什么样

现在的安卓 App 是一个壳：`MainActivity.java`（544 行）里放了一个 WebView，界面全部是打包进去的网页。
滚动、转场、按压反馈都跑在网页线程上，模糊层一多就掉帧，所以比 iOS 明显不跟手。

改造后：安卓界面用原生代码重写，和 iOS 一样直接调线上接口 `https://17tongyou.com/travel/api`。
后端不用改，网页版不受影响，iOS 不受影响。

**先把预期说清楚**：

- 能达到的：滚动、转场、按压、键盘跟随都是系统原生的，流畅度接近 iOS。
- 达不到的：iOS 的 Liquid Glass 是苹果系统自带的材质，安卓没有对应物。安卓上能做的是「半透明 + 背景模糊 + 高光描边」的近似效果，
  而且真正的背景模糊只在 Android 12 及以上可用，更老的系统只能退成半透明纯色。观感会接近，但不会一模一样。

## 2. 技术选型

| 项 | 选择 | 理由 |
| --- | --- | --- |
| 语言 / 界面 | Kotlin + Jetpack Compose（Material 3） | 写法和 SwiftUI 几乎一一对应，iOS 的页面结构可以直接照着搬 |
| 页面跳转 | Navigation Compose | 官方方案，支持共享元素转场和预测性返回手势 |
| 网络 | OkHttp + kotlinx.serialization | 轻，对应 iOS 的 `API.swift`（270 行） |
| 图片 | Coil | Compose 的标准图片库，带内存和磁盘缓存 |
| 登录状态 | Android Keystore 加密保存 | 对应 iOS 把 token 放钥匙串 |
| 背景模糊 | 开源库 Haze（Android 12+），老系统降级 | Compose 自带的模糊只能模糊控件自己，模糊不了它背后的内容 |
| 最低系统 | 保持 Android 8（minSdk 26） | 不丢现有用户 |

包名 `com.tongyou.travel`、签名密钥、App Links、应用内更新检查全部沿用，老用户直接覆盖安装。

> 以上库的具体版本、Haze 在各系统版本上的实际表现，我需要在开工第一步做一个小样验证，不是现在就能打包票的。

## 3. 怎么迁移：一页一页换，不是一次推倒

采用和 iOS 相同的思路——**原生为主，没改完的页面继续用网页兜底**（iOS 至今也保留了 `Web/` 兜底）。
这样每个阶段都能单独发版，中途停下来 App 也是完整可用的。

```
阶段 0  地基 ──→ 阶段 1  登录 + 首页 + 问 AI ──→ 阶段 2  行程 ──→ 阶段 3  记账 ──→ 阶段 4  我的及其余
                        ↑ 做完这步，最常用的路径就已经是原生的了
```

### 阶段 0：地基（不改变用户看到的东西）

- 工程接入 Kotlin 和 Compose；现有 Java 壳保留，作为「网页兜底容器」。
- 网络层、登录状态、主题（深浅色、品牌色、字号）、玻璃卡片组件、按压反馈、触感。
- **登录状态迁移**（最要紧的一项）：现在的 token 存在 WebView 的 `localStorage` 里。
  新版首次启动时必须把它读出来转存到原生加密存储，否则**所有老用户升级后都会被踢回登录页**。
- 模糊效果小样：在 Android 8 / 11 / 12 / 15 上各跑一遍，确定降级策略。

### 阶段 1：登录 + 旅行首页 + 问 AI 对话

对应 iOS：`LoginView`、`TravelHomeView`、`HomeView`、`Chat/*`、`MarkdownView`，约 2300 行 Swift。

- 登录 / 邀请码注册。
- 首页：今天的行程卡、我的旅行、灵感目的地、通知入口、三项底栏。
- 对话：800ms 轮询、思考进度、流式打字机、追问按钮、地点卡、参考来源、候选目的地、图片上传、定位、停止生成。
- **Markdown 原生渲染**：标题、列表、表格、图片、引用。这是本阶段最费工的一块，表格尤其容易出问题。
- 暂时仍走网页兜底的：手账海报、预算明细、扫码登录卡、分享计划单。

### 阶段 2：行程

对应 iOS：`Trips/*`，约 1700 行 Swift。

- 行程列表、新建（含出发日期）、邀请处理。
- 行程详情：按天切换、时间线、地点增删改、拖动排序、导航、成员邀请、群聊、投票、出发日期询问。
- **地图**是这一阶段的关键决策，见第 6 节问题 2。

### 阶段 3：记账

对应 iOS：`LedgerView`、`LedgerCollaborationView`，约 700 行 Swift。

- 账本列表与详情、记一笔、一句话记账、币种与汇率、成员与分享链接加入。

### 阶段 4：我的及其余

对应 iOS：`Me/*`、`FriendsView`、`HistoryView`、通知、游游，约 1900 行 Swift。

- 好友、历史对话、记忆、技能、连接（扫码）、公告、客服、管理员页面。
- 游游（旅行搭子）的动作和气泡。这块纯属锦上添花，建议放最后，或者安卓先不做。

## 4. 工作量与风险

**体量**：iOS 现有约 8100 行 Swift。安卓原生写完预计是同一量级的 Kotlin，外加登录迁移、兜底容器这些 iOS 没有的部分。
这是五个阶段的持续工程，不是一两次改动能完成的。阶段 1 是其中最大的一块。

| 风险 | 说明 | 应对 |
| --- | --- | --- |
| 老用户被登出 | token 在 WebView 里，原生读不到 | 阶段 0 专门做一次性迁移，并用旧版覆盖安装实测 |
| 以后每个功能写三遍 | 网页、iOS、安卓各一份 | 这是选原生的长期成本，没有办法消除，只能接受 |
| 安卓机型碎片化 | 华为、小米、OPPO 的系统各有差异，我手上只有模拟器 | 每阶段发版前需要你或朋友在真机上过一遍 |
| 安装包变大 | 现在约 2.9MB，加入 Compose 后预计到 10MB 上下（估计值） | 开启代码压缩；实际数字阶段 0 结束时能给出 |
| 模糊效果在老系统上没有 | Android 11 及以下不支持背景模糊 | 降级成半透明纯色，不影响功能 |
| 两套界面并存期间风格不一致 | 原生页面和网页兜底页面观感不同 | 按使用频率排序，先换最常用的；兜底页面只留低频功能 |
| 现有自动化测试作废 | 现在的设备测试都是针对 WebView 壳写的 | 每阶段重写对应的测试 |

## 5. 每个阶段的验收方式

- 该阶段覆盖的页面，逐项对照 iOS 同一页面的功能清单。
- 从线上旧版（0.11.x）覆盖安装，登录状态保留、能正常启动。
- 深色 / 浅色、系统字体放大、减少动态效果三种设置下各看一遍。
- 至少一台真机实测；我这边只能保证模拟器。
- 按项目规范，每阶段各出一份计划、踩坑记录和测试用例文档。

## 6. 需要你定的 5 件事

1. **做到哪一步为止？** 我的建议是先只承诺阶段 0 + 阶段 1，发一版看实际手感，再决定后面三个阶段做不做。
   最常用的路径（打开 App → 问 AI）在阶段 1 就已经是原生的了，后面的阶段收益递减。
2. **行程地图用什么？**
   - 高德安卓地图 SDK：效果最好，但要在高德后台用包名和签名指纹另外申请一个 key，还要处理它的隐私合规弹窗。
   - 地图那一块继续嵌网页（现有的高德 JS 地图）：省事，其余部分照样是原生的，但地图区域的手感不变。
   - 我的建议是先嵌网页，阶段 2 做完再看要不要换。
3. **游游要不要搬到安卓原生？** 动作和气泡的代码量不小（iOS 约 760 行），对流畅度没有贡献。建议安卓先不做。
4. **没换完的页面，是继续用网页兜底，还是先隐藏入口？** 建议兜底，功能不缺失。
5. **谁来做真机验收？** 每个阶段发版前都需要有人在真实安卓手机上过一遍，尤其是登录迁移那一步。

## 7. 不做的事

- 不改后端接口，不动网页版和 iOS。
- 不做鸿蒙原生、不上架应用商店（发布方式照旧：官网 APK + 应用内更新提示）。
- 不追求和 iOS 像素级一致，只追求同样的信息结构和同等的流畅度。
