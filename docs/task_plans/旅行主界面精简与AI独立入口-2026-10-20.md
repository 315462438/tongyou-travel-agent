# 旅行主界面精简与 AI 独立入口

## 目标
按用户确认的方向，将 Web、Android WebView、iOS 收敛为「旅行 / 记账 / 我的」，独立「问 AI」入口。移除同游圈和接力横幅的主要入口，保留数据库与协同行程、账本权限。保持现有可读字号、浅深主题，减少首屏表单。

## 方案
- 旅行首页展示真实行程卡片、创建入口和目的地灵感；点卡进入现有行程工作台。无数据、失败、加载均有独立反馈。
- AI 独立展示，快捷任务先回填再发送；历史收进 AI 与「我的」。关闭 AI 保留草稿和正在进行的对话。
- 三端使用相同信息结构。旅行卡加入叠片、按压反馈；面板/页面采用短距离淡入，减少动态时关闭位移动画。
- 用户账户工具保留在「我的」，高级工具折叠。社交旧通知只保留必要兼容处理，不删除内容或成员。
- 首轮不新增相册扫描、照片故事生成，也不假装拥有尚未实现的结构化 AI 推荐接口；复用现有攻略与导入行程能力。

## 涉及模块
frontend Home、独立旅行首页组件与样式、导航与自动化浏览器测试；iOS RootView/HomeView/MeView/TripsView；现有 API 无协议变更。

## 验收
1. 三个主导航和独立 AI 入口，首页无同游圈/接力横幅。
2. 行程打开/创建、账本协作及链接加入可达；历史可搜索并继续对话。
3. AI 快捷词不自动发送；关闭再打开保留输入，运行中可退出到旅行且能恢复。
4. 320/390/430px 与桌面无横向溢出，底部按钮不遮挡最后一项；浅深主题和减少动态均可用。
5. 前端构建、单测、新浏览器流程测试及 iOS 编译通过；结果记录在 docs/test_cases。

## 交付边界
先完成并验证源码与本地预览；发布安装包、线上部署分别报告实际完成状态，不把本地构建等同于用户设备更新。

## 完成记录
- Web/Android 共用页面和 iOS 原生入口已改造，旅行首页为真实行程横滑旅行册、创建/导入和目的地灵感。
- AI 快捷任务、草稿和会话恢复、历史与我的已接入；旧功能权限 API 保持原协议。
- 动效包括卡片按压、底栏选中滑动、Web 面板淡入、iOS 行程卡原生 zoom 转场；减少动态时关闭自定义位移。
- 前端 99 个单元回归、六组浏览器流程、生产构建、iOS 编译及浅深两组原生 UI 回归全部通过。详见 [测试记录](../test_cases/旅行主界面精简与AI入口-2026-10-20.md)。
- 本轮为本地源码交付，线上与手机安装版本尚未发布。

## 发布追加（用户已要求安装 iOS、部署并推送安卓更新）
- iOS 升为 1.0.8 (9)，沿用原包名与开发团队，Release 构建后覆盖安装到已连接的 iPhone，检查安装版本与启动。
- Android 升为 0.7.0 (10)，沿用原签名，独立打包新网页快照；执行单测、lint、签名/资源清单检查，发布版本化 APK 后原子切换 latest.json。
- Web 仅发布前端静态产物：保留旧哈希资源和旧入口备份，先同步资源再替换 index.html；本轮无后端变更，不重启业务服务。
- 验收线上入口及资源哈希、API 健康；验证 APK 下载、Range、大小、SHA256 与更新清单一致。0.6.0 客户端通过已有检查更新功能收到提示，0.5.0 及更早需手动下载安装。
