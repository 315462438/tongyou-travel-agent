# Phase 83 · 接力站真实热门推荐与动效搜索改版

日期：2026-08-10

## 问题

Phase 82 虽然补上了任意目的地能力，但页面仍以一个大白色表单为第一视觉，既没有旅行吸引力，
搜索框又保留了浏览器原生输入描边。用户进入接力站后先看到“操作控件”，没有先获得“最近哪里值得
看”的内容价值。

## 目标

1. 首屏先展示平台近 30 天真实热问目的地，再提供搜索；
2. 热门推荐带真实目的地图片，点击直接进入接力站；
3. 搜索框改成克制的玻璃胶囊样式，完全清除原生黑框；
4. 复用项目现有 React Bits 动效能力，加入轻量、可降级的动态光效；
5. 不引入新的前端依赖，不伪造热度数字。

## 方案

- `SocialHub` 打开时复用 `GET /api/onboarding`，读取平台近 30 天真实热问目的地；
- 复用 `GET /api/onboarding/covers` 为前四个目的地补高德真实景点封面；
- 接口失败时使用现有目的地兜底，仅标记为“推荐”，不冒充实时热榜；
- 顶部改成四张可点击热门目的地卡，图片上只展示排名、目的地和“查看接力”；
- 在推荐卡下放一条紧凑搜索区，文案为“没有你想去的？搜索任意目的地”；
- 复用现有 React Bits `Aurora` 作为推荐区背景光效，降低透明度并支持
  `prefers-reduced-motion`；
- 搜索输入显式设置 `border: 0 / outline: none / appearance: none`，焦点效果由容器统一控制；
- 发布器、动态列表、好友和个人主页逻辑保持不变。

## 涉及模块

- `frontend/src/components/SocialHub.tsx`
- `frontend/src/components/Aurora.tsx`（仅复用，不改实现）
- `frontend/src/index.css`
- `frontend/tests/visual-regressions.test.mjs`
- Phase 83 测试与踩坑文档

## 验收标准

1. 首屏视觉顺序为热门推荐卡 → 搜索 → 当前目的地动态；
2. 推荐数据来自 onboarding 热门接口，封面来自现有 covers 接口；
3. 点击推荐卡和搜索任意目的地都能切换接力站；
4. 搜索输入在聚焦时没有浏览器原生黑色矩形描边；
5. 动效不阻挡点击，低动态偏好下关闭；
6. 手机端推荐卡横向滑动，搜索框不溢出；
7. 前端测试、lint、生产构建与后端回归通过后部署。

## 实施结果

- 已接入 `/api/onboarding` 的近 30 天真实热问目的地，推荐卡不再写死；
- 已复用 `/api/onboarding/covers` 和现有图片代理展示高德真实景点封面；
- 推荐接口失败时才回退静态灵感，并明确使用“本期旅行灵感”而不是伪装实时榜单；
- 已复用 React Bits `Aurora` 构建顶部低透明动态光效，低动态偏好下不挂载；
- 已把四张热门图片卡放在搜索前，手机端改为横向吸附滑动；
- 已将搜索改为紧凑渐变玻璃胶囊，并显式清除原生边框、outline、appearance 和 focus 阴影；
- 前端 58 项测试、lint 和生产构建通过；后端 781 项回归通过。

### 可读性追加修正

首轮线上截图暴露出社交页辅助字号普遍只有 7.5–10px，在高分屏下无法舒适阅读。本阶段追加统一
可读字号基线：说明/时间/标签不低于 11px，按钮与筛选不低于 12px，正文不低于 14px；好友和
个人主页同步调整，移动端导航标签也不再使用 8px 字号。

测试说明：`docs/test_cases/接力站真实热门推荐与动效搜索改版-验收用例.md`。
