# 快答不再阻塞采集（Phase 101）

2026-08-21　线上 Langfuse 实测驱动

## 问题：两个，一个质量一个延迟

最近三条完整 guide 轮的 quick_take 调用：

```
9.7s   v4-flash  out=0    reason=1000   ← 思考链吃满预算，正文为空
11.2s  v4-flash  out=0    reason=1000   ← 同上
10.6s  v4-flash  out=166  reason=676    ← 只有这次正常
```

### ① 三次里两次没写出正文

`max_tokens=1000` 被思考链吃光（`reason=1000` 精确顶格）。`emit_guide_quick_take` 里
已有兜底 `text = (reply or "") or (reasoning or "")[:200]`，所以**不是空白**——
但用户看到的是**模型的内部独白前 200 字**，而不是一句给人看的初步思路。

这正是 Phase 11 提速时在 ITINERARY/HOTEL 上解决过的同一类问题（思考链 1.5 万字符
吃满 16000 预算），当时的解法是**在 system 里写思考纪律**。quick_take 这条漏了。

### ② 它还阻塞了采集 ~10 秒

图拓扑是 `parse → quick_take → collect` 的硬边。快答是一次 LLM 调用，采集是网络 I/O，
两者没有数据依赖——串起来纯属浪费。用户等的这 10 秒里，浏览器和小红书一动不动。

## 方案

### A. 思考纪律 + 预算保险

`GUIDE_QUICK_TAKE_SYSTEM` 追加一条（照搬 ITINERARY 那条已验证的写法）：

> 思考不要展开：最多两三行要点即可，把输出预算留给正文。

同时 `max_tokens` 1000 → 1600。**两条都要**：纪律负责让它别想太多，预算负责纪律漂移时
仍有正文空间（Phase 89 的教训——prompt 纪律在长上下文里必然漂移，不能只靠它）。

兜底逻辑保持不变，它是最后一道网。

### B. 快答与采集并行

**不改图拓扑**（那会牵动 checkpoint 与恢复语义）。改法是让节点**不等 LLM 返回**：

```
quick_take_node:
    msg_id = _add_streaming_message(cid)   ← 占位，必须同步、必须先做
    后台线程跑 emit_guide_quick_take(...)   ← 不 await
    立刻返回 {"msg_id": msg_id}
                ↓
    collect 立刻开始，与快答生成重叠
```

**占位仍然同步创建**——Phase 71 的顺序不变式没有松动：占位必须先于快答消息落库，
否则 `_is_running` 判本轮完成、前端停止轮询、完整版永远收不到。变的只是**快答的 LLM
调用**不再挡路。

用线程而不是 asyncio task：`emit_guide_quick_take` 是同步函数（内部 `llm.generate_with_reasoning`
是阻塞调用），包成 task 需要改造整条调用链；而 `quick_take_node` 本身是同步节点。
一个 daemon 线程最简单，且与仓库既有做法一致（记忆整理、崩溃续跑都是这么起的）。

### 三个必须处理的边角

1. **线程引用要留住**——不留会被 GC 掉。用模块级 set 持有，结束时自己移除。
2. **停止语义**：`emit_guide_quick_take` 内部已有 `is_cancelled(cid)` 检查（生成后、
   写消息前）。线程化后这个检查更重要——本轮可能已经结束，绝不能再往会话里塞消息。
3. **不等它结束**：整轮结束时不 join。快答迟到就迟到，它是增强；为它拖住终稿是本末倒置。

## 验收标准

`tests/test_guide_quick_take.py`（已存在，补用例）：

1. 思考纪律在 system prompt 里（防止后人重构时删掉）
2. `max_tokens` ≥ 1600
3. 正文为空时仍用 reasoning 兜底（既有行为不回归）
4. **`quick_take_node` 不等待 LLM 返回**：让假 LLM 阻塞 2 秒，断言节点在 0.5 秒内返回
5. **占位仍然同步创建**：节点返回时 `msg_id` 已存在（顺序不变式）
6. 快答线程抛异常不影响节点返回值
7. 本轮已被停止时，快答线程不写消息
8. `guide_quick_take=False` 时完全不起线程
9. 全量回归无新增失败

## 刻意不做

- **不改 LangGraph 拓扑**。把 quick_take 变成并行分支要动 checkpoint 与恢复语义，
  收益（同样 ~10s）不变而风险大得多。
- **不关闭思考模式**。`LLMClient` 没有暴露该开关，加参数要动所有调用方；
  而思考纪律是仓库里已验证有效的手段。
- **不动兜底逻辑**。它救过场，保留。
- **不为快答做重试**。迟到或失败都可接受，它是垫场的。
