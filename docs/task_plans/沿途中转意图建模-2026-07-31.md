# Task Plan · 沿途中转意图建模（2026-07-31）

## 问题（线上真实对话 f5f91bbc）

用户问「合肥出发，终点是武汉，帮我看一下**途经**有什么可以闲逛的地方，例如古镇」：

1. 第一轮：解析坍缩成 destination=武汉 → 产出武汉城市攻略，还推荐了武汉以南的
   咸宁羊楼洞（方向与行程相反）。
2. 第二轮补充「自驾」重问：解析把「未定的中途点」当成缺失目的地 → destination 空 →
   等了近 4 分钟得到一句反问「想去哪里呢」（其中 parse 一步 2.5min 是深夜 API 延迟，
   反问本身不该发生——终点武汉明明是已知的）。

根因：需求模型只有 `destination` 一个地点槽，「A→B 沿途/途中停留推荐」意图无法表达，
模型只能在「坍缩成终点攻略」和「当成目的地缺失」之间二选一。

## 方案（四层）

| 层 | 改动 |
| --- | --- |
| Schema | `Preference` 加 `origin`（出发地）+ `waypoint_trip`（是否在征集沿途停留点） |
| 解析 | PREF_SYSTEM：沿途请求 → waypoint_trip=true、origin=A、destination=B（终点已知**不反问**）；用户选定某个中途点后 → destination=该点、waypoint_trip=false、顺路背景写进 special_requirements |
| 采集 | `_xhs_query_plan`：waypoint 轮搜「{A}到{B} 沿途 {兴趣}」而非「{B} 旅游攻略」；TASKPLAN_SYSTEM 同样按沿途生成查询；waypoint 轮不复用上一轮（终点城市）的旧来源 |
| 生成 | 追加 waypoint 指令：只推荐**顺路**停留点（行进方向上、不明显折返），标注距起终点车程，正文围绕中途站组织，不写成终点城市攻略 |

## 同批次顺带修复（用户同日反馈）

- **停止链路**：budget/poster/反思无取消检查点 + `asyncio.run` 线程池 join 拖延终稿
  （详见 `docs/pitfalls/停止链路asyncio线程池join与记忆污染.md`）。修后停止 ≤2s 生效。
- **记忆污染**：旧行程 trip_state（国庆成都/预算5000）泄漏进无时间的新行程正文。
  `filter_foreign_trip_memories` + 注入块「记忆使用纪律」。

## 验收

- `tests/test_waypoint_trip.py`：schema 默认值、查询计划 waypoint 分支、生成指令内容、
  revision 复用门控。
- 线上复测原话「合肥出发，终点是武汉，帮我看一下途经有什么可以闲逛的地方，例如古镇」：
  不反问；推荐点位于合肥→武汉方向（如六安/桐城/潜山/太湖一线），不出现终点以南的咸宁。
