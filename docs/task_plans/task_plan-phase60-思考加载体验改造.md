# Task Plan — Phase 60：思考加载体验改造

## 目标

把对话生成期间分散的 spinner 与 progress 文本升级为一个持续更新的「智能体工作台」：
用户能看见当前阶段、最新动作、已等待时间和停止入口；进入流式正文后自然退场，减少长任务
像卡死、消息列表反复跳动的问题。

## 方案

### 前端状态归一

- 保留后端现有 progress 消息协议，不要求本期同步改接口；
- 从 progress 文案、流式占位和 reasoning 状态推断五个阶段：
  理解需求 → 搜集资料 → 整理方案 → 生成内容 → 检查优化；
- 运行期间把普通 progress 行收拢进工作台；登录接管、来源确认、深度推理提示等交互卡片
  仍按原样独立展示；
- 流式正文出现首段后隐藏工作台，继续使用流式光标，避免加载卡和正文争抢注意力。

### 视觉与动效

- 渐变思考核心、轨道粒子、呼吸光晕和活动状态 shimmer；
- 阶段完成/激活/等待三态平滑切换；
- 显示已等待时间、模式标签、最新动作和长时间无新进度提示；
- 工作台内提供明确的停止按钮；
- 手机端改为纵向阶段列表；
- `prefers-reduced-motion` 下关闭旋转、呼吸、shimmer 和入场动画。

### 涉及模块

- `frontend/src/interaction.ts`：阶段推断与时长格式化纯函数；
- `frontend/src/pages/Home.tsx`：工作台组件、运行计时和消息收拢；
- `frontend/src/index.css`：工作台布局、动效、移动端及低动态模式；
- `frontend/tests/`：阶段推断与视觉契约自动化测试。

## 验收标准

1. 发送普通攻略、酒店或深度研究问题后，只出现一个持续更新的思考工作台；
2. 后端 progress 文案能映射到合理阶段，已完成阶段显示勾选；
3. 最新动作和等待时间持续更新，30 秒无新进度时有明确提示；
4. 登录接管与确认卡片不被工作台吞掉；
5. 流式正文出现后工作台自然隐藏，正文继续稳定增量渲染；
6. 工作台停止按钮可触发现有停止接口；
7. 桌面端与 390px 手机端无横向溢出；
8. 开启减少动态效果后无持续旋转或闪烁动画；
9. `npm test`、`npm run lint`、TypeScript 类型检查与生产构建全部通过。

## 实施结果

- 已完成统一工作台、五阶段推断、运行计时、停滞说明、停止入口、流式退场；
- 已完成桌面/手机样式、低动态模式和反思循环阶段不倒退；
- 自动化测试、lint、TypeScript 类型检查和生产构建通过；
