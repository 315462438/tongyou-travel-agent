# 旧安卓适配清理与投票通知直达

## 目标与范围

接续 5b67dff 后的两项遗留工作：清理共享网页中只服务已退役 Android WebView 容器的代码；Web、Android、iOS 点击投票通知后切到对应日期并定位投票。保留旧 APK 的服务端 API 兼容性；旧 APK 使用自己的快照，不需要保留新 Web 中的桥接代码。

## 方案

1. 删除 nativeAndroid bridge、专属样式/启动就绪/下载劫持/震动/硬件返回分支。保留标准浏览器分享、下载、打印、手机布局和 Android 浏览器的性能降级。AndroidTripWorkspace 实际供手机网页版复用，重命名为 MobileTripWorkspace，不删布局能力。
2. 移除只测旧壳的浏览器脚本；共享的手机/桌面、分享、动效、行程回归改成标准浏览器路径，保留有效断言。
3. 投票通知保持现有 meta.trip_id / poll_id / day 协议。三端把目标携带到行程详情；行程数据载入后校验日期范围，使用投票现状校准日期，并定位卡片。普通群聊/行程通知不误切投票；旧通知缺失 day、整趟行程、删除投票或天数变动都能正常回退。
4. 目标须一次消费，轮询不能把用户后续手动切换的日期拉回；重复点击同一通知及从已打开的另一行程进入也必须正确。Web 特别修正 overlay 已挂载时换通知目标未切换行程的问题。

## 模块

- frontend/src：App、Home、Trips、通知、分享与交互反馈、MobileTripWorkspace 及相关 CSS。
- Android：通知目标纯函数、MainActivity 导航参数、TripsScreen 的日期与列表定位。
- iOS：独立 Foundation 路由值类型、AppRouter/TripRef、通知、行程加载与滚动定位。
- backend/tests：现有通知 day/poll_id 协议的回归断言；预期不改 API 或数据库。

## 验收

- Web 全量单测与构建；浏览器本地假数据回归通知目标/跨行程/重复点击、手机与桌面布局、分享操作；不访问真实账号数据。
- Android 单测/lint/正式签名 APK；Swift 路由逻辑可执行测试与 iOS Release 编译。
- 按用户既有指示不启动 Android/iOS 模拟器，不将构建通过当作真机交互验收。
- 更新踩坑、测试说明及发布管理文档，保留与本任务无关的 dsh-skin-plugin 未跟踪目录。

## 实施补充

- 共用行程组件使用 `MobileTripWorkspace` 名称，CSS 使用独立 `compact-trip-*` 前缀，避开既有列表天数徽章的 `mobile-trip-days`。
- 浏览器验证中修正了共享工具栏群聊图标的可见性；分享状态 Hook 移到消息组件 early return 之前，消除既有条件调用错误。
- 测试说明见 `docs/test_cases/旧安卓适配清理与投票通知直达-2026-11-10.md`；原生均不启动模拟器。沿用此前“上线”的授权，验证后发布 Web、Android，并覆盖安装 iPhone。
