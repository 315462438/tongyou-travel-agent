# Task Plan — Phase 55：geocode 持久缓存（提速）

## 背景
读了 ai-agent-book chapter5（Agent 提速方法论：并行/缓存/模型分层/永续会话/早执行）。
对照本项目，模型分层、流式、浏览器池、限流并发都已做；**缺口是缓存**。
`geocode_names(names, city)` 在导入攻略、加地点、AI 起草、生成海报等处被反复调用，
每次都把相同地名（宽窄巷子、布达拉宫…）重新打高德 geocode——有并发限流但**无跨请求缓存**。

## 方案（低风险纯增益）
- 新表 `travel_geocode`：`key="城市|地名"` → `location="lng,lat"`（`create_all` 启动自动建）。
- `geocode_names` 改三步：
  1. 一次 `IN` 查缓存；
  2. 只对**未命中**的地名打高德（保留原 Semaphore 限流并发）；
  3. 新拿到的坐标 `merge` 写回缓存（只存命中的；写失败不影响本次结果）。
- 只缓存命中（有坐标）的；未命中不缓存——名称可能后续被修正，留待重查。
- key 带城市前缀，避免不同城市同名地点误命中。

## 为什么不做「高德∥浏览器并行」（清单里的 ②）
- 收益有限：高德是秒级 HTTP，浏览器抓取是长尾且**共用单条 CDP 会话 + MCP 串行锁 + 每用户
  浏览器池串行**，物理上无法在一个浏览器里真并行；并行只能省下高德那几秒。
- 风险集中在最敏感的链路：`asyncio.gather` 两分支后，停止按钮的 `TurnCancelled` 取消语义、
  异常隔离都要重做，性价比低。故暂不做。

## 验收
- `test_geocode_cache.py`：命中跳过高德、部分命中只查未命中、未命中不缓存、city 维度隔离——4 例过。
- 现有 trip 测试直接 monkeypatch `geocode_names`，不受影响；全量 412 过。
- 线上：新表启动自动建，导入/加点/海报重复地名不再打高德（降 QPS、提速）。
