# Task Plan · 旅行预演与灵感入口改造（2026-08-07）

## 背景与问题

平台当前已经具备攻略、酒店、预算、路线图、协同行程、记忆和深度研究等完整能力，空状态也完成了
“热门目的地 + 三下起步”改造。但首屏的主要交互仍然是聊天输入框和能力卡片，用户需要先理解
“我该怎么问”，最终心智仍接近通用 AI 对话产品；平台已有的浏览器采集、路线、预算与风险检查能力
没有在第一屏形成一个清晰、可传播的产品承诺。

## 目标

把登录后的空状态从“问 AI 一个旅行问题”升级成“把旅行灵感变成可预演的计划”：

1. 默认入口为**旅行预演**，用少量结构化选择生成一条可直接执行的真实规划需求；
2. 增加**收藏炼金**，支持粘贴攻略/小红书等公开链接并交给现有浏览器链路提炼地点、去重和排路；
3. 增加**预算盲盒**，从出发地、预算、天数和旅行氛围反推候选目的地，自动使用深度推理；
4. 首屏明确展示预演将检查的四类结果：路线、节奏、预算、风险/备选；
5. 保留自由聊天、平台热门目的地和“三下起步”，避免已有能力回退；
6. 桌面与移动端均能在首屏完成输入，不产生横向溢出。

## 方案

### 1. 灵感工作台

在 `Home.tsx` 新增 `InspirationLaunchpad`：

- 三个模式 tab：旅行预演 / 收藏炼金 / 预算盲盒；
- 每个模式只要求最少必要字段，未填满也能生成自然、诚实的需求；
- 主 CTA 直接调用现有 `send()`，不新增平行后端流程；
- 预算盲盒通过发送级覆盖强制开启 `deep_reasoning`，避免 React 状态更新延迟导致本条仍走普通模式；
- 自由 Composer 降为“直接问 17同游”，继续支持任意旅行问题。

### 2. 结构化 prompt builder

在 `interaction.ts` 增加无副作用构造函数：

- `buildJourneyPreviewPrompt()`：要求产出逐日时间轴、预计步行/交通、预算、疲劳点、风险和备选；
- `buildInspirationImportPrompt()`：要求打开用户给出的公开链接，提取真实地点、去重、校验并排成可执行路线；
- `buildBudgetRoulettePrompt()`：要求在预算约束内给 3 个候选目的地，再给首选方案与费用口径；
- `isPublicInspirationUrl()`：前端只接受 `http/https` 链接，拒绝伪协议和纯文本误提交。

构造函数不虚构用户未提供的出发地、预算或天数，缺失信息用“未确定/请给合理假设并标注”表达。

### 3. 视觉与响应式

- 重写首屏主标题与说明，核心承诺为“把收藏夹里的旅行，提前过一遍”；
- 灵感工作台使用一张主面板而不是继续堆四张同质能力卡；
- 移动端字段单列、tab 可横向滚动、CTA 保持拇指友好；
- 尊重 `prefers-reduced-motion`，不增加持续性大动画。

## 明确不做（本期边界）

- 不开放匿名真实生成：当前邀请码体系和浏览器池有成本/滥用边界，匿名额度需要独立风控设计；
- 不宣称已支持图片内容理解：现有上传接口只保存图片，当前主模型链没有可靠视觉解析；
- 不新增第二套攻略生成或数据库表；
- 不在本期实现同行人投票、实时位置感知和旅后照片电影，它们作为后续阶段接在本入口之后。

## 验收标准

1. 新会话首屏默认看到旅行预演，而不是先看到空白聊天框；
2. 三种模式均能生成语义完整、长度受限的 prompt 并发往现有会话 API；
3. 预算盲盒本条请求一定携带 `deep_reasoning=true`；
4. 收藏炼金拒绝空值与非 HTTP(S) 链接，并给出就地错误提示；
5. 原自由输入、热门目的地、三下起步、深度推理和沙箱开关仍可使用；
6. 390px 与桌面布局无横向溢出，键盘与屏幕阅读器可识别 tab/字段/错误；
7. 前端单测、lint、TypeScript 和生产构建全部通过。

## 实施记录

- 首页主标题改为“把收藏夹里的旅行，提前过一遍”，默认展示三模式灵感工作台；自由 Composer、
  三下起步和平台热门目的地移动到工作台之后，原能力未删除。
- `interaction.ts` 新增三类 prompt builder、HTTP(S) URL 校验与分享文本链接提取；缺失信息不编造，
  收藏链接去重并限制 5 条。
- `send()` 增加发送级 `deepReasoning` 覆盖；收藏炼金和预算盲盒当前请求直接发
  `deep_reasoning=true`，同时点亮持久开关供用户理解后续状态。
- onboarding 异步返回常驻城市时只补空值，不覆盖用户已输入的出发地。
- 新增桌面/移动响应式样式、错误 live region、tab 语义和 reduced-motion 兼容现有全局策略。
- 新增 4 组交互纯函数/首屏视觉契约回归；前端测试 56/56 通过，lint 无新增 warning，生产构建通过。
- `frontend/dist` 已同步到 `backend/static`，并清理旧的哈希构建文件，后端托管产物与源码构建一致。

## 线上反馈后的方案调整（2026-08-07）

首版上线后反馈：“界面太花哨，三个功能相似”。复盘确认这是信息架构问题，不是换配色能解决：

- 旅行预演、收藏炼金、预算盲盒底层都只是把不同输入翻译成现有 Agent 请求，不应被包装成三个
  等权产品 tab；
- 极光、渐变标题、三套模式色、玻璃卡、四项能力格和下方快捷卡同时争夺注意力；
- 用户必须先理解产品内部分类，违背“直接说一个念头就开始”的目标。

调整为**单入口自动分流**：

1. 一个主输入同时接受目的地或分享文本；检测到 URL 自动走收藏整理；
2. 主输入留空但填写出发地 + 预算时，自动走预算推荐；
3. 其他短目的地输入走旅行预演；
4. 出发地、天数、预算、节奏作为同一行轻量约束，不再切换模式；
5. 自由 Composer 默认折叠为次级入口，避免与主输入竞争；
6. 移除空状态 Aurora、渐变标题、三套模式背景和大块功能解释，热门目的地缩成轻量灵感按钮。

### 第二轮视觉反馈（同日）

实际截图反馈确认：单入口的信息架构是对的，但把 Aurora、渐变标题和动态效果全部拿掉后，首屏退化成
普通后台表单，品牌情绪与“旅行向往感”不足。最终调整原则：

- **保留单入口**，不恢复三个相似 tab；
- 恢复顶部 Aurora、渐变流光标题、玻璃面板、CTA 渐变和轻量入场/悬浮反馈；
- 动效只服务于氛围和操作反馈，不让多个功能块重新争夺注意力；
- `prefers-reduced-motion` 下关闭标题流光、面板光带和位移动画。

### 第三轮视觉精修（同日）

线上截图显示恢复后的光效覆盖面积和饱和度偏高，标题在动画中会形成明显的红蓝断层，输入面板内部
又偏平，整体仍不够精致。本轮不增加任何功能块，只校准视觉层级：

- Aurora 收束在首屏上半部，降低振幅、速度、饱和度与透明度，保留可感知但不抢内容的动态氛围；
- 标题改为连续的蓝—靛—紫—玫色相，减小背景位移并放慢流光，避免橙红与高饱和蓝硬切；
- 提高副标题和表单提示的对比度，保证光效背景上仍清晰可读；
- 主面板采用轻微冷色玻璃渐变、内描边和更克制的投影，约束栏增加上下层次；
- 热门目的地由下划线文字改为轻量胶囊，使可点击性更明确，但不恢复卡片堆叠；
- 自动化视觉契约补充“柔和 Aurora、连续标题渐变、胶囊建议”的断言，并继续覆盖减弱动画模式。
