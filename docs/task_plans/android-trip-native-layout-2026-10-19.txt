目标：把 Android 协同行程详情按 iOS TripBoard 的层级重新排版，解决桌面头部/多组导航/固定内容高度叠加导致的比例失调。不是移植 SwiftUI 二进制，复用原 API 与业务操作，提供 Android 专属页面结构。

方案：Android 独立导航栏（返回、简短标题、群聊、更多）；单一纵向滚动正文（行程概况、日期胶囊、当天概览、行程/地图分段、编号时间线）。详情隐藏全局底栏，退出详情恢复。工具收进更多及独立工具界面，保留邀请、原攻略、导出、旅行账本、增减天数、AI 提案、日期设置等现有能力。
地点卡片采用 iOS 的编号轨道 + 名称/时间 + 描述/标签 + 编辑/导航/更多，地图保持当前天；只在显示时挂载地图。表单/确认/群聊等复用业务组件并做 Android 触控尺寸适配。
范围：frontend Android 专属组件与 CSS，Trips.tsx 接入与返回层级；Android 0.3.0 (4) 独立签名包。Web/iOS 不部署 UI 变化，不改 API/数据结构。

验收：320/390/430 宽度与横屏/大字体情况下无横向溢出；正文一次纵向滚动可访问最后地点；顶部栏不挤压正文；唯一日期选择；地图/行程/工具切换保持天数；创建/编辑/移动/删除的请求仍正确；权限与未定位/未知费用提示保留；菜单可关闭/系统返回逐层退出；编辑键盘下保存可见；原网页协同行程回归。
测试：浏览器假 API 的长行程/长标题/30天、空天/成员编辑/owner/定位中/失败等；模拟器原生 WebView 回归与协同行程实际渲染检查；签名包内快照验证、升级包版本/证书、公网下载哈希。

完成：上述用例通过，Android 0.3.0 (4) 同签名覆盖安装成功，版本化公网下载与完整 SHA 已核验。网页回归发现日期弹层焦点偏离时 Escape 未关闭，已在共享组件修复捕获监听；本次只随 APK 发布，未部署 Web。
