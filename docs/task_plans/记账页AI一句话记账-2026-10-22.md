# 记账页 AI：一句话记账（已上线：网页 / 安卓 0.10.5 / iOS 1.0.20）

## 目标

用户在记账页说/打一句「今天午饭拉面 1200 日元，打车 2800，买药妆一万二」，
智能体拆成多条账单，自动填好标题、金额、币种、分类、日期，确认后一次记入当前账本。

## 方案

### 流程：拆单 → 预览卡 → 一键记上

1. `POST /api/ledgers/{book_id}/ai-draft {text}` → 返回 `drafts[]`（**不写库**）。
2. 前端在输入框下方展示草稿卡片：每条可改金额/币种/分类/日期，可删；底部「全部记上（N 笔）」。
3. 点确认 → `POST /{book_id}/entries/batch` 一个事务全部入账（一条不合法就都不记）。草稿生成时就带 UUID，
   沿用 `_replay` 的按 id 幂等，重复点击、网络重试都不会重复记账；同 id 不同内容返回 409。

不在第一版做「说完直接入账」：账本可能是多人共享的，记错币种（¥ 当成人民币还是日元）会直接污染所有人的汇总，
而预览只多一次点击。

### 抽取（`app/agent/ledger_draft.py`）

- `LLMClient.parse()` + schema `LedgerDrafts{items:[title, amount, currency, category, spent_on, note, currency_guessed]}`。
  分类、币种用枚举约束为账本已支持的集合（`CATEGORIES` / `CURRENCIES`），抽出后再过一遍 `EntryBody` 校验。
- **金额照抄，不让模型算数**（同 Phase 67/113）：「两人一共 200」记 200，不替用户人均；「一万二」这种中文数字由模型
  转成 12000 —— 这是唯一允许的转换，单测钉住常见写法。
- **日期在服务端算**：模型只输出 `today / yesterday / 2026-10-21` 这类相对或绝对标记，服务端按用户时区换成日期，
  不让模型自己推「今天是几号」。
- **币种默认值**（模型拿不准时）：①文本里明说的（日元/円/RM/$）②账本关联行程的目的地国家 → 当地货币
  ③该账本最近 10 笔最常用的币种 ④CNY。「¥」「元」在日本行程里有歧义，标 `currency_guessed=true`，
  预览卡上该字段高亮提醒用户看一眼。
- 思考档位：`low`（保留思考以认中文数字、判币种是否明说，但这是用户在等的交互）。服务器实测 5 句 0.7–1.8s，全部正确。
- 输入走 `wrap_external` 之外的普通用户输入通道（这是用户自己的话，不是外部内容）；输出只进草稿，不进记忆。

### 接口要不要做成 MCP

**第一版做成后端内部工具函数，不做 MCP。** 智能体和账本在同一个后端进程里，MCP 只多一层进程/协议边界，
权限还得在 MCP 那侧重做一遍（现在 `_book(db, id, user, "edit")` 一行就校验了成员和角色）。
真正需要 MCP 的场景是让**外部**智能体（Claude Desktop、别的 App）读写用户账本，那需要用户级授权令牌和
只读/可写范围，属于单独立项。

工具函数会写成 `draft_entries(user, book_id, text)` / `commit_entries(user, book_id, drafts)` 两个纯后端函数，
记账页接口和将来主对话里的「记一笔」都调同一份，以后要包 MCP 也只是再套一层。

## 验收标准

- 「午饭拉面1200日元，打车2800，药妆一万二」在日本行程账本 → 3 笔 JPY，分类 餐饮/交通/购物，金额 1200/2800/12000。
- 「昨天酒店 480」→ 日期为昨天、分类住宿、币种按默认链推断。
- 「¥300」在日本行程账本 → 币种 JPY 且 `currency_guessed=true`，卡片高亮。
- 确认两次只入账一次（幂等）；无 edit 权限的成员看不到输入框、接口 403/404。
- 抽取失败或什么都没抽到 → 提示「没认出金额，换个说法试试」，不生成空草稿。
- 后端单测：中文数字、币种默认链、日期换算、枚举外值兜底为「其他」、`EntryBody` 校验失败的条目被剔除并告知。

## 实施记录

- 「今天」由客户端传本地日期，服务端只接受与服务器日期相差 ≤1 天的值，否则用服务器日期。
- 等模型时先 `db.rollback()` 释放事务，不攥着连接。
- 「需要看一眼」的判定：没写币种时，新账本且没写「元/块/¥」，或写了「¥/元」却落在外币上。歧义是整句级的
  （「饮料¥300 地铁 260」两条都会提醒），模型侧不做逐条判断。
- 网页：`Ledger.tsx` 的 `QuickEntry`（Enter 识别、草稿逐项可改、改币种即清除提醒、手机上草稿出现时滚入视野）；
  iOS：`LedgerView.swift` 的 `LedgerQuickEntry`。
