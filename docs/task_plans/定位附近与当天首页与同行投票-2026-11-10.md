# 定位回答「附近」、出行当天首页、同行人投票（2026-11-10）

## 要解决的问题
1. 问「附近有什么」时被反问「你在哪个区」——App 本来可以知道。
2. 行程开始后首页仍只是入口，今天去哪要自己翻行程。
3. 多人出行最卡的是做决定（住哪家、哪天走），群聊里来回问没有结论。

界面原则不变：不加主入口。定位无界面；当天卡只在有行程进行/临出发时出现在首页顶部；投票是行程工具里的一项。

## 方案
### 定位
- 客户端只在消息含「附近/周边/周围/离我/就近…」时取一次定位，随消息发 `location`（WGS-84 `lng,lat`）；拿不到照常发。
- 后端 `_TURN_LOCATION[cid]` 只活一轮，不进库、不进记忆；`amap.locate_device` 用高德接口转 GCJ-02 并逆地理；
  `_nearby_block` 把位置写进 prompt（标明临时位置、不要反问），再用一次 `classify(off)` 取品类关键词 →
  `amap.search_around` 按距离查周边 → 清单进 prompt，并作为地点卡候选。
- 只在直答链路生效。安卓加 `ACCESS_COARSE_LOCATION` + WebView 定位授权（仅本站来源）；iOS 加 `LocationOnce` 与用途说明。

### 当天首页
- `GET /api/trips/today?date=YYYY-MM-DD`（日期由客户端按本地时区给）：进行中的行程 → 第几天 + 当天地点（含导航）；
  否则 7 天内最近要出发的 → 倒计时；都没有 → `{"trip": null}`，首页不显示卡。必须声明在 `/{trip_id}` 之前。
- 依赖行程设置了出发日期；没设日期的行程不会出现。

### 投票
- 表 `travel_trip_poll` / `travel_trip_poll_vote`（(poll,user) 一行，改票就地改）。
- `GET/POST /trips/{id}/polls`、`POST …/{pid}/vote`、`POST …/{pid}/close`、`DELETE …/{pid}`；全部过成员校验；
  结束/删除限发起人或行程创建者；发起时同事务给其他成员写 `trip_poll` 通知；投票本身不写时间线。
- 网页/安卓：行程工具栏「投票」；iOS：行程右上菜单「一起投票」。

## 未做
- 投票结果不会自动写回行程（需要人看结果后自己改）。
- AI 自动生成投票选项。
- guide / 深度研究链路不使用定位。
