# 三端按钮交互反馈（2026-10-22）

## 目标

用户反馈：iOS / 安卓 / 网页「点完按钮之后交互有点生硬」。诊断后的具体缺口：

| 端 | 现状 | 缺口 |
| --- | --- | --- |
| 网页 + 安卓（安卓是 WebView 套网页） | 全站 `:active` 规则只有 3 条；按钮按下无任何形变/波纹 | 手指按下那一刻没有「我接住了」的反馈；移动端 `:active` 在触屏上还经常不触发 |
| 安卓原生壳 | 无任何触感 | 保存成功/失败、切换标签全是静默的 |
| iOS | 玻璃按钮自带交互，但**列表行（行程、地点、账本、账单、候选卡）都是 `.buttonStyle(.plain)`**，按下零反馈；底栏切换无动画无触感；保存成功只有 sheet 消失 | 行按下无反馈、成功/失败无触感 |

**实用性说明**（项目取舍标准见记忆「实用性优先」）：这里做的都是「按下确认 + 结果确认」两类反馈，
解决的是「我点到了没有 / 保存成功了没有」这个真实疑问；不做彩带、吉祥物这类纯观赏动效。

## 方案

### 网页 + 安卓（`frontend/src/pressFeedback.ts`，`main.tsx` 安装一次）
- 文档级 `pointerdown` 委托，命中 `button / [role=button] / [role=tab] / a.btn / summary`（排除 disabled、
  `aria-disabled`、`[data-no-press]` 祖先）。
- **按压形变**：JS 设 `data-pressed="sm|lg"`（面积大的卡片只缩 1.5%，小按钮缩 4%），松手/取消/离开移除。
  用 CSS 独立属性 `scale` 而不是 `transform`——**不覆盖**元素已有的 `transform`（FAB 定位、hover 上浮）。
  选择器包在 `:where()` 里零特异性，组件自己写了 `scale` 的照旧生效。
- **波纹**：在 `document.body` 上叠一个与按钮同位置、同圆角的 fixed 容器（pointer-events:none），
  里面放扩散圆。**不往按钮内部插节点、不改按钮的 position/overflow**——全站上千个按钮的布局一处不碰。
  颜色取按钮的 `currentColor`，深浅色模式自动适配。
- `prefers-reduced-motion: reduce` 下不形变、不波纹（触感保留）。
- **触感（仅安卓 App）**：`nativeHaptic(kind)` → `TongyouNative.postMessage({type:'haptic'})`。
  克制使用：切换类控件（`role=tab`、`aria-pressed`、`aria-checked`）给轻触；
  Toast `success` 给确认、`error` 给拒绝——全站成功/失败都已经走 Toast，一处接入全站生效。
  普通按钮按下**不**震（每次点击都震是噪声）。
- Toast 成功图标加一个弹入。

### 安卓原生（`MainActivity.onMessage`）
- 新增 `case "haptic"`：`tick`→`CLOCK_TICK`，`confirm`→`CONFIRM`(API30+，否则 `VIRTUAL_KEY`)，
  `reject`→`REJECT`(API30+，否则 `LONG_PRESS`)。`performHapticFeedback` 自带遵循系统触感开关。

### iOS
- `TravelPressStyle` 挪进 `Design/Glass.swift` 作为公共样式，按下时给极轻 impact。
- 所有 `.buttonStyle(.plain)` 的行/卡片改用它（底栏 tab 除外，tab 单独处理）。
- 底栏：选中图标切 `.fill` + `symbolEffect(.bounce)` + `.sensoryFeedback(.selection)`。
- `Haptics.success()/error()`：在新建行程、保存/删除地点、调整顺序、编辑行程、记一笔、
  保存账本、加入账本等保存点调用（sheet 随即 dismiss，`.sensoryFeedback` 挂在将消失的视图上不可靠，故用命令式）。
