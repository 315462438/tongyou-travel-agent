# 标签页未读提醒（Phase 98）

2026-08-18

## 背景：为什么不是浏览器推送

Phase 97 把群聊消息接进了通知中心，但同行者**必须打开页面**才看得到铃铛
（30s 轮询 + 窗口聚焦刷新）。自然的下一步是 Web Push，实测后否掉了。

Web Push 的投递由**浏览器厂商**的推送服务中转，从服务器实测：

```
fcm.googleapis.com                  连不上        ← Chrome / Edge 走这里
updates.push.services.mozilla.com   HTTP 406（通）
api.push.apple.com                  HTTP 405（通）
```

**FCM 连不上，而 Chrome 和 Edge 是绝大多数用户。** 这还不只是服务器出不去：
国内用户的 Chrome 本身也要和 FCM 保持长连接，那条同样不通——把服务器搬到境外也没用。
Firefox 国内份额极低；Safari 收 Web Push 必须先「添加到主屏幕」装成 PWA，转化率可忽略。

所以「人不在这个标签页时叫住他」，只能靠**浏览器自己就会显示**的东西。

## 方案

未读时改两处：

1. **标签页标题**：`(3) 17同游 · 一起规划，一起出发`
2. **favicon**：在现有图标上叠一个红点

无需权限、无需 Service Worker、不依赖任何外部服务，覆盖最高频的真实场景——
**人挂着页面在干别的事**。

### 实现

- 纯函数 `badgedTitle(baseTitle, unread)` 放 `interaction.ts`（项目惯例：纯逻辑可单测）
- hook `useAttentionBadge(unread)` 放 `hooks/`，在 `Home.tsx` 接 `notificationUnread`
  （公告 + 社交 + 群聊的合计，Phase 97 的群聊未读天然计入）
- favicon 用 **canvas 在现有图标上叠红点**，而不是另备一张「带红点的图」——
  品牌图标只有一份，换图标时不用同步维护第二份。CSP 的 `img-src data:`（Phase 69）允许 data URI

### 三个要点

1. **原始标题只在挂载时捕获一次。** 拿 `document.title` 反复加工会叠成 `(1) (2) 标题`——
   这是这类功能最容易写出来的 bug，所以把它做成纯函数并用一条性质钉死：
   `badgedTitle(badgedTitle(t, 1), 2) === badgedTitle(t, 2)`
2. **favicon 只在「有/无未读」翻转时重画**，不是每轮轮询都画（轮询 30s 一次，
   每次重画是白费的 canvas 开销和潜在闪烁）
3. **失败静默降级**：favicon 画不出来时标题提醒照常工作

## 验收标准

`frontend/tests/interaction-utils.test.mjs` 追加 4 条：

1. 未读数拼进标题，0 时还原
2. **反复加工不叠加**（核心性质）
3. 超过 99 显示 `99+`，且 `99+` 的产物能再剥干净
4. 脏输入（空标题 / 负数 / 小数 / NaN）不炸

外加 `npx tsc --noEmit` 与 `npm run build` 通过。

## 刻意不做

- **不做 Web Push**，理由见上（主要用户群收不到）
- **不做微信服务号模板消息**：那是唯一能在国内触达「完全离开页面」用户的路径，
  但需要认证服务号 + 用户关注并绑定，是产品决策不是技术选型，另行评估
- **不做标题闪烁**（在两个标题间来回切）：干扰大于价值，静态计数已经够
- **不按窗口是否聚焦区分**：Gmail/Slack 都是有未读就显示，简单且不意外
