## 0. Bug：侧栏收起后无法展开

`.sidebar-expand` 是 `position: fixed; z-index: 20`，`.app-topbar` 是
`position: relative; z-index: 24`，二者同在**根层叠上下文**（`.app` 只有 `position: relative`
无 z-index，不成上下文；`.main` 也没有）。topbar 有不透明背景 + `backdrop-filter`，
于是把展开按钮整个盖住 —— 侧栏一收起就再也展不开。

`.app.view-desktop.collapsed .app-topbar { padding-left: 64px }` 本就是给这个按钮留位的，
说明布局意图是对的，**只有层叠顺序错了**。改 `z-index: 26`（高于 24，低于
`.composer-menu-mask` 的 30）。

## 1. 角色管理

`PATCH /api/admin/users/{user_id}/role`，body `{is_admin: bool}`。

防呆（都在服务端）：
- 不能改自己的角色（避免把自己锁在外面）
- 不能把**最后一个** admin 降级（系统会没有管理员，无法恢复）

前端：用户管理面板每行加「设为管理员 / 取消管理员」按钮 + 二次确认。

## 2. 邀请码

现状 `settings.register_invite_code` 是**写死在 .env** 的单一常量，改一次要重启服务。

新表 `travel_invite_code`：`code` / `created_by` / `max_uses`(默认 5) / `used_count` /
`active` / `created_at`。

| 路由 | 说明 |
| --- | --- |
| `GET /api/admin/invites` | 列表：码、已用/上限、状态、创建时间 |
| `POST /api/admin/invites` | 生成新码（可传 max_uses，默认 5） |
| `DELETE /api/admin/invites/{code}` | 停用（不删，保留审计痕迹） |

注册校验顺序（**兼容优先，不能把存量流程弄坏**）：
1. DB 里有 active 且未用满的码 → 命中即 `used_count += 1`
2. 否则回退 `settings.register_invite_code`（.env 那把老钥匙继续有效）
3. 两者都没配 → 开放注册（本地开发行为不变）

**并发**：`used_count` 递增必须用**带条件的 UPDATE**
（`WHERE code=… AND used_count < max_uses`）并检查影响行数，
不能「先读后写」——两个人同时用最后一个名额会双双通过。

## 3. 公告

新表 `travel_announcement`（`title`/`content`/`created_by`/`created_at`）
+ `travel_announcement_read`（`announcement_id`+`user_id` 复合主键）。

**不为每个用户复制一份公告**（28 个用户 × N 条公告 = 无意义的写放大），
未读 = 「存在公告且我没有对应的已读行」。

| 路由 | 权限 |
| --- | --- |
| `GET /api/announcements` | 登录：列表 + 每条是否已读 |
| `GET /api/announcements/unread` | 登录：未读数（喇叭红点，低频轮询） |
| `POST /api/announcements/{id}/read` | 登录：标记已读 |
| `POST /api/admin/announcements` | admin：发布 |
| `DELETE /api/admin/announcements/{id}` | admin：撤下 |

前端：顶栏喇叭图标 + 红点 → 抽屉列表（标题/正文/时间），打开即标记已读。

## 4. 图片与表情

**表情**：纯前端 emoji 选择器（常用 8 组 × N 个），插入到输入框。
不引第三方库、不做自定义表情包 —— 微信那种「自带小表情」用 Unicode emoji 即可覆盖。

**图片**：新表 `travel_upload`（`id`/`user_id`/`mime`/`size`/`created_at`），
文件落 `settings.upload_dir`（默认 `{tmp}/travel_uploads`）。

| 路由 | 说明 |
| --- | --- |
| `POST /api/uploads` | 登录：multipart 单图，校验 MIME 白名单 + 大小上限 |
| `GET /api/uploads/{id}` | **登录**：按 id 取图 |

消息里以 `![](/travel/api/uploads/{id})` 形式内联，客服与行程群聊共用同一套。

安全要点：
- 只认 `image/png|jpeg|webp|gif`，且**用文件头实际探测**，不信 `content-type`
- 大小上限 `upload_max_bytes`(5MB)
- 存盘文件名用 uuid，**不使用用户提供的文件名**（路径穿越）
- CSP 的 `img-src 'self'` 已允许同源，无需放宽
