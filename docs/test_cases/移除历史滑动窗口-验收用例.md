## 核心不变式

> **模型可见的历史边界只由日志里的 `surface_op='replace'` 事件决定。**
> `_assemble_history` 是纯投影读取，自己不截窗。

## 用例

| # | 用例 | 断言 | 对着哪个后果 |
| --- | --- | --- | --- |
| 1 | 未超限 → 全量 surface 逐字 | 16 条消息全在，摘要为空 | 追问「解释上一轮推荐」要看得到攻略全文 |
| 2 | 改 `history_rounds` 不影响装配 | `history_rounds=1` 与 `=20` 返回**完全相同** | Phase 89 docstring 点名的「边界追溯性移动」 |
| 3 | **无 replace 就无边界移动** | 折叠一次后再追加一轮，`replace` 计数不变且 `second[:len(first)] == first` | 前缀缓存命中的充要条件；滑动窗口破坏的就是这条 |
| 4 | 超限触发就地折叠 | `update_history_summary` 被调用一次 | 不再静默砍 |
| 5 | 折叠留痕且不删原文 | 表里恰好多 1 行、`surface_op='replace'`、`role='summary'` | Phase 91 「压缩不删除任何东西」 |
| 6 | 近窗自身超字数时收窄 keep | 折叠后 `_history_chars(msgs) <= limit` | 否则 `len(live) <= keep` 永远早退 → 滑动窗口原样回来 |
| 7 | 折叠抛异常不影响本轮 | 仍返回可用历史 | 旁路是增强不是前置条件 |
| 8 | **紧急降级必留痕** | 丢消息时打 `ERROR`，日志含 `still over limit` | 改造前是偶发/单轮/自愈/无日志的静默 bug |
| 9 | 降级至少保留一条 | 单条 5000 字 + limit=10 → 返回 1 条 | 不能让模型连上文都没有 |
| 10 | 老会话仍读 `conversation.history_summary` | 摘要含「预算3000」 | Phase 91 存量兼容不能丢 |
| 11 | 未超限不注入存量摘要 | 摘要为空 | 没有遮蔽时注入只会与全文重复 |
| 12 | 本轮用户消息去重 | 历史里不含本轮原话 | 它会作为「用户最新要求」出现在末条 user |

## 手动回归（线上）

1. 找一个消息数 > 10 且总字数 < 60000 的旧会话，追问一句 → 应看到**全文历史**注入
   （`meta.context_manifest.history_mode == "verbatim"`，`history_count` 等于全部消息数）。
2. 制造超限会话后连发两轮 → `travel_message` 里 `surface_op='replace'` 只应新增
   **一条**，不是两条。
3. `journalctl -u travel-backend | grep "still over limit"` 应为空。有输出说明折叠
   失败了（LLM 故障），此时才会丢消息 —— 这行日志就是当初缺的那个记录。

## 踩坑

测试 fixture 的 `created_at` **必须早于 `now()`**。折叠写的 `replace` 行用 DB 默认时间，
而 `derive_surface` 按 `created_at` 排序并且不允许遮蔽自己之后的消息 —— 种子数据用未来
时间戳会让 replace 排到最前面，**遮蔽区间静默失效**（表面现象是「折叠了但历史没变短」）。
