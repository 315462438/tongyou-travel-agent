## 自动化用例

| 编号 | 场景 | 断言 |
| --- | --- | --- |
| A1 | 旅行预演完整输入 | prompt 包含目的地、出发地、预算、步行/交通、风险和雨天备选 |
| A2 | 旅行预演缺少可选信息 | 不编造出发地和预算，明确要求模型标注合理假设 |
| A3 | 旅行预演缺目的地 | builder 返回空，UI 就地提示，不创建空会话 |
| A4 | 分享文本混有标题/口令 | 只提取其中 `http/https` 链接 |
| A5 | URL 去重与数量限制 | 相同 URL 只保留一次，一轮最多 5 条 |
| A6 | 危险/无效协议 | `javascript:`、`file:` 和纯文本不能进入浏览器任务 |
| A7 | 收藏炼金任务语义 | 明确要求实际读取、提取地点、去重、披露失败链接，不做泛泛改写 |
| A8 | 预算盲盒必要字段 | 缺出发地或预算时不生成 prompt |
| A9 | 预算口径 | 要求往返大交通、3 个差异候选和超支降级方案 |
| A10 | 自动分流 | URL 优先走收藏整理；主输入为空且有出发地+预算时走预算推荐；其他走预演 |
| A11 | 深度推理路由 | 收藏整理与预算推荐调用 `onLaunch` 时携带 `deepReasoning: true` |
| A12 | 次级能力不丢 | 自由 Composer 可展开，真实热门目的地作为轻量建议 |
| A13 | 视觉与信息架构 | 保留柔和 Aurora、连续冷色渐变标题和玻璃面板，但没有三个模式 tab |
| A14 | 减少动态效果 | reduced-motion 下关闭标题流光、面板光带和位移动效 |
| A15 | 移动端契约 | `view-mobile` 下约束两列、主操作单列，无固定宽度溢出 |
| A16 | 视觉精修契约 | Aurora 高度/透明度受限，标题不含橙红硬切，热门建议使用轻量胶囊边界 |

## 人工走查

| 编号 | 步骤 | 期望 |
| --- | --- | --- |
| M1 | 新建对话 | 首屏仍只有一个主输入面板；极光集中在顶部且不压低文字对比，标题蓝紫玫连续过渡，无三模式 tab |
| M2 | 输入“阿勒泰”、4-5 天、松弛、预算 6000 | CTA 为“开始规划”，消息包含约束与行程体检要求 |
| M3 | 主输入粘贴含两条链接的分享文本 | 状态提示识别 2 条链接，CTA 自动变成“整理成行程”，以深度推理发送 |
| M4 | 主输入留空，只填合肥、3000 元 | 状态提示按预算推荐，CTA 自动变化，并要求现实交通成本 |
| M5 | 点击热门目的地建议 | 地名填入同一个主输入，不跳到另一套界面 |
| M6 | onboarding 延迟返回常驻城市 | 仅为空的出发地自动补常驻城市，不覆盖用户手填城市 |
| M7 | 切换移动端预览 | 约束两列排列、CTA 独占一行，页面可纵向滚动到底 |
| M8 | 展开自由提问 | 原 Composer、深度推理、沙箱和快捷模板照常可用 |
| M9 | 停留观察 15 秒 | 标题流光缓慢且无明显红蓝断层，面板顶部光带不干扰输入和约束阅读 |

## 边界确认

- 本期不承诺截图/照片内容识别；图片视觉模型接通前不能把上传按钮包装成“已支持”。
- 本期不开放匿名真实生成；邀请码、成本和滥用风控保持现状。
- 公开链接是否可读受登录墙、站点风控和网络状态影响，任务必须诚实披露未成功读取的来源。
