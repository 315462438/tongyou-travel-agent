# Phase 46 — 前端交互体验优化验收用例

## 自动化用例

运行：

```bash
cd frontend
npm test
npm run lint
npm run build
```

### TC-46-01 输入框快捷键

- 普通 Enter 发送；
- Shift+Enter 仅换行；
- 中文输入法组合输入期间按 Enter 不发送；
- 输入会去除首尾空白并限制在 4000 字以内。

对应自动化：`frontend/tests/interaction-utils.test.mjs`。

## 手工交互用例

### TC-46-02 登录页

1. 桌面端打开登录页，Tab 可依次访问登录/注册、用户名、密码、显示密码和提交按钮；
2. 密码可显示/隐藏，Enter 可提交，提交期间字段禁用并显示忙碌状态；
3. 390×844 视口中，表单和主提交按钮无需滚动即可到达。

### TC-46-03 对话与侧栏

1. 手机展开侧栏后，点击遮罩或按 Escape 可关闭；
2. 会话条目可通过 Enter/空格打开，当前会话具有可识别状态；
3. 删除会话必须确认，成功或失败均出现 Toast；
4. 消息发送失败时输入内容保留，成功后才清空；
5. 输入框显示快捷键和字数，达到上限时明确标红。

### TC-46-04 异步反馈

- 加入/接受行程邀请、停止生成、创建行程、复制分享文案和记账均有成功或失败提示；
- Toast 可手动关闭，错误提示使用 `role=alert`；
- 分享关闭和链接重置必须二次确认。

### TC-46-05 协同行程移动端

1. 小于 900px 时显示“行程 / 地图 / 助手”三段切换；
2. 每次只展示当前板块，长页面不再由三栏纵向堆叠；
3. 从检查项定位具体地点时自动切回“行程”；
4. 删除地点二次确认，成功后出现反馈；
5. 桌面端仍保持三栏同时展示。

### TC-46-06 可访问性与动效

- 键盘焦点清晰，不只依赖颜色表达状态；
- 开启“减少动态效果”后，动画和过渡接近关闭；
- 手机底部 Toast 避让安全区，关键按钮点击区域可达。
