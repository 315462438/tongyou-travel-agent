## 后端（pytest）

| 用例 | 断言 |
| --- | --- |
| 兜底插图遇表格行命中 | 图片插到表格块之后；表格 4 行保持连续 |
| 占位符写在表格单元格里 | 占位符从行内剥掉，图片移到表格后；表格完整 |
| 流式模式 | 不做兜底；行尾 `[[img:` 残片剥净；表格完整 |
| 单括号 `[img:名称]` | 一样被替换成图片 |
| 全角冒号 `[[img：名称]]` | 一样被替换 |
| 单括号无匹配占位符 | 从正文剥净（不再漏给用户） |
| 灵感图兜底 | 图下带 `*图源：小红书笔记「…」*` 图注 |
| xhs 采集尝试上限 | 全部笔记不合格时 note_detail 恰被调 n+2 次；逐篇回调收到 n+2 次 |
| xhs 进度回调抛异常 | 采集不受影响 |
| 360 相关性过滤 | 「唧唧Down下载」「哔哩哔哩下载中心」被滤掉；含查询词元的保留；查询无有效词元放行 |
| 深度研究终稿择优 | 长报告后跟收尾寒暄 → 取报告；无明显更长的早期消息 → 取最后一条；空输入返回 "" |
| 预算口径对账 | 正文合计与逐项重算差 >20% → notes 追加差异说明；≤20% 不加 |

## 手工验收（部署后线上）

1. 新会话发一条完整攻略请求：正文所有四列表格完整渲染、无 `[img:`/`[[img:` 泄漏、
   无 `**` 裸星号、价格区间无删除线；灵感图下有「图源」图注。
2. 等待期「当前动作」在小红书阶段每 ~20 秒推进一条「正在读第 N 篇…」。
3. 深度推理跑一轮对比问题：终稿是完整报告（含对比表），不是收尾摘要。
4. 预算明细：若与正文合计差距大，面板注明口径差异。
