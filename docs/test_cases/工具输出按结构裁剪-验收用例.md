**关于「有效率」这个指标的订正**：计划里写的验收线是「窗口有效率 ≥70%」，实测时发现
这个指标**定义得不对**——我用「历史章节里某句话的位置」当正文锚点，而锚点之前那 1984 字
是**信息框**（面积/深度/岛屿/世界遗产编号/坐标）和导语，对旅行规划全是有用信息，
不该算作无效。所以改用可验证的断言：**具体的 chrome 特征串必须消失、具体的正文特征串
必须存在**（用例 1、2）。这比一个口径含糊的百分比更能钉住行为。

## 三、不变式

| # | 用例 | 断言 | 测试 |
| --- | --- | --- | --- |
| 14 | HTML 幂等 | `reduce_auto(reduce_html(x)) == reduce_html(x)`，三个样本 | `test_html_reduction_is_idempotent`（×3） |
| 15 | a11y 幂等 | `reduce_a11y(reduce_a11y(x)) == reduce_a11y(x)`，三份快照 | `test_a11y_reduction_is_idempotent`（×3） |
| 16 | 不新增字符 | 裁剪产物的每一段（忽略空白）都能在朴素提取里找到 | `test_reduced_text_invents_no_characters`（×2） |
| 17 | 认不得就别动 | 纯文本、JSON 原样通过，`kind == "plain"`、`dropped == 0` | `test_plain_text_and_json_pass_through_untouched` |
| 18 | 识别器 | `looks_like_html` / `looks_like_a11y` 正反例 | `test_detectors` |
| 19 | 畸形输入不抛异常 | `""`/`<`/`<html`/`<<<>>>`/`\x00\x01\x02`/`"<p>"*5000`/`&#;&#x;&amp` 共 7 种 | `test_malformed_input_never_raises`（参数化） |
| 20 | 空输入 | 三个入口都返回 `kind == "empty"` | `test_empty_input` |

用例 16 的表述值得单说：不变式是**「不新增字符」**（比较时忽略空白），不是逐字匹配——
块级边界把空格换成换行是结构标注，本来就该允许。这条用例真的抓到过一个 bug（内联标签
文本无分隔拼接），见坑记第 3 条。

（原名 `test_short_snapshot_untouched`）。该用例的**意图**是「短快照不被截断」，

所以改为断言「无截断标记 + 可读文字还在 + `uid=` 已剥离」。
