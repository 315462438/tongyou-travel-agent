# 验收用例 · 攻略后的「接下来」（2026-08-05，改造 ③）

## 背景

08-04 那批**拿到攻略的 8 个用户里只有 1 个（猫巷子）**自己摸到了正确路径：
攻略 → 生成手账海报 → 几小时后带着真实日期（8月15-18号）回来重新规划 → 再出海报。
他也是这批里唯一二次回访、且当时仍在线的用户。

原因不是功能缺失——海报/预算/协同行程三个入口都在，但它们混在
`📋 复制 / 🔗 调用链 / 🎨 海报 / 💰 预算 / 🗺️ 协同` 这排**大小相同的小按钮**里，
5000 字正文之后被整体忽略。

改法：把猫巷子那条路径提成显式的「接下来」卡片区。

## 自动化

```bash
cd frontend && npm test
```

| 用例 | 断言 |
| --- | --- |
| B1 存在「接下来」区块 | `next-steps` 渲染 |
| B2 三张卡 | 手账海报 / 日期定了排到每一天 / 叫上同行的人一起改 |
| B3 卡片形态 | `flex-direction: column` + grid 布局，不是又一排小按钮 |
| B4 已导入态 | 已有 `imported_trip_id` 时变成「打开协同行程」 |

## 人工走查

| 用例 | 步骤 | 期望 |
| --- | --- | --- |
| M1 攻略后 | 生成任意一份攻略 | 正文下方出现「接下来」三张卡，比小按钮显眼 |
| M2 海报 | 点「生成手账海报」 | 与原按钮行为一致，开始生成 |
| M3 日期细化 | 点「日期定了？排到每一天」 | 输入框预填日期模板，用户改成自己的日期即可发送 |
| M4 协同 | 点「叫上同行的人一起改」 | 导入并打开协同行程板 |
| M5 生成中禁用 | 本轮还在跑时 | 三张卡禁用（防止导入过期内容） |
| M6 移动端 | 手机模式 | 三张卡单列，不挤 |

## 边界

- 「日期定了」只是**预填模板**（含示例日期），用户需自行改成真实日期——
  产品不知道他的行程，编一个具体日期直接发送会造成错误结果。
- 复制/调用链仍留在原来的小按钮行，它们是工具性动作而非「下一步」。
