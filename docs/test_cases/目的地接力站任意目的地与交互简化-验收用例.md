## 自动化用例

### 前端

运行：

```bash
cd frontend
npm test
npm run lint
npm run build
```

覆盖：

1. 页面存在任意目的地输入框，示例包含黄山、京都、冰岛；
2. 表单 Enter 会阻止刷新并调用目的地切换；
3. 天堂寨等按钮仅作为快捷入口；
4. 发布器只显示“问一个问题 / 报个现场 / 分享路线”；
5. 三类动作分别映射到 planning / on_trip / returned；
6. 不再渲染旧 `postPhase` 阶段选择器；
7. 现场情报明确提示 72 小时有效；
8. 搜索框、三类动作和移动端布局存在对应响应式规则。

结果：`58 passed`；lint 通过，保留 2 条与本功能无关的历史 Fast Refresh 警告；生产构建通过。

## 手工验收

1. 输入“黄山”并按 Enter，标题切换为黄山且加载黄山动态；
2. 输入“京都”并点击“查看接力”，能进入京都空站或动态列表；
3. 点击天堂寨快捷项，可重新回到天堂寨；
4. 点击“发一条接力”，只需选择一种动作、确认目的地并输入正文；
5. “问一个问题”发布后出现在准备去；“报个现场”出现在正在玩并显示有效期；
6. “分享路线”出现在刚回来；
7. 在发布器中把目的地从当前站改成另一地点，发布后自动进入新目的地；
8. 手机端输入框、查看按钮、快捷目的地和发布按钮均在首屏可操作，没有横向溢出。
