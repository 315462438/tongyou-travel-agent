## 二、压缩的是呈现，不是信息（Phase 71 的四项一件不少）

| # | 断言 | 对应 Phase 71 的哪条 |
| --- | --- | --- |
| 6 | `thinkingRowLabel(mode, elapsedSec)` 出现在渲染里 | 已用时间 + 预期时长 |
| 7 | `className="think-row-trail"` | 足迹（收进展开区） |
| 8 | `staleSec >= 45` + 「正在深入思考中」+「可以关掉页面」 | 静默期安抚 |
| 9 | `waitReassurance(elapsedSec, mode)` | 超时后的分段文案 |
| 10 | 不含「秒没有新消息」 | 旧的「像卡死」文案没回潮 |

**这一组是本次最该防的回归。** Phase 71 是实测结论：流失的原因不是「久」，
是「不知道还要多久」+「静默空隙」。视觉压缩很容易顺手把它们一起删掉。

## 五、变异检验（已实跑，都能红）

- `{thinkingRowLabel(mode, elapsedSec)}` → `{mode}`：红 1 条（时间与预期一起没了）。
- 删 `.think-row-summary[data-follow-end] { text-overflow: clip; }`：红 1 条。

## 六、手工复验

1. 发一条规划请求 → 收起态**只占一行**，同一行能看到模式 / 已用时间 / 预期 / 当前动作。
2. 点整行 → 展开足迹；再点收起。键盘 Enter/空格同样可切换。
3. 等 45s 无新进度 → 出现「可以关掉页面」次行；超过预期时长后追加分段文案。
4. **停止仍然可用**——本次唯一移除的交互入口是行内那个停止按钮，
   composer 的发送键在 running 时仍是黑色停止方块（Phase 71）。
5. 终稿到达后「已深度思考」折叠行与运行时那一行**长得一样**；展开时摘要让位给正文，
   不再出现「摘要 = 正文第一行」的重复。
6. 移动端窄屏不横向溢出。
