## 行为分流

| # | 场景 | 断言 | 测试 |
| --- | --- | --- | --- |
| 1 | 首次导航抛 `TimeoutError` | navigate 只调 **1 次**；仍走 snapshot 并返回 ok + 正文（部分加载的页面被救回） | `test_timeout_skips_retry_and_salvages_via_snapshot` |
| 2 | 超时以普通异常 + 消息文本出现（MCP 侧常态） | 同上，只调 1 次 | `test_timeout_by_message_also_skips_retry` |
| 3 | 非超时错误（CDP 抖动）、第二次成功 | navigate 调 **2 次**，返回 ok——**原行为保留**，那才是当初加重试的合理场景 | `test_transient_error_still_retries_once` |
| 4 | 非超时错误连抛两次 | 异常照旧冒泡不吞（上层自愈/降级依赖它） | `test_transient_error_twice_still_propagates` |
| 5 | 首次成功 | navigate 只调 1 次 | `test_success_navigates_exactly_once` |

## 判别函数（参数化 8 例）

`_looks_like_timeout`：`TimeoutError()`（**str 为空**也要认出）、`asyncio.TimeoutError`、
timed out / Timeout / 大小写变体 → True；CDP lost / target closed / 空消息 → False。

**退化方向**：识别不出来一律当非超时 → 保留重试 = 今天的行为，不会更差。
