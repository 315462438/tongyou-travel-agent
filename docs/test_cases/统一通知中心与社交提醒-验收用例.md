# Phase 84 · 统一通知中心与社交提醒验收用例

日期：2026-08-11

## 自动化用例

| 编号 | 场景 | 预期 | 自动化位置 |
| --- | --- | --- | --- |
| N-01 | A 向 B 发好友申请 | 仅 B 收到未读好友申请；A 无通知 | `backend/tests/test_notification_api.py` |
| N-02 | B 接受 A 的申请 | B 的申请提醒移除；A 收到“已接受”提醒 | 同上 |
| N-03 | B 给 A 的接力反馈并切换类型 | A 始终只有一条同事件通知，内容与类型更新并回到未读 | 同上 |
| N-04 | B 再点一次同一反馈 | 反馈与对应通知一起撤销 | 同上 |
| N-05 | B 尝试读取 A 的通知 | 返回 404，不泄露通知是否存在 | 同上 |
| N-06 | 单条已读与全部已读 | 未读数持久更新，跨查询仍保持已读 | 同上 |
| N-07 | 顶栏铃铛 | 合并社交与公告未读，显示数字徽标并打开统一浮层 | `frontend/tests/visual-regressions.test.mjs` |
| N-08 | 点击通知 | 好友事件直达好友页，接力事件直达对应目的地 | 同上 |
| N-09 | 通知视觉 | 浮层、未读态、公告入口和移动端规则存在 | 同上 |

## 人工烟测

1. 用账号 A、B 分别登录两个浏览器；A 请求添加 B，B 的铃铛应出现 `1`；
2. B 打开通知，点击好友申请应进入好友页；接受后 A 收到“接受了你的好友申请”；
3. A 发一条接力，B 点“有用”，A 的铃铛增加；点通知应进入该目的地接力站；
4. B 把反馈切成“我也到过·属实”，A 不应新增第二条通知；B 再点一次应撤销通知；
5. 点击“全部已读”后刷新页面，未读数字不应恢复；
6. 在手机布局确认浮层可滚动、文字可读，外部点击或关闭按钮可退出。
