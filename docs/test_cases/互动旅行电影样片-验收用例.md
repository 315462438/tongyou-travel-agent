# 互动旅行电影样片 · 验收用例

对应开发计划：`docs/task_plans/互动旅行电影样片优化-2026-08-10.md`

## 自动化用例

执行：

```bash
cd frontend
npm test
npm run lint
npm run build
```

覆盖点：

1. 首页入口仍懒加载 `ImmersivePreview`，不增加首页主包首载；
2. 体验层保留 `dialog` 语义、接口加载、路线分支和转真实行程闭环；
3. 源码不再渲染常驻 `immersive-hud`；
4. 长按时间固定为 900ms，触控 Pointer Events 与空格键均能触发；
5. 视差 CSS 变量、电影取景框和项目内 WebP 氛围图均已接线；
6. “氛围演绎”与“真实地点参考”文案同时存在；
7. 移动端有独立取景框/长按布局，reduced-motion 关闭动画和视差变换。

## 人工交互用例

### 桌面端

1. 登录后从首页点击“先去天堂寨走两分钟”；
2. 首幕应显示高清春夏山谷主视觉，左上角明确标注“氛围演绎”；
3. 移动鼠标，取景框与画面只做轻微反向位移，不产生眩晕或露出边缘；
4. 短按推进按钮应自动归零，不切场；持续按住约 0.9 秒才进入下一幕；
5. 按住空格键获得等价推进效果，Escape 可随时退出；
6. 第二幕选择任一路线，后续标题和体力应随路线改变；
7. 点击“行程感受”才展开体力、模拟花费与非实时说明；
8. 结束后可重新体验，或生成包含所选路线的真实行程请求。

### 移动端

1. 取景框不超出屏幕，顶部品牌、进度和关闭按钮均可见；
2. 长按按钮宽度适合拇指操作，浏览器长按菜单不会弹出；
3. 路线选项单列显示，正文可滚动且不被安全区遮挡；
4. 状态说明按需展开，不常驻遮挡主画面。

### 降级

1. POI 图片失败时自动切换到项目内氛围图，体验仍可完成；
2. `prefers-reduced-motion` 开启时取消场景入场、呼吸、光斑和颗粒动画，并关闭视差；
3. 接口失败时显示重试和返回首页，不残留滚动锁。
