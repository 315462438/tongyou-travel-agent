## 人工走查（线上 https://17tongyou.com/travel/）

前置：发一条会走完整攻略流水线的消息（如「我想去成都玩3天，帮我排个行程」），
在**生成过程中**（正文正在一段段长出来时）操作。

| 用例 | 步骤 | 期望 |
| --- | --- | --- |
| M1 上翻可停住 | 生成中向上滚 2-3 屏，停手观察 15s（≥10 次轮询） | 视口**纹丝不动**，不被拉回底部 |
| M2 出现回到底部入口 | 同 M1 | 消息流底部浮出「↓ 回到最新内容」胶囊 |
| M3 点击回到最新 | 点该按钮 | 平滑滚到底，按钮消失，此后继续自动跟随新内容 |
| M4 手动滚回也恢复跟随 | 不点按钮，自己滚到最底 | 按钮消失，恢复自动跟随 |
| M5 贴底时正常跟随 | 生成中保持在底部不动 | 新内容持续可见，行为同修复前 |
| M6 发新消息重新贴底 | 上翻脱离后直接发下一条 | 自动回到底部并恢复跟随 |
| M7 切换会话 | 上翻脱离后点侧边栏另一个会话 | 新会话直接定位到最新一条 |
| M8 移动端 | 手机/移动端模式重跑 M1-M3，用手指拖动 | 同上；按钮不被底部输入框遮挡 |

## 边界

- **M1 是这次的核心用例**：修复前它必然失败（每 1.5s 被拽回一次）。
- 图片延迟加载会引起轻微布局位移，属浏览器 scroll anchoring 范畴，不在本次修复范围。
- `onWheel` 只覆盖滚轮；触屏靠 `onScroll` 复算即可（无平滑动画抢方向盘问题），故 M8 单列。
