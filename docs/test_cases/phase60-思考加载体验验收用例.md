# Phase 60 — 思考加载体验验收用例

## 自动化用例

运行：

```bash
cd frontend
npm test
npm run lint
./node_modules/.bin/tsc --noEmit -p tsconfig.app.json
npm run build
```

### TC-60-01 阶段推断

- 「理解需求」映射到第 1 阶段；
- 搜索、小红书、高德、携程和读取来源映射到「搜集资料」；
- 整理、汇总、路线规划映射到「整理方案」；
- 流式生成映射到「生成内容」；
- 自检、反思、重排和优化映射到「检查优化」；
- 同一句含多个阶段关键词时，优先展示更靠后的阶段。

对应自动化：`frontend/tests/interaction-utils.test.mjs`。

### TC-60-02 运行时长

- 负数归零；
- 一小时内显示 `MM:SS`；
- 超过一小时显示 `H:MM:SS`。

对应自动化：`frontend/tests/interaction-utils.test.mjs`。

### TC-60-03 视觉契约

- 页面包含统一思考工作台、阶段列表和停止按钮；
- CSS 包含思考核心与阶段动效；
- `prefers-reduced-motion` 明确关闭持续动画。

对应自动化：`frontend/tests/visual-regressions.test.mjs`。

## 手工交互用例

### TC-60-04 普通攻略

1. 发送「帮我规划成都 3 天路线」；
2. 用户消息下只出现一个思考工作台，不出现多条 spinner；
3. 阶段从理解需求推进到搜集资料、整理方案和生成内容；
4. 最新 progress 文案显示在「当前动作」区域；
5. 流式正文首段出现后工作台隐藏，正文继续平滑增长。

### TC-60-05 深度研究与停滞反馈

1. 开启深度推理并发送多城市比较问题；
2. 工作台标记为「深度推理」，计时器每秒更新；
3. 30 秒没有 progress 更新时出现「任务仍在运行」说明；
4. 点击工作台「停止」后沿用现有停止流程并结束轮询。

### TC-60-06 登录接管与来源确认

- 携程登录接管卡片、小红书/来源确认卡片保持可见和可点击；
- 等待用户操作时不额外叠加思考工作台；
- 用户完成操作、Agent 恢复执行后工作台重新出现。

### TC-60-07 手机与低动态模式

1. 390×844 视口下工作台无横向滚动，阶段改为紧凑纵向展示；
2. 停止按钮始终可触达；
3. 系统开启「减少动态效果」后，无核心旋转、呼吸、扫描和波形动画；
4. 阶段、当前动作和等待时间仍通过文字完整表达。
