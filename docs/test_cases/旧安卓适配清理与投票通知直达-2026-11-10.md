# 旧安卓适配清理与投票通知直达测试

## 自动化覆盖

| 用例 | 预期 | 实现 |
| --- | --- | --- |
| 第 2 天投票通知 | 进入对应行程、选中第 2 天、定位投票卡 | Web 浏览器 + 三端逻辑测试 |
| 投票现状与旧通知日期不同 | 以当前投票日期为准；整趟投票不强制旧日期 | 三端逻辑测试 + Web 浏览器 |
| 缺失 day、删除投票、非法/越界日期 | 已知投票可反查日期；其他情况安全打开有效日期 | 三端逻辑测试 + Web 浏览器 |
| 同一条已读通知重复打开 | 每次定位，正常标记已读 | Web 浏览器；Swift 请求身份测试 |
| 已打开另一个行程再进入 | 换到新行程并清掉旧详情状态 | Web 浏览器 |
| 进入后手动改日期、随后轮询 | 保留用户选择，不重复滚动 | Web 浏览器；原生一次消费状态 |
| 投票与群聊通知互相切换 | 投票显示投票，群聊正常展开抽屉 | Web 浏览器 |
| 通知协议和访问权限 | API 保留 trip_id / poll_id / day，读后仍保留；第三人不可访问 | 后端参数化 API 测试 |
| Android 列表定位 | 包括整趟投票、日期标题、错误提示等可选行时索引正确 | TripNotificationTest |
| 旧壳清理后网页分享 | 手机标准系统分享、多张完整 PNG；不支持分享时实际下载 PNG | share-browser |
| 手机行程样式 | 日期可点、地图标记/定位、无坐标/地图失败/横屏、无横向溢出 | trip-route-browser |
| 普通网页交互 | 主流程、账户弹层、AI 明暗对比、搜索偏好、游游、按压与减少动态 | 对应 browser 脚本 |
| 登录服务暂时不可用 | 保留 token，显示重连，恢复后进入主界面 | trip-notification-browser |
