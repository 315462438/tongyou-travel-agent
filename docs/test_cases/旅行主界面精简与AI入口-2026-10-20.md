# 旅行主界面精简与 AI 入口测试

## 自动化用例

| 用例 | 断言 | 实现 |
| --- | --- | --- |
| 导航精简 | 旅行/记账/我的三项，无同游圈主入口，AI 按钮可命中 | journey-browser.mjs / JourneyUITests.swift |
| AI 快捷任务 | 点击找美食回填，发送前没有 POST | 浏览器；iOS 检查输入内容 |
| 草稿恢复 | 收起后重开保留输入 | 两端 UI 测试 |
| 对话恢复 | 发送后有回复，收起重开保持会话；默认联网开 | 两端 UI 测试；联网字段由浏览器断言 |
| 历史 | 我的→历史→搜索/打开旧对话；可关闭历史 | 浏览器 / iOS |
| 行程 | 点击指定旅行册打开对应 ID；填写并创建空白行程 | 浏览器 |
| 账本权限与分享 | viewer 无记一笔；分享链接确认加入后打开目标只读账本 | 浏览器 |
| 异常和空状态 | trips 503 显示重试；重试无数据后显示明确下一步 | 浏览器 |
| 尺寸与主题 | 320/390/430/1280px、844px 横屏，无根节点横向溢出；浅深色截图 | 浏览器 |
| 降低动态 | reduced-motion 时关闭动画 | 浏览器 |
| iOS 原生 | 编译；iPhone 17 Pro 模拟器三项导航、回填、草稿、发送恢复、历史返回 | XCTest |

## 执行

前端已有单元回归：
```sh
cd frontend
npm test
npm run build
```

浏览器回归（独立终端启动 Vite）：
```sh
cd frontend
npm run dev -- --host 127.0.0.1 --port 4185
```
```sh
# 如果环境没有 Playwright，在临时目录安装，避免改动生产依赖。
npm install --prefix /tmp/tongyou-qa playwright
cd frontend
PLAYWRIGHT_MODULE=/tmp/tongyou-qa/node_modules/playwright/index.mjs npm run test:journey
```
`CHROME_PATH` 可指定 Chrome；非 macOS 默认使用 Playwright 浏览器，需先安装对应浏览器。
`JOURNEY_QA_URL` 默认 `http://127.0.0.1:4185/travel/`；`QA_CASE` 可单独运行一个尺寸；截图和 JSON 默认写入 `/tmp/tongyou-journey-qa`。

iOS（仓库根目录）：
```sh
python3 ios/scripts/generate-project.py
xcodebuild -project ios/Tongyou.xcodeproj -scheme Tongyou \
  -configuration Debug -destination 'platform=iOS Simulator,name=iPhone 17 Pro,OS=26.3' \
  -derivedDataPath /tmp/tongyou-journey-build \
  -only-testing:TongyouUITests/JourneyUITests CODE_SIGNING_ALLOWED=NO test
```
模拟器名称/系统可替换为本机已安装版本。浅色、深色分别执行（`xcrun simctl ui <UDID> appearance light/dark`）。测试通过显式 `--journey-ui-test` 使用 DEBUG URLProtocol，所有请求均为内存夹具；不访问生产 API、不写测试 token 到 Keychain。Release 中不包含测试传输代码。

## 验证边界

浏览器的 Android 用例验证 WebView 页面的 UA 分支与布局，不等于 Android 真机 GPU、键盘和系统安装包测试。iOS 验证为模拟器。UI 夹具只证明交互和请求流程，不证明真实 AI 推荐质量、真实汇率或生产权限安全；本次没有修改后端权限协议。

本地验收阶段未发布；后续用户追加发布要求，发布记录见下文。未推送 GitHub。相册整理/照片故事和新的结构化 AI 地点卡接口不在本轮实现范围。
