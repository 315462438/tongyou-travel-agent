# Phase 54 — 真实使用回归验收用例

## 自动化用例

1. `resolve_route`：深度开关关闭时，`guide` 仍进入联网攻略；`research` 才降级并提示；
   完整单方案规划即使分类模型误判也强制进入 `guide`。
2. 攻略导入：保留 stop 交通方式、逐日过夜计划、酒店候选和预算分类。
3. 住宿判断：火车过夜/返程日 `overnight=false`；当天往返景点使用实际过夜城市。
4. 路线检查：步行腿与驾车腿分别累计，混合交通不误报整段步行。
5. 健康策略：系统提示禁止主动推荐具体药物/保健品与固定禁浴天数。
6. 记忆覆盖：完整新规划不注入旧“当前行程”和旧兴趣主题。
7. CSS：邀请输入框和按钮使用 `minmax(0,1fr) auto`，弹层不超出视口；导入酒店与预算标签存在。

## 手工验收

使用普通模式提交“武汉到拉萨 15 天、两人、火车进飞机返、酒店 300–500、含预算”：

- 直接进入联网攻略，不显示“已用快速模式作答”；
- 导入后自动选中首个有地点日期；
- 住宿面板的火车过夜/返程日显示无需住宿，当天往返羊湖仍显示拉萨；
- 攻略候选酒店显示在住宿面板，可一键加入当前日；
- 费用面板显示计划分类，“景点票价已录入”与计划门票无歧义；
- 检查中心的步行里程只包含步行腿，详情与地图交通方式一致；
- 1280px 宽度打开行程操作，邀请按钮完整可见。
