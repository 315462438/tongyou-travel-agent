# Phase 65：移动端 UI 重构验收用例

## 自动化用例

### 视图判定

1. 390px 视口默认移动端，即使本地曾保存网页端偏好。
2. 1440px 首次访问默认网页端。
3. 桌面保存移动端偏好后可继续预览移动布局。
4. 粗指针横屏设备仍默认移动端。

### 结构与样式回归

1. 根节点包含 `view-${layoutMode}`，右上角存在“网页端 / 移动端”双模式控件。
2. 移动端存在“新对话 / 行程 / 历史 / 记忆”四项底部导航。
3. 移动历史侧栏使用 `translateX` 收起，打开时有遮罩。
4. 底部导航使用 `safe-area-inset-bottom`，按钮触区至少 48px。
5. 首页快捷入口为两列；360px 以下退化为单列。
6. 攻略目录为单列，表格和消息操作在组件内部横向滚动。
7. 移动输入框采用三列主输入 + 第二行模式开关，不与发送按钮相互挤压。
8. 桌面选择移动端预览后，协同行程也使用手机宽度和三分区单面板切换。
9. 行程页点击“新对话”会同时关闭 `showTrips`、清除 `tripsBoard` 并进入空白对话；
   历史和记忆入口同样先关闭前一个全屏页面。

## 手工验收

1. 360 / 390 / 430px 视口首次进入移动版，顶部和底部均不遮挡内容。
2. 点击右上角“网页端 / 移动端”，当前态清楚，刷新后桌面预览偏好保留。
3. 打开历史抽屉、选择会话、点遮罩或按 Escape，抽屉均可正常关闭。
4. 分别打开协同行程、记忆和长攻略；返回主对话后底部导航仍可用。
   特别验证从协同行程直接点击左下角“新对话”，应立即回到对话首页。
5. 发送多行消息、打开深度推理/沙箱开关，软键盘场景下发送按钮保持可见。
6. 阅读含图片和宽表格的五日攻略，整页不发生横向滚动，表格本身可滑。
7. 检查 iPhone 底部 Home Indicator 区域，输入框和底部导航不被遮挡。
