## 自动化用例

| 编号 | 场景 | 断言 |
| --- | --- | --- |
| A1 | 目的地清洗 | 多城表达取首项，最长 24 字 |
| A2 | 图片安全 | 只接受高德/Autonavi HTTP(S) 图片域名 |
| A3 | 天堂寨场景包 | 固定返回 6 幕、2 个分支选项和路线变体 |
| A4 | 分支差异 | 主峰线体力消耗显著高于峡谷慢行线 |
| A5 | 图片全失败 | 接口仍返回完整 6 幕，`has_images=false` |
| A6 | TTL 缓存 | 同一目的地二次请求不重复构建场景包 |
| A7 | 通用目的地契约 | 非天堂寨仍返回相同 6 幕/分支数据结构 |
| A8 | 首页入口 | 显示“先去天堂寨走两分钟”，点击打开懒加载全屏层 |
| A9 | 对话框语义 | 全屏层为 `role=dialog` + `aria-modal=true`，Escape 可退出 |
| A10 | 真实图代理 | 所有场景图通过 `/api/img?u=` 加载 |
| A11 | 游戏化状态 | HUD 展示时间、环境、体力、体验花费和六段进度 |
| A12 | 分支交互 | 路线选择应用 `scene.variants[route]`，影响旁白与体力 |
| A13 | 行程转化 | 结算 CTA 生成包含路线、地点、现实核实要求的 prompt |
| A14 | 移动端 | HUD 四格紧凑布局，选项单列，结算按钮纵向排列 |
| A15 | 减少动态效果 | 推镜、雾漂移、场景/HUD 入场和悬浮位移全部关闭 |
