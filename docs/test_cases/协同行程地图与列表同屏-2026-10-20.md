# 协同行程地图与列表同屏测试

## 自动化用例
| 用例 | 验收 | 自动化入口 |
| --- | --- | --- |
| 手机同屏 | 320/390/430 宽首屏可见地图和第一项地点，无地图/行程互斥 tab | `frontend/tests/trip-route-browser.mjs` |
| 桌面同屏 | 日期、当天地点与地图并排，地图和地点可同时操作 | 同上，1280 浅/深色 |
| 双向联动 | 点地点移动地图；点标记选中并滚动对应行；全览清除选中 | 同上，隔离 SDK stub 验证调用 |
| 编号与切日 | 中间未定位地点不导致标记重编号（1、3）；切日更新；空日仍可添加 | 浏览器 + iOS UI tests |
| 地图故障 | SDK 与静态图失败仍显示提示，地点与编辑可用 | 浏览器 map-failure |
| 主题与尺寸 | 浅/深主题、横屏、减少动态、无水平溢出 | 浏览器及 iOS 深色测试 |
| 编辑和协作 | 编辑表单、成员入口、重新定位、系统返回与键盘正常 | 浏览器 + Android 原生测试 |
| iOS 同屏 | 地图在列表上方、首项可点击、日期切换、空日添加、详情隐藏主导航 | `ios/UITests/JourneyUITests.swift` |
| Android 覆盖安装 | 同签名、版本递增、旧版可收到新版本提示，下载哈希一致 | 打包/发布验证 + 模拟器 |

## 运行
```sh
cd frontend
npm test
npm run build
PLAYWRIGHT_MODULE=/tmp/tongyou-qa/node_modules/playwright/index.mjs npm run test:trip-route
PLAYWRIGHT_MODULE=/tmp/tongyou-qa/node_modules/playwright/index.mjs npm run test:journey
```
浏览器默认连接本地 Vite `http://127.0.0.1:4185/travel/`，API 全部使用内存夹具，无生产数据写入。`TRIP_QA_URL` 可替换为部署地址；`QA_CASE` 可只运行单个尺寸。交互地图的外部 SDK 被测试替身拦截，验证的是点位/编号/焦点协议，不宣称验证真实地图瓦片质量。iOS 使用 `--journey-ui-test` 的 DEBUG 内存请求。

原生 iOS / Android 的执行命令同《旅行主界面精简与AI入口-2026-10-20》。所有结果在完成后补记。
