# 高德前端凭据改环境变量（2026-08-25）— 验收用例

自动化测试：`frontend/tests/no-inline-keys.test.mjs`（6 条，全离线）

## 背景

开源前审计发现 `frontend/src/components/TripMap.tsx` 硬编码了两个值：

| 控制台 Key | 类型 | 值的性质 |
| --- | --- | --- |
| `js_map` 的 Key | Web端(JS API) | **本质公开**——必须下发到浏览器，藏不住 |
| `js_map` 的安全密钥 | Web端专属配对密钥 | **真密钥**，绝不能进仓库或生产构建 |

后端那对（`Putan-Lite-web` / Web服务 + `AMAP_SECRET` 数字签名）一直在 `.env` 里，不受影响。

⚠️ 安全密钥虽只在 `import.meta.env.DEV` 分支（生产构建摇树剔除、线上 JS 实测不含），
但**源码里那份一开源就公开**——摇树保护的是访客看不到，保护不了仓库读者。

## 用例

| # | 用例 | 期望 | 自动化 |
| --- | --- | --- | --- |
| 1 | 源码无 32 位 hex 字面量 | 全 `src/` 扫描为空 | `前端源码不含 32 位 hex 字面量…` |
| 2 | 已泄露的两个值不得回流 | 精确串匹配为空 | `曾经泄露过的两个高德值不得回到源码` |
| 3 | 凭据来自构建期变量 | 两个 `import.meta.env.VITE_*` 都在 | `TripMap 的凭据全部来自构建期环境变量` |
| 4 | 安全密钥只在 DEV 分支 | 读取位置落在 `DEV` 块内，生产走 `_AMapService` | `安全密钥只在 dev 分支使用…` |
| 5 | 缺 key 不静默白屏 | 显式判空 + `console.error` 点名变量 + `onFail` | `缺 key 时不静默白屏…` |
| 6 | `.env.example` 无真值 | 两个变量留空，全文无 32 位 hex | `.env.example 存在且不含真值` |

> 用例 1 的判据**宽于**用例 2：只钉已知泄露值的话，换了新 key 再硬编码一次照样漏过去
> ——护栏只防上一次的错等于没防。

## 变异检验（2026-08-25 实跑）

护栏必须验证它真的会红，否则等于没有：

| 变异 | 结果 |
| --- | --- |
| key 硬编码回源码 | 6 条中 **3 条红** |
| 安全密钥挪出 DEV 分支（生产泄露） | **1 条红** |
| 去掉缺 key 的判空 | **1 条红** |
| 全部恢复 | **6 条全绿** |

## 构建验证（人工）

```bash
cd frontend && npm run build
grep -r '<安全密钥>' dist/   # 必须无输出
```

2026-08-25 实测：产物**不含**安全密钥；JS key 已注入 `dist/assets/Trips-*.js`（预期内，
不注入地图就用不了）；**不给环境变量重建时产物里连 key 也没有**——fork 的人默认用自己的。

## 遗留动作（代码之外，需在高德控制台操作）

1. **重置 `js_map` 的安全密钥**——旧值已进 git 历史，删文件删不掉历史。
2. 新值同步到两处：本地 `frontend/.env.local`、服务器
   `/etc/nginx/sites-enabled/default` 的 `jscode=` 参数。
3. 给 `js_map` 配**域名白名单**（限 `17tongyou.com`）——key 本质公开，白名单才是真防护。
