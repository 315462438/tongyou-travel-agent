# 部署重启杀死后台任务导致会话永久卡死

> 记录：2026-07-06（用户报告「卡住了」）

## 现象

用户发起请求后界面一直停在「正在综合多个来源，生成攻略…」转圈，永远不结束，
输入框因 running=true 被锁死，这个会话再也无法使用。

## 原因

攻略生成跑在 FastAPI `BackgroundTasks` 里（同进程）。`deploy.sh` 的
`systemctl restart travel-backend` 会直接杀掉进程——正在跑的后台任务无声死亡。
而 running 的判定是「最后一条消息是 user/progress」，任务死了没人再写消息，
于是会话永久显示运行中。任何进程崩溃/OOM 同理。

**部署时机与用户请求撞车是必然会发生的事，必须有自愈机制。**

## 解决办法（两层兜底）

1. **启动修复**（`app/db/maintenance.py`）：服务启动时不可能有真正在跑的任务，
   把所有悬挂会话（最后一条是 user/progress）补一条「被重启中断，请重发」的
   assistant 消息。幂等。
2. **running 过期判定**（`chat_api._is_running`）：最后一条 user/progress 超过
   `turn_stale_min`（默认 30 分钟）视为已中断——覆盖进程没重启但任务假死的情况。

单测：`tests/test_stuck_conversation.py`。

## 经验

- 同进程 BackgroundTasks 天生不抗重启；要么接受并做好自愈（本项目做法），
  要么上独立任务队列（个人工具没必要）。
- 「运行中」这类状态永远要配过期时间，不能只靠最后写入方来解除。
