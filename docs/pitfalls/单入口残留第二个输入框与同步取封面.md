# 单入口残留第二个输入框与同步取封面

日期：2026-08-07

## 现象

首页名义上已经合并为单入口，但为了保留普通问答又在下方放了可展开 Composer。用户展开后同时
看到两个输入框，不知道该在哪里问；首屏虽然有光效，却没有旅行内容，视觉吸引力仍然不足。

另一个风险是直接在 `/api/onboarding` 中同步请求多张第三方封面：高德一旦限流或抖动，会让主
入口的常驻城市和热门榜一起变慢。

## 原因

- “功能没有删除”被错误等同于“旧控件必须继续存在”，导致同一能力出现两个交互入口；
- 纯目的地预演与普通旅行问题没有在唯一输入内区分；
- 图片只是增强内容，却被放进了首屏关键数据的同步链路。

## 解决办法

- 唯一 textarea 同时接受短地名、自然语言问题和分享链接：仅短地名套预演模板，普通问题原样交
  给后端 `direct/guide/research` 路由；
- 删除空状态第二 Composer，热门卡点击只回填唯一 textarea；
- 排名接口继续快速返回字符串，封面拆到独立 `/api/onboarding/covers` 异步请求；
- 封面成功和空结果都做 TTL 缓存，单城异常独立降级，前端始终有渐变占位。
