# 必应间歇性限流导致整轮失败 + 备用搜索引擎选型

> 记录：2026-07-06（用户报告：开封攻略两次都返回「没能抓到足够资料」）

## 现象

用户连续两轮请求，两个必应查询**一个结果都没返回**（进度里没有任何
「已读取/跳过」），来源为空，直接走失败兜底「要不要换个目的地」。
几分钟后在服务器上手工复现却完全正常（6 条结果）。

## 原因

必应对服务器 IP 的**间歇性限流**（已知坑，代码注释有记录：同 IP 连续查询
只有第一个可靠）。当天大量冒烟测试搜索加剧了触发。限流窗口内 search_web
的两次内部重试都拿不到结果，且当时**没有备用引擎**，一轮就放弃。

## 解决办法：360 搜索兜底

必应两次尝试均空 → 自动切 `https://www.so.com/s?q=`（`h3 a` 提取）。

备用引擎选型实测（同一台腾讯云服务器）：

| 引擎 | 结果 |
| --- | --- |
| 百度 | ❌ 机房 IP 直接弹「百度安全验证」滑块 |
| 搜狗 | ❌ 返回空结果（疑似风控） |
| 360 搜索 | ✅ 正常返回结果 |
| DuckDuckGo 等境外 | ❌ 服务器在境内，不可达 |

360 注意事项：
- 结果链接是 `www.so.com/link?m=...` 跳转链，open_page 跟随重定向即可，**不能**
  按「搜索引擎自身域名」一刀切过滤；
- 需过滤 360 自家内容服务：wenku/wenda/ai/xinwen 等 `*.so.com`（`/link` 路径除外）。
  见 `BrowserTool._is_360_self_service`。

## 经验

- 单一搜索引擎 = 单点故障；限流是间歇的，重试**当时**没用，换引擎才有用。
- 备用引擎必须在目标部署环境实测：百度/搜狗对机房 IP 的风控和家宽完全不同。
