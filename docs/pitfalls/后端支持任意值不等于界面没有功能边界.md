# 后端支持任意值不等于界面没有功能边界

日期：2026-08-10

## 现象

接力站的后端从第一版开始就接受任意 `destination`，但前端只给出天堂寨、杭州等几个固定按钮，
也没有自由输入框。用户因此合理地认为产品“只能接力天堂寨”。

同时，页面把旅行阶段和内容类型做成两套选择，虽然数据模型更精确，却要求用户理解内部分类。

## 原因

- 产品能力由用户看见的入口决定，不由接口参数决定；
- 固定快捷标签放在主位置时，会被理解成完整支持范围；
- 将数据库字段一一映射为表单控件，把系统建模成本转嫁给了用户。

## 解决办法

- 任意值能力必须提供明显的输入或搜索入口，快捷标签只作为次级建议；
- 以用户动作组织发布器：提问题、报现场、分享路线；
- 在前端内部完成类型到阶段的确定性映射，避免两个相关字段重复询问；
- 首屏只保留一个主任务链，统计与解释不重复出现；
- 自动化测试同时断言自由输入、Enter 提交和三类动作映射，防止后续退回固定标签。

## 结论

“接口能做”不代表“用户知道能做”。面向用户的入口必须真实表达系统边界，内部数据结构不应直接
决定表单复杂度。
