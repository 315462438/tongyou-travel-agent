# 按明度批量换色的三个盲区（2026-08-24）

把 `index.css` 里 779 种硬编码颜色迁到「行记」token 时，规则是
**保 CIE L\*、只换色相**（闸门 ΔL\* ≤ 6）。这条规则本身是对的——对比度靠明度，
明度不动就不会把字弄瞎。但它有三个盲区，全是**真实数据跑出来才暴露的**。

## 一、小尺寸状态指示器：要彩度，不要明度持平

`.online-dot.on` 原本 `#34c759`（L\*72），按明度映到 `--x-pine-74`（`#A1BDAB`）。
明度分毫不差，但**彩度被"越浅越降彩度"的规则削掉了**——8px 的圆点会被看成灰色，
"在线"这个信息直接消失。

徽标同理：`.bell-count` 原 `#ef4b56`（L\*57）→ `--x-cinnabar-58`（`#D46E5E`），
白字压上去只有 **2.9:1**（原本 3.5:1，本来就不高）。

**规则**：小尺寸、承载状态语义的元素（圆点、数字徽标、未读点）一律回**满彩度锚色**，
不参与明度映射。改用 `--x-pine` / `--x-cinnabar` 之后，白字对比度到 5.9:1，
比改造前还好。

## 二、多停靠点装饰渐变：会塌成一坨同色

每个停靠点独立按明度映射，于是

```css
/* 前：六色 sheen */
linear-gradient(102deg, #244fc1 0%, #4e63d3 19%, #785cca 39%, #b464a0 60%, #705dcc 80%, #3158c8 100%)
/* 后：四段同色 + 一个漏网的蓝 */
linear-gradient(102deg, #244fc1 0%, var(--x-pine-44) 19%, var(--x-pine-44) 39%, var(--x-n50) 60%, var(--x-pine-44) 80%, var(--x-pine-44) 100%)
```

因为原来那六个色**明度相近、只有色相在变**——而映射恰恰只看明度。

全仓 123 个渐变里只有 3 个塌了（其余都是两停靠点，无碍），**手工重写这 3 个**即可。
检测方法：`停靠点 ≥3 且 token 去重后数量变少`。

## 三、表意色：天空不是品牌蓝

`.auth-sky` 的注释白纸黑字写着「高空蓝天」：

```css
linear-gradient(178deg, #2472c9 0%, #3f92dd 30%, #74b6ec 58%, #b7dcf6 82%, #e6f2fb 100%)
```

迁移器认得出它是"蓝"，就按角色刷成了松绿——**明度全对，天是绿的**。

**规则**：描绘实物的颜色（天空、海水、夜色、植被、皮肤）不进角色映射。
它们和「品牌蓝」在色值上无法区分，只能靠**选择器/注释**识别，所以必须显式进
PROTECT 名单。

## 一般化

> **批量换色的危险不是"改错颜色"，是"改得悄无声息"。**

三个盲区的共同点：**编译过、测试过、构建产物正常**，只有把真实页面渲染出来量一遍
才看得见。所以这次的验证不是靠肉眼看截图，是在渲染后的页面上用 `getComputedStyle`
逐元素算对比度——比看图可靠，也能进 CI。

⚠️ 那个对比度脚本第一版给出**11 处失败全是假阳性**：它只读 `backgroundColor`，
而登录页的底是 `background-image` 渐变，于是一路穿透到 `body` 去比。
修正版遇到 gradient 底一律跳过（宁可少测，不可乱报）。
