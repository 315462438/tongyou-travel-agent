# 防泄漏的 gitignore 规则，会顺手吞掉「讲密钥」的文件

## 现象

2026-08-25 把高德凭据改成环境变量后，新增了一条护栏测试和一份验收用例：

```
frontend/tests/no-hardcoded-secrets.test.mjs
docs/test_cases/高德前端凭据改环境变量-验收用例.md
```

两个文件都写好了、测试也跑通了（6 条全绿，还做了变异检验），但 `git status`
**从头到尾没有它们**。不是没写成功，是 git 根本不显示。

## 原因

`.gitignore` 里有一组防凭据外泄的规则：

```
# 凭据交接类文档一律不进仓库（真实凭据请放在仓库之外）
*凭据*
*credential*
*secret*
*.secrets
```

规则本身是对的，但它按**文件名**匹配，分不清「**含有**密钥的文件」和「**讲**密钥的文件」：

- `no-hardcoded-**secret**s.test.mjs` —— 一条禁止硬编码密钥的测试
- `高德前端**凭据**改环境变量-验收用例.md` —— 一份说明怎么不放密钥的文档

**越是围绕密钥治理做的东西，名字里越可能带这些词，也就越容易被这组规则吞掉。**

## 为什么危险

普通文件被误忽略，最多是「怎么没提交上」，早晚会发现。但这次被吞的是**护栏测试**：

- 本地跑 `npm test` 一切正常（文件在磁盘上）
- 提交、推送、CI 全都不会报错
- 别人 clone 下来 —— **那条测试根本不存在**

于是「禁止把 key 写回源码」这条防线，在除了作者本机之外的**所有地方都不生效**，
而且没有任何征兆。对准备开源的仓库来说，这正好是最不该失效的那条。

## 解决办法

改名避开，而不是给 `.gitignore` 加否定规则：

```
frontend/tests/no-inline-keys.test.mjs
docs/test_cases/高德前端密钥改环境变量-验收用例.md
```

（`密钥` 不在规则里，`key`/`inline` 也不在。）

不加 `!` 否定规则的理由：那组规则的价值就在于**宁可错杀**——真有人把
`生产环境凭据.md` 拖进仓库时，它是最后一道拦截。为了两个文件在上面凿洞，
等于把误杀率换成漏杀率，方向反了。**让被误伤的文件改名，比让防线打折扣便宜得多。**

## 后续约束

1. 新增文件后，**确认 `git status` 里真的看得见它**——尤其是文件名里带
   `secret` / `credential` / `凭据` / `key` / `token` 这类词的时候。
2. `git status --porcelain` 对非 ASCII 文件名默认转义成八进制
   （`"docs/test_cases/\351\253\230..."`），**中文文件名用 grep 过滤会漏**。
   要么 `git status` 不带 `--porcelain`，要么 `git -c core.quotepath=false status --porcelain`。
   本次就因为这个，一度以为文档也被忽略了、实际它已经正常显示。
3. 一般化：**凡是「按名字模式排除」的机制，都要问一句「有没有一类正当文件恰好长这个样子」。**
   同类还有 `*.log`（会吞掉 `logging_config.log.example`）、`*test*` 的构建排除等。
