# 深度研究终稿择优：不能在全量 messages 里取最长（2026-07-30 当天翻车）

## 现象

修复「终稿取到收尾寒暄」（走查 P0-1）时，把 `deep_research._extract_answer` 改成
「所有 AI 文本消息里取最长」。上线后第一轮验证就翻车：问「长沙 vs 南昌怎么选」，
流式期间报告正常，终稿却变成**上一轮的武汉美食攻略**。

## 原因

deep research 的输入 `messages` 带着注入的近几轮对话历史（Phase 56），LangGraph 的
result state 会把这些历史原样带回来。历史里的旧攻略（4800+ 字）比本轮报告更长，
「全局取最长」就把旧回复当成了本轮终稿。

## 解决

择优范围限定在**最后一条 human 消息之后**的 AI 消息（即本轮真正生成的输出）：
先定位末条 `type=="human"` 的下标，只扫其后的消息，再做「最后一条 vs 明显更长者」
的择优。回归测试 `test_extract_answer_ignores_history_before_last_human`。

## 教训

凡是对 agent 的 result.messages 做全局扫描/聚合（找答案、找工具调用、统计），都要先
问一句：**这个列表里混着输入历史吗？** LangGraph state 的 messages 是「历史+本轮」
的并集，不是「本轮产出」。同类既有代码 `_extract_skills_used` 扫 read_file 调用也有
此暴露面（历史里的工具调用会被重复统计），目前影响仅为技能徽标显示，暂不改。
