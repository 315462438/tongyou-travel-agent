# 汇率行情可提前一天发布，不能全当未来异常

## 现象

iOS 账本改为 SGD 汇总 CNY 账单后显示「未获得 CNY 汇率」。生产服务器与本地请求官方接口均 HTTP 200：

```json
[{"date":"2026-10-25","base":"SGD","quote":"CNY","rate":5.219}]
```

实测时生产 UTC 日期是 2026-10-24。原 `convert_totals` 返回 `total_minor=null`、`missing=["CNY"]`，却没有网络错误。

## 原因

原新数据检查要求 `0 <= (today - rate_date).days <= 7`，将上游合法的次日观察值全部过滤；而缓存只检查超过 7 天，规则又不一致。[Frankfurter 官方 2.4.0 变更记录](https://github.com/lineofflight/frankfurter/blob/main/CHANGELOG.md#240---2026-09-09)说明，v2 最新汇率会包含提前一天发布的观察值。

原循环对整批记录统一捕获错误；单条非法数值、日期或缺字段也会导致整批有效记录丢失。

## 修复与边界

- 新请求与缓存共用日期校验，接受当日前 7 天至后 1 天，保留真实行情日期。
- 后 2 天及更远日期、超过 7 天行情仍不可计入完整总额；不修改服务器时钟、不拼造当前日期、不引入固定汇率。
- 逐条忽略非法记录，其他有效币种继续返回；任一需要的币种缺失时仍不显示完整总额。
- Decimal 取倒数及整数分四舍五入、来源和查询时间、有效缓存降级沿用原行为。

回归入口为 `backend/tests/test_ledger_fx.py` 及 `test_personal_ledger.py`。旧实现新增回归 9 项失败，修复后账本相关 69 项测试通过。后端修复即可覆盖三端，手机不需要重新安装。
