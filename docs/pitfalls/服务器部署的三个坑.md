# 踩坑：服务器部署的三个坑

> 日期：2026-07-03　|　阶段：Phase 1 线上部署

## 坑 1：非 80 端口外网被重置（同 PostgreSQL 那个坑）

- 后端起在 8080，`nc -z` 能握手，但外网 `curl` HTTP 载荷被重置（HTTP 000）
- 8000 也一样；**只有 80 端口外网 HTTP 200**（服务器已有 nginx 欢迎页）
- 根因：云安全组/中间网络只放行 80，其它端口 TCP 能连但应用层流量被掐

**解决**：用服务器已有的 nginx 反代——在 `/etc/nginx/sites-enabled/default` 的
default_server 块内加 `location /travel/ { proxy_pass http://127.0.0.1:8080/; }`
（尾斜杠会剥掉 `/travel` 前缀）。前端用子路径部署：`vite base:'/travel/'` +
API 路径 `/travel/api`。线上地址 http://<服务器IP>/travel/

## 坑 2：nginx 备份文件放在 sites-enabled 里会被加载

- `cp default default.bak` 到 **同目录**，nginx 把 `default.bak` 也当配置加载
- 报错 `duplicate default server for 0.0.0.0:80`

**解决**：备份要挪出 sites-enabled（`mv default.bak /root/`）。
另外用 `rindex("}")` 定位 server 块结尾会匹配到文件末尾注释里的 `}`，
应改为找第一个「只含 `}` 的行」。

## 坑 3：snap chromium 在 systemd 下跑不起来

- Ubuntu 24.04 的 chromium 是 snap 包，systemd 直接 ExecStart 报
  `Content snap GPU wrapper not found` + exit 3，无限重启
- snap 需要用户会话的 dbus/XDG_RUNTIME_DIR，systemd system 服务里没有

**解决**：
1. 装官方 deb 版 Chrome（`google-chrome-stable`），对 puppeteer/headless 友好
2. **不再单独常驻 Chrome 服务**，改为让 chrome-devtools-mcp 自己拉起 headless
   浏览器：`.env` 设 `CHROME_EXECUTABLE=/usr/bin/google-chrome`，mcp_client 检测到
   后用 `--headless=true --isolated=true --executablePath` 启动，省掉一个 systemd 单元

### 本地 vs 服务器的浏览器模式

| 环境 | 模式 | 配置 |
|---|---|---|
| 本地开发 | 连现成调试 Chrome（共享登录态） | `CHROME_DEBUG_URL`，跑 start_chrome.sh |
| 服务器 | mcp 自启动 headless | `CHROME_EXECUTABLE=/usr/bin/google-chrome` |
