# 部署脚本固定等待导致健康检查假失败

## 现象

`backend/deploy/deploy.sh` 已完成 rsync、依赖安装和 systemd 重启，但脚本最后以 curl
状态码 7 退出，看起来像部署失败。随后检查发现 `travel-backend.service` 实际已经正常运行，
健康接口也返回 `{"status":"ok"}`。

## 原因

旧脚本在重启服务后固定 `sleep 3` 秒，只检查一次 `localhost:8080/api/health`。本次 uvicorn
从 systemd 启动到 FastAPI application startup complete 约用了 4 秒，单次检查刚好落在端口
开始监听之前，因此产生假失败。数据库迁移或 checkpoint 初始化稍慢时更容易复现。

## 解决办法

- 健康检查改为每 2 秒一次、最多 15 次，总等待上限 30 秒；
- 使用 `curl -fsS`，只有 HTTP 成功才视为健康；
- 超时后自动输出最近 50 行服务日志再退出；
- 部署完成提示改为真实公网入口 `http://42.194.202.233/travel/`，不再提示外网不可达的 8080。

这样既允许正常的启动耗时，也不会在服务真正失败时无限等待或静默通过。
