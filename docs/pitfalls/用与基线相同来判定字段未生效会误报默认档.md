# 用「与基线相同」判定字段未生效，会把默认档误报成「被忽略」

## 现象

探测 DeepSeek 的 `reasoning_effort` 是否真的生效时（Phase 108），脚本的判据是：

> 拿「不带字段」的基线和「带字段」的结果比 `reasoning_tokens`，
> **相同就说明字段被服务端静默忽略了**。

跑出来的结论里有两行是这样的：

```
deepseek-v4-pro / high:              ⚠️ 思考 token 与基线相同（3000）——很可能被静默忽略
deepseek-v4-flash-vision-exp / high: ⚠️ 思考 token 与基线相同（2999）——很可能被静默忽略
```

但同一批数据里 `off` 和 `low` 都明确生效（3000 → 0 / 3000 → 1455）。
同一个字段在同一个模型上，不可能只有 `high` 那一档被忽略。

## 原因

**`high` 就是该模型的默认档位。** 不带字段 = 用默认 = `high`，所以两者结果本来就该相同。

判据把「这一档恰好等于默认值」和「字段被忽略」这两件完全不同的事，映射到了同一个观测结果上
——**观测量不足以区分假设**。

顺带一提，`deepseek-v4-flash` 那行给出的是 `2942 → 2999（+57）`，被判成「✓ 生效」，
其实同样是默认档，差的 57 只是采样噪声。**噪声让错误判据看起来对了**，这比直接报错更危险。

## 解决办法

- 判定「字段是否被接受」要用**能区分假设的那一档**：挑一个**明确不同于默认**的档位
  （这里是 `off` 或 `low`），它变了就说明字段被认了；
- 与基线相同时，正确的结论是「**该档位与默认一致，或字段被忽略——本次数据无法区分**」，
  而不是二选一里挑一个报出来；
- 更根本的：**不要把「差值为 0」当成一个有语义的信号**。它既可能是「没生效」，
  也可能是「生效了但目标值恰好相同」。要判生效，就得让期望值与基线**必然不同**。

## 后续约束

凡是「探测某个开关是否被下游接受」的脚本，都要先回答一个问题：
**如果这个开关生效了，我预期看到什么与现在必然不同的东西？** 答不上来就说明这次探测
设计不出结论，换一档再测，而不是把模棱两可的观测硬解释成结论。
