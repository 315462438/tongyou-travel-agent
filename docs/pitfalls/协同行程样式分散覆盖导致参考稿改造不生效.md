# 协同行程样式分散覆盖导致参考稿改造不生效

## 现象

修改 `index.css` 中最早的“Phase 35/36 协同行程”样式后，页面只有部分颜色或尺寸生效；
标题栏、三栏宽度、面板圆角等仍显示为后续版本的旧值。在不同窗口宽度下还可能出现桌面样式
生效、显式移动模式却回到旧样式的情况。

## 原因

协同行程经过多个阶段迭代，同一批选择器分散在 Phase 35、36、43、47、61、63、65 等区段。
后出现且权重相同的规则会覆盖前面的修改；显式 `.mobile-layout` 又不完全依赖媒体查询，单改
`@media (max-width: ...)` 无法覆盖桌面窗口里的手机预览模式。

## 解决办法

1. 新视觉主题放在现有业务样式之后，以 `.trips-overlay` 作为局部作用域统一覆盖，避免污染主站。
2. 使用协同行程自己的 `--trip-*` 语义别名映射全局 `--tx-*` token；不要复制参考稿色值，
   也不要修改全局 token 影响其他页面。
3. 响应式同时覆盖两条路径：真实窄屏媒体查询和 `.trips-overlay.mobile-layout` 显式移动模式。
4. 桌面新增导航后，移动端必须显式隐藏它，并恢复原有地图/助手内部标签，避免功能入口丢失。
5. 用源码结构回归测试固定 token、栏宽、导航显示规则和移动触区，防止后续阶段再次静默覆盖。
