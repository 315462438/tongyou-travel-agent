# 推荐页不能先让用户面对空白搜索框

日期：2026-08-10

## 现象

接力站已经支持任意目的地，但首屏仍先展示搜索表单。用户进入页面时还没有明确目标，视觉上只得到
一个需要完成的任务，没有获得任何“最近哪里值得看”的灵感。同时输入框仅设置 `outline:none`，
没有重置浏览器/全局样式带来的 `border` 和 `appearance`，聚焦后出现突兀的黑色矩形。

## 原因

- 发现型页面和工具型页面的首屏目标不同：发现页应先给内容，再要求输入；
- 输入框的原生外观由 border、outline、appearance、box-shadow 多层共同决定，只改一项不可靠；
- 热门数据和封面能力已经在 onboarding 使用，社交页却又单独写死了一套目的地。

## 解决办法

- 首屏先读取平台近 30 天真实热问数据，展示四张带真实封面的目的地卡；
- 搜索降级为“没有你想去的？”第二入口；
- 复用已有 onboarding/covers 和图片代理，避免第二套推荐口径；
- 搜索 input 显式设置 `border:0; outline:0; appearance:none; box-shadow:none`，焦点光效统一放到容器；
- 动效复用 React Bits Aurora，设置 `pointer-events:none`，并在低动态偏好下不挂载；
- 接口回退时更换文案，不能把静态兜底伪装成实时热榜。

## 结论

旅行发现页的顺序应是“先给灵感，再允许精确搜索”。复用真实数据源和明确处理浏览器原生样式，
比单纯给表单套一个大卡片更能提升吸引力。
