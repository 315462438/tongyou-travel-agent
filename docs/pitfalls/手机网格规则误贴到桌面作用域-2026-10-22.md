# 手机端的网格规则被贴到了桌面作用域

**现象**：桌面 AI 对话页的输入框被挤成右侧一条窄列，「问我任何旅行问题…」竖排，停止按钮压在模式胶囊上。

**原因**：2026-10-20（e2357d5）把 `.composer` 的手机三列网格（`34px minmax(0,1fr) 36px`）连缩进一起贴进了
`index.css` 顶层，替换掉原来的 flex 规则。手机作用域（720px 媒体查询、`.view-mobile`）给每个子元素都指定了格子，
桌面没有 → 子元素自动排布，输入框落进第 3 列（36px）。

**解决**：顶层恢复一行 flex；网格只留在手机作用域。`interaction-utils.test.mjs` 钉住顶层规则必须是 flex、不得有
`grid-template-columns`。

**一般化**：挪动 CSS 时带着缩进的规则块往往来自某个媒体查询，贴到顶层前确认它依赖的配套规则是否一起生效。

## 第二轮（同日）：修了桌面，721–1000px 仍然错位

桌面修好后用户截图仍错位。原因是**还有第三个作用域**：窗口宽度在 721–约 1000px 时应用切到 `.view-mobile`
布局，它的网格同样只给 `.composer-modes` 指定了格子，plus / 上传图片 / 输入框 / 发送都靠自动排布——
上传图片按钮占掉第 2 列，输入框又落进 36px。720 以下的媒体查询给了大部分格子，唯独漏了上传图片按钮。

修法：两处手机网格都改为 `auto auto minmax(0,1fr) 36px`，每个子元素显式指定列。测试钉住每个子元素都有
`grid-column`，并覆盖 390/600/720/721/800/1000/1440 七档宽度实测输入框宽度。

**教训**：第一轮只量了 1000 和 1440 两档，正好跳过了出问题的区间。布局修复要扫断点两侧（720/721）和
视图模式切换点，而不是挑几个「典型宽度」。
