# iOS 签名续期时命令行找不到账号

## 现象

续签 iOS 1.0.11（12）时，`xcodebuild -allowProvisioningUpdates` 报 `No Accounts` 和找不到 `com.yuchengjiang.tongyou` 的描述文件，但 Xcode 的 Apple Accounts 页面显示个人团队已登录。

## 排查与处理

- 系统钥匙串中仍有有效的 Apple Development 证书；最初本地只有另一 App 的描述文件。
- 在 Xcode 的 Apple Accounts → Personal Team 下载描述文件后，单独重试命令行仍失败。
- 用 Xcode 打开 `ios/Tongyou.xcodeproj` 并查看 Signing & Capabilities 后，同游及 UI 测试的 Xcode Managed Profile 自动生成；随后同一命令行构建成功。根因尚未完全确定，不能仅凭 `No Accounts` 判断必须重新登录或重建证书。
- 设备服务、钥匙串和签名信任检查需要在允许访问 macOS 系统服务的执行环境运行。受限环境曾使 `security find-identity` 返回 0、`codesign --verify` 返回 `CSSMERR_TP_NOT_TRUSTED`；获得系统服务访问权限后，同一证书/产物校验通过。
- 新描述文件创建于 2026-10-22 09:29:48 +08:00，到期于 2026-10-29 09:29:48 +08:00。

## 安装后的设备确认

`devicectl device install app` 成功后，第一次启动被 iOS 以 Security 拒绝，错误列出无效签名、权限或未显式信任描述文件的可能性。应先核对本地产物签名、有效期及包名，再由用户在手机「设置 → 通用 → VPN 与设备管理」检查开发者信任/验证。安装成功不能直接视为启动成功，也不要为解决续签而先卸载 App。
