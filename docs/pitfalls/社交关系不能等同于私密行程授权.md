# 社交关系不能等同于私密行程授权

日期：2026-08-10

## 现象

加入好友系统后，很容易直接复用现有协同行程成员关系，或默认让好友看到用户的私人会话、记忆和
行程。这会把“保持联系”错误升级成“访问私人旅行数据”，既违反用户预期，也可能造成越权。

另一个隐蔽问题是：即使接力列表过滤了私密主页作者，如果阶段统计仍对所有帖子计数，陌生人仍能
从数量变化推断私密用户的活动，且页面数字会和可见内容不一致。

## 原因

- 好友关系是长期社交关系，协同行程成员是单份行程的显式授权，两者生命周期和权限完全不同；
- 只关注响应正文中的字段隐藏，忽略了聚合统计也可能泄露不可见数据；
- 头像上传接口返回上传 ID，如果资料接口不校验归属，用户可以绑定其他账号上传的图片。

## 解决办法

- `travel_friendship` 独立建模，不写入 `travel_trip_member`，成为好友不会自动加入任何行程；
- 私人行程、聊天、记忆不出现在社交 API 字段白名单里，协同仍要求用户主动邀请；
- 接力列表和阶段统计使用相同的公开性条件：公开主页作者，或查看者本人；
- 私密主页仅本人或已经接受的好友可查看，搜索始终排除私密主页；
- 绑定头像前校验 `travel_upload.user_id == current_user.id`；
- 用自动化测试覆盖私密作者的帖子和统计同时不可见，以及好友可查看私密主页但仍拿不到私人行程。

## 结论

社交关系只能作为展示资料的一个可见性信号，不能成为业务资源的隐式授权。任何新增社交功能都应
分别检查正文、聚合统计、媒体归属和下游资源权限。
