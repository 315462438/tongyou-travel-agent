# 品牌改名不能只改浏览器标题

## 现象

浏览器标题改名后，微信顶部仍可能显示旧名称或旧闪电图标；登录页、侧栏、移动顶部栏和导出的路线
海报也可能继续出现旧品牌，形成多个名字并存。

## 原因

1. 品牌信息散落在 `index.html`、favicon、React 页面、海报模板和 LLM system prompt。
2. favicon 是强缓存资源，即使文件内容替换，WebView 仍可能继续使用旧 URL 的缓存。
3. 站内旧图标是多处复制的内联 SVG，单点修改容易漏掉。

## 解决办法

1. 建立统一的 `BrandIcon / BrandWordmark` React 组件，登录页和主界面共用。
2. favicon 改为新路线图标，同时将引用升级为 `favicon.svg?v=2` 主动刷新缓存。
3. 同步 HTML title、application-name、Apple Web App title、Open Graph 标题和描述。
4. 搜索用户可见代码中的旧品牌，并增加自动化测试防止 `travelX` 回流。
5. 后端面向用户的助手 system prompt 同步使用“17同游”，内部服务名和 API 路径保持不变。

## 后续约束

- 品牌文案统一从“17同游 / 17tongyou / 一起规划，一起出发”三项中选用。
- 新增页面不得重新内联一套品牌图标。
- 再次更换 favicon 时必须升级查询版本号，微信和 Safari 才能可靠刷新。
