# 前端改动「部署了但没生效」：dist 被拷成了 static/dist 子目录

2026-08-13，Phase 87 前端上线时踩到。

## 现象

后端改动生效（新表建好、新接口可用），但**前端界面完全没变**——新增的标签一个都没出现。
部署脚本报「部署完成」，服务健康检查通过，日志无 error。

## 原因

按 CLAUDE.md 的部署说明执行：

```bash
npm run build && cp -r dist ../backend/static
```

`cp -r src dst` 的语义是：**dst 不存在** → 把 src 复制成 dst；**dst 已存在且是目录** →
把 src 整个放进去，变成 `dst/src`。

`backend/static/` 早就存在，所以这条命令实际产生的是：

```
backend/static/index.html        ← 旧的，仍在被服务
backend/static/assets/…          ← 旧的
backend/static/dist/index.html   ← 新构建，没人读它
backend/static/dist/assets/…
```

`deploy.sh` 忠实地把这个结构 rsync 上去了，nginx/FastAPI 仍然服务根目录下的旧 index.html。

排查时的关键一步是对比 hash：

```bash
grep -o 'assets/index-[^"]*\.js' backend/static/index.html   # index-BDpYJ3SW.js（旧）
# 而 npm run build 的输出里是 index-BsUgXpgz.js（新）
```

## 解决

```bash
npm run build && rm -rf ../backend/static/dist && cp -r dist/. ../backend/static/
```

`dist/.` 表示「dist 的内容」，才会铺进 static/ 而不是塞成子目录。
（`rsync -a dist/ ../backend/static/` 同理，注意源路径末尾的斜杠。）

服务器上也要清一次遗留的嵌套目录——`deploy.sh` 对 static **不带 `--delete`**
（故意的，为了让已打开页面的旧 chunk 不 404），所以错误结构不会自动消失。

## 教训

1. **`cp -r A B` 的行为取决于 B 存不存在**，这类命令写进文档时要用 `A/.` 或
   `rsync A/ B/` 把语义钉死，别依赖目标目录的当前状态。
2. **「部署成功」不等于「改动生效」**。健康检查只证明后端起来了。前端改动上线后，
   最快的自证方式是比对 `index.html` 里的 chunk hash 与本次构建输出是否一致：
   ```bash
   curl -s https://17tongyou.com/travel/ | grep -o 'assets/index-[^"]*\.js'
   ```
3. 后端生效、前端不生效，第一反应不该是「浏览器缓存」——先确认服务器上到底放的是哪一版。
