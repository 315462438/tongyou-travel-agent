# 中文按「连续汉字块」取关键词等于没切词

**日期**：2026-08-21（Phase 103，来源全文按关键词重取）

## 现象

给复用路径写「按本轮问题从全文里重新取窗口」时，关键词抽取第一版是：

```python
_CJK = re.compile(r"[一-鿿]{2,}")   # 2 字以上连续汉字块
found = _CJK.findall(text) + _WORD.findall(text)
```

单测直接暴露：

```
'第3家酒店的取消政策是什么，帮我详细介绍一下'
  -> ['家酒店的取消政策是什么', '帮我详细介绍一下']
```

整句被抓成**一个 token**。拿它去 `str.find(page_text)` 永远命中不了——功能表现是
「重取从来没成功过」，而且**不报错、不抛异常**，只是每次都静默退回旧摘录。

## 原因

英文靠空格天然分词，中文没有。`[一-鿿]{2,}` 只是「连续汉字」，标点之间的一整句都是连续的。

## 解决办法（两步，缺一不可）

**① 用虚词字符切开汉字块**：

```python
_FUNCTION_CHARS = "的了是在和与也都很就还要会能可有我你他她它们这那些什么怎样吗呢吧啊请帮给对从把被让再又只更最及以为而且但因所之其或等一二三四五六七八九十"
_SPLIT_CJK = re.compile(f"[{_FUNCTION_CHARS}]+")
```

⚠️ 表里**刻意不含** 中/上/下/里/出/个 —— 它们在真实地名里太常见（中山路、湖里区、出海口），
切进去会把地名劈碎。

**② 长片段再补首尾 n-gram 兜底**：

只靠①不够。动词不是虚词，穷举是输的：

```
'把行程改到湖里区' -> ['行程改到湖里区']   # 改/到 不在表里，还是粘着
```

与其无止境扩表，不如保证**短锚点一定存在**。中文短语多为中心语在后（「…的取消政策」
「…改到湖里区」），所以取末 3/4 字；也有中心语在前的（「早餐几点开始」），所以再取首 2/3 字：

```python
def _anchors(frag):
    if len(frag) <= 4: return []
    return [frag[-3:], frag[-4:], frag[:2], frag[:3]]
```

结果：

```
'把行程改到湖里区'   -> ['行程改到湖里区', '到湖里区', '湖里区', '行程改']
'加上中山路和鼓浪屿' -> ['加上中山路', '上中山路', '鼓浪屿', '中山路', '加上中', '加上']
```

噪声锚点（`行程改`）匹配不上页面，代价只是白占一个候选位。

## 为什么不上分词库

jieba/pkuseg 要装依赖、要加载词典（内存本来就紧），而这里的产出**只是给 `str.find` 找锚点**，
不需要词性、不需要准确边界。多切几刀比少切安全：切碎了顶多多几个无效候选，切不开就是
一个都用不了。

## 一般化

**「按字符类正则抓词」在中文上是个静默失效的默认选项。** 它不报错、不崩溃，只是永远匹配
不上，功能看起来「实现了但没效果」。

写这类代码时用例里必须放**真实中文问句**（带的/是/什么/帮我），而不是 `"关键词"` 这种
已经切好的样本——后者会让第一版顺利通过。
