# 本轮的中间产物会污染「上一轮说了什么」的判定

**发现**：2026-09-02，回答「记忆三态是怎么触发的」时顺手查出来的。

## 现象

三态通知（Phase 106 ②）在 guide 链路上**一直跑在退化档位**，线上每一轮都是，且不报错：

- 精确 diff（「忌口」已被移除，不再适用）只到得了 `parse_request` 和
  `emit_guide_quick_take` 的 prompt——本轮最早、最不需要它的两处；
- **写攻略正文那次永远只拿到泛泛的「以当前这份为准」**；
- Unknown 分支返回的 `announced` 是 `{}`（假值），于是 `meta.memories_changed`
  在 guide 路径上**从来没被写进去过**，「只说一遍」的账本恒空 → 那句泛泛的每轮都发。

## 根因

`previous_injected_memories(cid)` 靠扫最近的 assistant 消息来判三态，过滤掉了
流式占位 / 海报 / 预算面板，**但没过滤快答**。而快答写的 meta 是：

```python
_add_message(cid, "assistant", text, meta={"preliminary": True})
```

**没有 `memories_used`**。图的拓扑是 `parse → quick_take → collect → generate`，
所以终稿那次 `gather_context` 回头看时，最近一条「真回合」是**本轮自己刚写的快答**，
读不到 `memories_used` → 判 `_UNKNOWN`。

复现（真实消息序列）：

```
① 上一轮终稿之后                          -> InjectionHistory  (Known ✓)
② 本轮流式占位 + 快答落库之后（终稿看到的） -> _UNKNOWN          ✗
```

## 一般化

**凡「读回自己写过的东西」来判定历史状态的地方，都要问：本轮自己的中间产物会不会混进去？**

这条与 Phase 111 那条（`docs/pitfalls/别靠文案认出自己发过的消息.md`）是同一个家族的
两种走样：

| | 判据错在哪 |
| --- | --- |
| Phase 111 | 用**产物的形状**（问号结尾、长度）认自己发过的反问 → 措辞一变就失效 |
| 本条 | 判据本身对，但**扫描范围**把本轮自己的中间产物也算了进去 |

更糟的一点是它**自己跟自己比**：快答与终稿在同一轮，`gather_context` 的输入完全相同，
拿快答当基准的话 diff 必然为空——等于把变更信息整个吃掉。所以这不只是"多发一句噪声"，
是**该发的那句永远发不出去**。

## 为什么单测没抓到

原有 25 条用例里，构造的都是「上一轮终稿 → 本轮」这种干净序列，**没有一条在中间插入
本轮自己的快答**。而 `guide_quick_take` 默认 `True`，线上每一轮都插。
**测试的输入形状比生产干净，是这类失效最常见的藏身处**（同 Phase 111：单测喂的是
「想去哪里呢？」这种教科书式短问句，正好落在启发式命中的那一侧）。

## 修法

把 `preliminary` 加进过滤名单（`app/agent/memory.py`）。快答是**本轮内**的产物，
不是「早前告诉过模型什么」。

回归用例直接用真实序列做输入（`test_quick_take_does_not_reset_the_state_to_unknown`、
`test_a_turn_that_only_produced_a_quick_take_is_not_a_baseline`）；变异检验：
把 `preliminary` 从过滤里去掉 → 立刻红 2 条。
