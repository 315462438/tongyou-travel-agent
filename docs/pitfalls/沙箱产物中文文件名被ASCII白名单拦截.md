# 沙箱产物中文文件名被 ASCII 白名单拦截（下载 400）

## 现象

线上（2026-07-14）深度研究成功产出 `slides__output__商丘旅游指南.pptx`，前端产物卡片
点「下载」浏览器提示「网站出问题了」。后端无异常日志。

## 原因

`app/api/sandbox_artifacts_api.py` 的路径段安全校验用的是 ASCII 白名单
`^[A-Za-z0-9_.\-]+$`——写的时候只想着防路径穿越，忘了产物文件名来自 agent 起名，
**必然经常含中文**。中文文件名直接 400 "invalid path"，浏览器把下载失败显示成
「网站出问题了」，且 4xx 在后端只是正常请求日志，不留错误痕迹。

## 解决

- `batch_key`（服务端 uuid4 hex）保持严格白名单不变；
- `filename` 改黑名单：拒绝空段/`.`/`..`/`.` 开头（隐藏文件）/含 `/`、`\`、NUL、`..`；
  路径穿越仍有 abspath 前缀双重保险兜底。
- 测试补了中文文件名单元 + TestClient 全 HTTP 栈用例（Content-Disposition 对非 ASCII
  文件名由 Starlette 自动转 RFC 5987 编码，实测 200）。

## 教训

- 凡是「用户/模型起名的东西进 URL」，安全校验必须按**黑名单排除危险字符**设计，
  ASCII 白名单迟早拦下正常的中文名。
- 下载类 4xx 前端只会显示浏览器的笼统报错、后端也没有异常日志，排查时先手动 curl
  一次真实 URL 看状态码。
