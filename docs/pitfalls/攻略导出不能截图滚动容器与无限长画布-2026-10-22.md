# 攻略导出不能截图滚动容器与无限长画布

## 现象

用户反馈 Android 攻略长图拥挤、内容不全，iOS 导出则整张空白。用户补充前一张来自 Android，不能把两类问题都按 iOS 排查。原始空白图为 398 × 10796 像素。

## 原实现的限制

- Android `GuideBody` 用 html2canvas 直接截图聊天正文，正文中有横向滚动的表格与延迟加载图片。截图受到当前阅读容器尺寸/滚动状态影响，并非独立的分享版面。
- iOS 将整个 SwiftUI Markdown 页面交给离屏 ImageRenderer，表格强行分配在 390 点页面内，正文越长图片越高，缓存中的配图才会显示。仅检查 UIImage 非 nil 不能证明导出真的含文字；此次没有把空白图的底层渲染原因武断归结为某个确定的像素阈值。

## 处理

两端独立生成固定宽度计划单，只复制逐日安排与原文时间；未知时间不编造。通过分张保留全部抽取到的地点，使用实际文字测量布局，不再截图滚动表格。iOS 使用 UIGraphicsImageRenderer，Android 使用 Canvas 2D；预览即实际导出图片。iOS 完整攻略提供分页的文字 PDF；Android 简版旁可下载完整原文。协同行程的 Android 导出直接使用结构化地点数据。

## 解析和测试中的坑

- `第7天地点` 这样的表格单元格可能误触发日期标题正则。必须先排除表格/列表行，再识别日期；回归覆盖七天表格、末日末点与分张顺序。
- iOS URLProtocol 测试桩中的 POST 内容可能在 `httpBodyStream`，不能只查 `httpBody`，否则“用户不存在”的失败测试会错误地走成功分支。
- `accessibilityReduceMotion` 是只读的系统环境值，不能直接用 `.environment` 注入；生产继续读取系统设置，测试仅通过 DEBUG 启动参数覆盖邀请卡的动效分支。
- UI 自动化还必须检查实际 PNG 的尺寸、深色文字像素，以及长行程的末页。仅验证分享按钮存在、文件存在或系统调用返回成功都不足够。
- Android 原生回归中的旧首页测试把文字锁死为 `rgb(240,242,247)`，实际 Journey 主题是同样可读的 `rgb(238,242,248)`；改为检查深色场景文字通道亮度与草稿保持，不为匹配旧断言修改产品配色。
- 第二轮 Android 模拟器出现图形 ColorBuffer 错误及系统进程 `com.android.phone` 的 `DeadSystemException`，测试报告 `INSTRUMENTATION_ABORTED: System has crashed`。这不是 App 崩溃证据。仅重启本次专用 `TongyouQA35`，用 `-gpu software -cores 2 -memory 2048` 启动，在其他编译/UI 测试结束后单独重跑；不能把中断的测试当成通过。

## 邀请交互边界

链接创建只发生在用户点击复制/分享时；打开邀请面板不自动开启链接。现有行程邀请链接没有 24 小时过期协议，因此不能照参考图写假的期限。用户名邀请仍需对方接受；链接持有人可以加入编辑，须明确说明并提供关闭入口。
