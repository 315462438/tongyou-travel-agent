# 踩坑：流式生成时的自动滚动把用户「拽」回底部

**发现时间**：2026-08-04（线上反馈）
**涉及文件**：`frontend/src/pages/Home.tsx`、`frontend/src/interaction.ts`、`frontend/src/index.css`

## 现象

模型正在生成攻略时，页面每隔一两秒就自己往下跳一次。用户想往上翻看前面已经生成的内容
（或上一轮的回复），刚滚上去就被拉回底部，**根本读不了正文**。生成一份完整攻略要 2-6 分钟，
这段时间等于整个页面不可用。

## 原因

`Home.tsx` 里有一段无条件的「滚到底」：

```tsx
useEffect(() => {
  bottomRef.current?.scrollIntoView({ behavior: 'smooth' })
}, [messages])
```

它在聊天不是流式的时候没问题（`messages` 只在发消息时变一次）。但 Phase 11 之后攻略生成改成
**流式**：前端每 1.5s 轮询 `GET /api/chat/{cid}/messages`，`setMessages(data.messages)` 每次都产生
新数组引用 → effect 每 1.5s 触发一次 → 每 1.5s 强制滚到底一次。

**教训：任何「内容变化就滚到底」的 effect，在内容变成流式/轮询刷新的那一刻就会变成 bug。**
两者是在不同 Phase 引入的，单看各自都合理，凑一起才出问题。

## 解决

「粘底跟随」（stick-to-bottom）——只有用户本来就贴着底部时才跟随：

1. `interaction.ts` 出纯函数 `isNearBottom` / `shouldFollowBottom`（容差
   `NEAR_BOTTOM_PX = 120`），可单测。
2. `.thread` 挂 `ref` + `onScroll`：每次滚动重算是否贴底，写进 `stickBottomRef`。
3. 跟随 effect 改成 `if (!stickBottomRef.current) return`，且用 `threadRef.scrollTo` 而非
   `bottomRef.scrollIntoView`（后者会连带滚动所有祖先容器）。
4. 脱离时在 `.thread` 底部显示 sticky 的「↓ 回到最新内容」按钮，用户主动点回来。
5. 自己发新消息 / 切换会话 / 从协同板发起提问时，强制把 `stickBottomRef` 置回 `true`。

## 只靠 onScroll 不够：程序化平滑滚动会和用户抢方向盘

`scrollTo({ behavior: 'smooth' })` 的动画过程**自己也会持续触发 scroll 事件**。用户在动画进行中
往上滚，处理函数可能在动画还没结束的某一帧算出「仍然贴底」→ 把 `stick` 判回 `true` → 下一次
轮询又滚下去。表现是「往上滚一下，被弹回来」，比完全不能滚更难受。

所以额外挂了 `onWheel`：`deltaY < 0`（往上滚）的瞬间就直接 `stickBottomRef.current = false`，
不等 `onScroll` 复算。之后用户自己滚回底部时，`onScroll` 会正常把跟随打开。

## 参照实现

`frontend/src/pages/Trips.tsx` 的群聊（`nearBottomRef`）早就是这个模式，改 Home 时对齐了它。
**以后凡是新增「会自动增长的消息列表」，默认就要带 near-bottom 判定，别再写无条件 scrollIntoView。**
