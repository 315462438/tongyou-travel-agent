# 多轮补图复用旧来源导致零图片

## 现象

用户在一份已有攻略后说“补一下各个行程中的图片”，新回复标题变成“含图片版”，正文却仍然没有图片。
线上检查发现该回复：

- Markdown 图片数：0
- 小红书来源数：6
- 六个来源的 `images` 数量全部为 0

## 原因

多轮修改为了提速，只要目的地不变且来源类型覆盖需求，就直接复用上一轮 `sources`。
这些来源是在小红书图片解析功能上线前保存的，只有 `title/url/summary`，没有 `images`。
生成模型拿不到“可插入图片”清单，却仍会顺着用户措辞写出“含图片版”，造成文案与产物不一致。

## 解决办法

1. 在复用旧来源之前识别明确图片意图：补图、图片、配图、图文、含图、照片、实景图。
2. 图片意图成立且旧来源图片少于 3 张时，强制刷新当前目的地的小红书来源。
3. 按 URL 合并：同一来源只补 `images`，新有图来源追加，空图来源不追加。
4. 模型漏写图片占位符时，确定性地把最多 5 张图分散插到前 5 个章节，五日内行程可每天一张。
5. 不把“推荐拍照机位”误判成“给攻略补图片”，避免无意义刷新。

## 后续注意

- “复用来源”不能只判断来源类型，还要判断本轮所需的能力字段是否存在。
- 模型在标题里声称“含图片”不算验收；必须检查最终 Markdown 中实际图片数。
- 数据结构升级后，要考虑旧消息持久化的兼容与按需刷新，而不只是新采集链路。
