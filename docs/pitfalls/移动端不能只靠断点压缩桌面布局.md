# 移动端不能只靠断点压缩桌面布局

## 现象

桌面端侧栏、消息区、攻略正文、输入框和弹层各自积累了若干 `max-width` 媒体查询。手机上虽然元素
勉强能缩小，但会同时出现顶部入口分散、侧栏宽度归零闪烁、输入框与底部安全区冲突、攻略操作按钮
换行过多等问题，整体仍像“被压扁的网页端”。

## 原因

1. 只有断点，没有明确的移动端布局状态和信息架构。
2. 折叠侧栏通过 `width: 0` 与子元素透明实现；改成浮层后仍会触发布局计算和过渡抖动。
3. 输入框、正文和导航都以桌面流式布局为基准，缺少统一的顶部栏、底部导航与可用高度约束。
4. 仅用 `window.innerWidth` 判断设备会漏掉手机横屏和部分触屏设备。
5. 底部导航初版只触发目标入口，没有关闭当前的全屏浮层；因此“新对话”状态已更新，
   但协同行程仍覆盖在上方，看起来像按钮失效。

## 解决办法

1. 根节点增加 `view-desktop / view-mobile` 显式状态；媒体查询负责物理视口，状态类负责信息架构。
2. 手机首次访问按 `width <= 820` 或 `(pointer: coarse)` 进入移动端，并提供可见切换与本地持久化。
3. 移动侧栏保留稳定宽度，用 `transform: translateX()` 开关；正文不再参与侧栏宽度动画。
4. 统一增加顶部栏和带 Safe Area 的底部导航，正文/输入区在同一个 `100dvh` 应用壳中分配高度。
5. 长攻略的表格和操作栏在组件内部横滑，禁止把横向滚动泄漏到整个页面。
6. 移动底栏按互斥一级导航实现：进入对话、历史或记忆前先关闭协同行程及其他抽屉，
   不能把它当成多个互不相关的弹层开关。

## 后续约束

- 新的一级入口应同时考虑桌面侧栏和移动底栏/抽屉的可达性。
- 底栏新增入口时必须写“从其他每个一级页面切入”的状态互斥测试。
- 手机触控目标不小于约 44px；底部固定元素必须包含 `env(safe-area-inset-bottom)`。
- 适配不能只测 375px，还需覆盖 360、390、430px和横屏粗指针场景。
