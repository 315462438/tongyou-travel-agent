# 安卓原生迁移的会话边界与网页兜底

## 旧登录凭证只应迁移一次

现象：旧版 token 在 https://17tongyou.com 的 WebView localStorage 中；直接换原生登录页会丢失登录态。若每次启动都读取旧 storage，原生退出后又可能恢复旧凭证，且每次冷启动还会启动浏览器内核。

处理：LegacySession 使用相同 origin 的离线空页面读取旧存储，不加载业务页面、不触网。TokenVault 通过 Android Keystore 的 AES-GCM 加密并同步提交，成功后登记 migrated，再清理旧值。后续冷启动只读取密文。网络失败保留凭证，401 只能清理发出该请求时的那一个 token。

## 异步清理不能抹掉新登录

现象：账号 A 退出后异步写 WebView 清空 token，如果用户已经登录 B 并打开网页兜底，迟到的清空可能把 B 的登录也删除。

处理：原生退出同步清理加密存储并保留迁移完成标记，不启动异步 WebView 清理。网页兜底在同源主文档启动时写入当前 native token 或清空；Storage 变化通过限定来源/主框架的桥同步回原生。旧页面只有在 expected token 仍匹配时才能修改会话。聊天服务捕获会话 token，并在请求前后检查会话未切换，避免旧页面借用新账号凭证。

另一个生命周期边界：进程被回收后，Android 可能直接重建最后停留的 WebFallbackActivity，而非先运行 MainActivity。容器必须先从加密存储恢复内存会话，才能注入页面；否则会把“尚未初始化”误认成“已退出”并清除网页登录。没有凭证或读取失败则返回原生鉴权入口。

## Android 网页兜底没有公共 URL 路由

现象：共享 Home.tsx 的会话/账本/账户/通知由 React state 控制，简单打开首页 URL 会丢失用户点击时的目标上下文。

处理：Android 独立 Vite 插件在构建快照时注入一次性路由 hook，调用已有 selectConv/openLedger/openAccount 等动作；Java 容器只注入白名单路由和 id。共享网页源码及 Web 发布产物均不改。插件要求源锚点唯一，失配即构建失败；脚本测试实际执行注入的各条路由，而不是只比较代码字符串。

## Compose 与 Markdown 的类型重名、仪器测试语义树

首次编译时 CommonMark Paragraph 与 Compose Paragraph 同名，需在分支中明确限定 org.commonmark.node.Paragraph。首轮设备测试的 4 条聊天用例因 FAB 文本在合并语义树中不可见而未能进入聊天；使用稳定的 open-ai testTag 定位按钮。此后用户要求停止模拟器，因此只编译修正后的测试包，不把这些用例记为已通过。

## 接口 409 不能当成本次消息已被接收

后端 409 表示已有一轮正在处理，本次草稿没有提交。ChatModel 会保留草稿和图片并继续观察当前任务；只有本次提交成功且输入仍与提交前一致才清空。点击追问也不应删除用户已写在输入框里的另一条草稿。对应行为已落地单元测试。
