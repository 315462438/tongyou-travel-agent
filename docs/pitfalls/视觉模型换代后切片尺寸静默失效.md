# 视觉模型换代后切片尺寸静默失效

## 现象

2026-09-10 DeepSeek 把 `deepseek-v4-flash-vision-exp` 转发到 V4.1 Flash。我们没改一行代码，
长截图读图照常返回、行数齐全、不报错——但数字大面积念错：1800×25242 长图（旧切法 8000 高 × 4 片）
按行对齐 **0%**、集合命中 38%。

## 原因

Phase 111 校准的是「单边 8192px 会不会被 400」，那是**收不收**的闸门。V4.1 每张图最多 1024 token
（官方计算器 v41 配置，约 1300×1300 的信息量），过了闸门的大图在服务端被缩小再读——**读不读得清**
是另一个维度，而切片参数只按前者定。模型别名转发让换代完全无感。

## 解决

单片按像素预算切：`tile_side = min(8000, vision_max_tile_pixels // width)`，预算 4MP，最多 16 片。
实测 3000/2000 高切片 100%。

## 教训

- **模型名被转发 = 模型换了**。凡按模型实测出来的参数（尺寸上限、思考档位、max_tokens），
  换代时都要重测，别名还能用不代表参数还对。
- 测「读得准不准」不能用有规律的数据：第一次用等差数列价格测出 136/136 全对，是模型推出来的，
  换成随机数立刻掉到 66%。
- 官方信息源之间也会对不上：API 文档 changelog 写 v4-pro「继续服务、计费不变」，而开放平台控制台公告写
  「V4.1 Pro 上线前，对 V4 Pro 的请求全部路由到 V4.1 Flash 并按 Flash 计费」。当天按控制台公告执行
  （更具体、且是面向本账号的通知），并全部切到 `deepseek-flash`。别只看一处就下结论。

## 同一天的第二个坑：换模型后「按一个人填」被当成照抄

抽取链路要求模型「金额按一个人算」。预算表标题写「两大一小」、表身是全家金额时，
V4.1 Flash 4 次里 3 次原样照抄 → 预算面板人均总额是正文的 **3.18 倍**，不报错、每行看着都对。
v4-pro 没踩是因为它根本没抽那张表（漏住宿油费、总额偏低）——**换模型换掉的是失误方向，不是失误本身**。

**原因**：「按一个人算」是一道隐藏的除法题，模型要先判断口径再换算，两步里任何一步走神就错。

**解决**：模型只照抄金额 + 标 `scope`（per_person/group），除法在服务端用最终人数做（Phase 67 同一原则：
不让模型算数）；`scope` 用 str 不用 Literal，免得一个枚举外的值打挂整条 cost 路。

**教训**：prompt 里每一个「按 X 口径填」都是藏着的算术。能拆成「照抄 + 分类」的，就别让模型换算。
