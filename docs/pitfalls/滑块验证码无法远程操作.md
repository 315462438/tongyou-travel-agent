# 滑块/拖动类验证码无法通过截图直播远程操作

> 记录：2026-07-06（用户报告：百度百科弹出旋转图片验证码，接管卡片操作不了）

## 现象

需登录来源确认卡选「登录读取」后，handoff 卡片里展示的是**百度安全验证**
（拖动滑块使图片转正）——截图直播是只读的，用户看得见但拖不了，
流程只能干等到超时。

## 原因

Phase 5 的远程接管设计基于「扫码登录」：二维码在**手机上**完成操作，截图只需
「看」。而滑块/拖动/点选类验证码必须在**那个浏览器里**产生可信的鼠标轨迹，
静态截图无能为力。两类页面此前都被归为 need_user_handoff 同等对待。

## 解决办法

区分 page_type：
- `login_wall`（可扫码）→ 保留远程接管（截图直播 + 扫码）。
- `captcha`（滑块类）→ **服务器模式不弹卡**，progress 说明
  「弹出了滑块验证码，云端浏览器无法远程操作，已跳过」后直接回退；
  本地模式保留接管（可见窗口里用户能拖）。

检测强化（`_detect_page_type`）：URL 含 `/verify` `/captcha` `wappass.` 或
文案含「拖动滑块/完成下方验证/安全验证/访问异常」→ captcha，不依赖 LLM 判定。

## 后续可选

真想远程过滑块需要做「坐标级远程操控」（前端在截图上拖动 → 轨迹转发 →
CDP Input.dispatchMouseEvent 产生可信事件），工程量大且对旋转/拼图类成功率低，
暂不做；百度系来源价值有限，跳过代价小。
