# Markdown 渲染中文场景三连坑（2026-07-30 走查发现）

LLM 生成的中文攻略 + react-markdown/remark-gfm 组合下，三个确定性渲染坑，
全部在线上真实出现过。修复见 `frontend/src/interaction.ts::prepareMarkdown`
与各 ReactMarkdown 挂载点、`backend/app/agent/orchestrator.py::_embed_images`。

## 1. GFM 单波浪线把价格区间吃成删除线

**现象**：`经济型 ¥400~600/晚，中档 ¥600~900/晚` 渲染成 `¥400600/晚，中档 ¥600900/晚`
（中间文字带删除线，视觉上直接消失/被读错）。

**原因**：remark-gfm 默认支持**单个** `~` 作删除线定界符。中文攻略里 `~` 几乎只用来
表示数字区间，两个区间的 `~` 互相配对，中间整段变 `<del>`。

**解决**：挂载时传 `[[remarkGfm, { singleTilde: false }]]`——`~~删除线~~` 仍可用，
单 `~` 恢复为普通字符。visual-regressions 测试里有护栏防止回退成默认挂载。

## 2. CJK 标点紧邻 `**` 时加粗不成立，星号裸奔

**现象**：`，**烤匠麻辣烤鱼（春熙路店）**解决午餐` 里 `**` 原样显示。

**原因**：CommonMark 定界符规则——关闭侧 `**` 前是标点（全角 `）`）、后紧跟文字时
不构成 right-flanking，不能闭合强调。中文「标点+加粗」是高频写法，模型天天这么写。

**解决**：渲染前 `prepareMarkdown` 把 `**内容**` 改写为 `**​内容​**`
（内侧垫零宽空格，使定界符两侧恒为「普通字符」），渲染不可见。所有 ReactMarkdown
入口（GuideBody、Trips 原攻略抽屉、copilot 回复）都要过这一层。

## 3. 兜底插图/占位符把表格从中间劈开

**现象**：四列行程表只渲染前两行，后两行变成 `| 傍晚 | … |` 裸文本。

**原因**：`_embed_images` 的兜底逻辑「在提及地点名的醒目行后插图」不区分该行是否在
表格块内；Markdown 表格行之间插入任何空行/图片行，表格即从该处断开。模型把
`[[img:]]` 占位符写进表格单元格时同理。

**解决**：`_embed_images` 全面表格安全化——表格行内命中的占位符/兜底图一律**推迟到
表格块结束后**插入（`_is_table_line` + pending 队列）。凡是「往模型生成的 Markdown
里程序化插内容」的新功能，都必须过表格避让，别再踩。

## 附：占位符要按「模型会写歪」设防

线上出现 `[img:名称]`（单括号）原样漏进正文：占位符正则只认 `[[img:...]]`。
模型对格式类约定的遵守是概率性的，解析端要宽容（现兼容单/双括号、半/全角冒号），
渲染端要有终稿剥离兜底。
