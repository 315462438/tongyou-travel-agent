# 旅行宠物必须读真实终态与键盘收起

## 部分正文不代表成功

现象：停止和异常失败会把流式消息终稿，已经产生的部分正文被保留；旧实现同时清空 meta。客户端只读“有非流式正文”无法判断本轮成功、停止还是失败，可能错误欢呼。

原因：输出内容与执行终态共用同一种表示。

解决：收尾保留原有正文行为，额外写入可选 `meta.cancelled=true` 或 `meta.error=true`；无占位时补的终稿也带标记。保持正常终稿不变，旧客户端继续兼容；React 与 Swift 按当前轮解读这些标记，成功动效只在同会话、同一轮实际经历 running 后播放。用户停止请求有本地状态兜底。

回归：`test_guide_quick_take.py` 覆盖部分正文保留及停止/失败标记；TS / Swift 检查确保部分结果不能报成功。

## 原生收起 AI 时不能只改透明度

现象：为保留草稿，原 AI NavigationStack 常驻，只用 opacity / hit testing 切换。加入键盘期间收起底部角色后，若文本输入仍是第一响应者，回到首页时可能继续保留键盘状态，导航与 AI 入口没有恢复。

解决：在 `router.aiOpen` 变为 false 时明确 resignFirstResponder，并重置 keyboardOpen；保留原视图和草稿。原 AI 收起/重开 UI 回归已通过。

## 系统提示与原生开关的 UI 测试

专用模拟器第一次打开键盘可能弹出滑行输入介绍，测试需处理系统 Continue 按钮。SwiftUI Form 的开关 AX frame 可能包含标签和留白，中心点击不一定落在实际 UISwitch 上；测试明确点右侧开关，并在退出前立即核对值，再检验重开和重启后的持久化。

常驻但不可见的 NavigationStack 仍可能出现在测试的完整 AX 层级中；“误开界面”应结合 isHittable、导航位置与实际截图判断，不能只使用元素 exists。
