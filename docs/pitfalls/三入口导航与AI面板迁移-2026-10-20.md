# 三入口导航与 AI 面板迁移

## 旧导航样式会覆盖新布局
现象：Android 旧五项底栏的选择器优先级高于新三项底栏，导致「我的」被独立 AI 按钮盖住。仅检查 DOM 中三个按钮存在不能发现问题。

解决：将迁移样式限定在 `journey-shell`，明确底栏与 AI 各自占用的宽度；用浏览器的 `elementFromPoint` 验证按钮中心实际命中，并覆盖 320px、横屏和桌面。旧账本/行程面板另有固定浅色背景，需要一起映射到主题变量。

## SwiftUI 按钮看得到但留白不能点
现象：AI 快捷按钮标签包含 `HStack + Spacer`，自定义按压样式后，自动化点击按钮中间没有触发动作，输入仍为占位文字。

原因：可视背景不等于点击区域，中间空白不在内容形状内。

解决：`TravelPressStyle` 为完整 label 增加 `contentShape(Rectangle())`，底栏用 `contentShape(Capsule())`。测试必须检查回填后的真实输入值，不只断言按钮存在。修复后 iOS 浅色、深色实际点击回归通过。

## 收起 AI 不能等同于销毁会话
Web 使用持久挂载的主视图加 `hidden`，输入状态保留在 Home；全局粘贴监听所在的启动输入组件只在打开时挂载。iOS 保留 AssistantView 的 NavigationStack 和 ChatStore，收起仅改变可见性及命中测试，隐藏时隔离辅助功能。进入对话后也提供「收起」按钮。

历史独立作为 sheet，从「我的」打开时避免把完整 NavigationStack 再嵌入另一个 NavigationStack；提供明确的「完成」关闭入口。

## 测试夹具必须符合真实响应结构
行程检查接口返回 `{issues: [], ticket_total: 0}`，不能统一返回 `[]`；错误夹具会造成无关的运行时异常。UI 测试使用隔离内存数据，不能依赖或写入线上账号。

截图时关闭/完成 CSS 动画，否则截图可能正好落在面板淡入的 opacity=0 帧，产生“没打开”的假象。实际点击、请求断言与截图需共同验证。

## 安卓升级测试不能把未来版本号写死
0.6.0 时更新提示夹具使用 versionCode=10；应用升级至 0.7.0 (10) 后，这个夹具成为“当前版本”，按正确业务规则不应再提示，旧测试就会失败。将夹具 code 改为 `BuildConfig.VERSION_CODE + 1`，下载路径和解析断言使用同一个动态 code，保证每次发布仍然覆盖“有新版”的真实分支。
