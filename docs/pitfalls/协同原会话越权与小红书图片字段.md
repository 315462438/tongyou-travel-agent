# 协同原会话越权与小红书图片字段

## 现象

1. 协同行程创建者点击“回到来源对话”正常；其他已加入成员点击后进入空会话或收到 404。
2. 小红书笔记已经参与攻略生成，但最终攻略仍经常只有高德/携程图片，海外攻略尤其容易成为纯文字。

## 原因

### 私人会话权限不能等同于行程成员权限

行程只保存了 `source_conversation_id`，前端直接切换聊天会话。聊天接口的正确安全边界是
`conversation.user_id == current_user.id`，所以 editor 不应也无法读取 owner 的完整私人会话。
问题不在聊天接口，而在协同板错误地把“查看导入的那一条攻略”实现成了“进入整个来源会话”。

### 小红书 MCP 的图片字段是驼峰且未被透传

线上 `get_feed_detail` 实际结构为：

```json
{
  "data": {
    "note": {
      "imageList": [
        {"urlDefault": "http://sns-webpic-qc.xhscdn.com/...", "urlPre": "..."}
      ]
    }
  }
}
```

旧解析只保留 `title/desc`，没有读取 `imageList`。此外 CDN 地址可能是 `http`，图片代理原白名单
也没有 `xhscdn.com`，即使直接透传也会被拒绝。

## 解决办法

1. 新增 `/api/trips/{trip_id}/source-guide`，先做行程成员校验，只返回被导入 assistant
   消息的正文与公开来源；不返回同会话的用户消息、其他回复、思考或记忆。
2. owner 响应额外带 `can_open_conversation=true`，editor 只看板内只读预览。
3. 解析 `imageList/image_list/images` 与 `urlDefault/urlPre`，每篇最多两张、去重并升级为 HTTPS。
4. `source.images` 接入统一配图库；模型漏放时，把最多三张小红书灵感图分散插到不同章节。
5. 图片代理只新增官方 `xhscdn.com` 后缀白名单，并在跟随重定向后再次校验最终 URL，防止绕过 SSRF。

## 后续注意

- “共享某个产物”不能通过放宽整个私人容器的权限实现；应提供产物级、最小字段的成员只读接口。
- 外部 MCP 的返回结构必须用线上真实样本核对，尤其注意 camelCase/snake_case 差异。
- 小红书图片应限量并保留来源链接，避免连续堆图、错配主题或把图片代理变成开放代理。
