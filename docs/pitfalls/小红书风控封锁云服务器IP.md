# 小红书风控封锁云服务器 IP（安全限制 300012）

> 记录：2026-07-06（Phase 5 线上冒烟时发现）

## 现象

服务器（腾讯云）上的 headless Chrome 打开小红书任意页面，显示的不是登录页而是：

```
安全限制
IP at risk. Switch to a secure network and retry.  300012
```

连登录二维码都不给展示 —— 扫码接管在这台服务器上对小红书走不通。
连带发现两个次级问题（均已修复）：

1. 该风控页被页面分类器判成可读内容 → 等待循环误判「登录成功」，
   把标题为「安全限制」的垃圾页当来源抓了进去。
   修复：`collect_via_site` 增加 `is_relevant` 相关性校验（复用 orchestrator 的
   `_is_relevant`，标题/正文须含目的地或旅行关键词），风控页被挡掉后回退搜索。
2. 本地开发（家庭宽带 IP）不复现，小红书正常出登录页 —— 这是 IP 信誉问题，
   不是代码问题。

## 原因

小红书对数据中心 IP 段（腾讯云/阿里云等）有风控黑名单，直接拒绝服务。
携程对云 IP 相对宽松（同一台服务器抓携程酒店列表页正常）。

## 解决/规避

- 已做：相关性校验兜底 + 超时回退必应搜索，整体流程不受阻塞。
- 如需服务器上真正抓小红书，可选：
  - 给 headless Chrome 挂住宅代理（`--proxy-server`，chrome-devtools-mcp 需要
    透传启动参数，待调研）；
  - 或小红书类内容继续依赖本地开发模式（本地 IP + 可见 Chrome 登录）。

## 经验

- 站点风控页可能长得像正常内容页，**站点直抓的内容必须过相关性校验**，
  不能只信页面类型分类器。
- 反爬处置要区分「要登录」和「IP 被封」：前者用户能救，后者等多久都没用。
