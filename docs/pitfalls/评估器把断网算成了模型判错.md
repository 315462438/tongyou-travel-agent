# 评估器把断网算成了模型判错

> 2026-08-14　建路由分类评估集（`backend/evals/route_eval.py`）当天踩到

## 现象

第一次跑路由分类评估集，报表打出：

```
严格准确率 **42.9%**（15/35），硬错 13 条，软错 7 条
```

混淆矩阵里绝大多数条目落在 `guide` 列。看上去是一个非常像样的结论——
**「快分类模型严重偏向 guide 通道」**，甚至能顺手编出解释：
ROUTE_SYSTEM 结尾那句「拿不准时一律选 guide」把模型带偏了。

这个结论是**完全错的**。真实情况是：跑评估的机器连不上 `api.deepseek.com`，
35 条里 33 条根本没调通模型。

## 原因

生产代码 `deep_research.decide_route()` 的兜底是对的：

```python
try:
    r = llm.classify(text[:500], _Route, system=ROUTE_SYSTEM)
except Exception:
    logger.warning("route classify failed, fallback guide", exc_info=True)
    return "guide"          # ← 分类挂了也得让用户拿到东西
```

问题在于**评估直接调了它**。于是：

| 发生的事 | 评估看到的 |
| --- | --- |
| 模型判成 guide | `"guide"` |
| API 连接失败 | `"guide"` |

两者**在返回值上完全无法区分**。评估把第二种算进了准确率的分子分母，
于是断网被记成「模型判错」。

更糟的是这个假结论**长得很合理**：它有混淆矩阵、有百分比、有一个说得通的
故事。如果不是恰好知道那台机器不通外网，很可能就照着这个数去改 prompt 了——
去修一个根本不存在的偏差。

## 解决办法

**评估侧不复用生产的兜底分支，自己接住异常并单独标档。**

```python
def classify_once(text, llm) -> str:
    """复刻 decide_route 的结构，但**不把异常吞成 guide**。"""
    if is_explicit_itinerary_request(text):   # 生产的确定性短路要一并复刻
        return "guide"
    r = llm.classify(text[:500], _Route, system=ROUTE_SYSTEM)   # ← 不 try
    ...
```

调用侧把异常标成 `run_error`，并且：

1. **单独一档 `error`**，既不算对也不算错
2. **准确率的分母是「跑成了的条数」**，不是总条数——把断网摊进分母会凭空造出
   一个「变差了」的结论；摊进分子更糟
3. 报表顶部大字提示「本轮不可用于前后对照」
4. **退出码 2**（≠ 1）：「跑不出来」要求人去看环境，「跑出来不合格」才是模型/prompt 的问题

回归测试：`tests/test_evals_routes.py::test_run_errors_never_masquerade_as_a_classification`

## 一般化

> **凡是生产代码有「失败时静默降级」的地方，评估都不能直接复用那条路径。**

降级在生产是正确的（用户要拿到东西），在评估里是有害的（把环境故障伪装成模型行为）。
这个项目里同类的地方还有：

- `xhs_mcp.search_notes` 失败返回 `[]`（评估会看成「小红书没搜到内容」）
- `_collect_amap` 单城失败 `continue`（评估会看成「高德没这个城市」）
- `build_trip_object` 单路失败留空且不登记 lane（评估会看成「正文里没有预算表」）

第三个已经在 `evals/extract_checks.py` 里区分了：`ext_no_expenses`（抽不到）
与 `ext_empty_lane_registered`（空结果却登记了，会被缓存固化）是两个不同的 code。
