现象：用户将“同一行程关联多个个人账本”理解为同行成员共同编辑。
原因：数据归类关联与访问权限是两个独立维度，仅添加 trip_id 不能代表用户授权共享历史账单。
处理：明确个人账本只有本人可见；共享账本需要显式选择，并定义成员查看/增改删、创建者管理、退出/删除后的归属。共享方式待用户确认，未发布本轮关联改动。
测试环境：SQLite 不能直接删除仍被外键引用的列，迁移回归应建立旧版空测试表再填入旧记录。迁移末尾 bootstrap 使用全局会话；独立 schema 测试替换 bootstrap，所有测试使用隔离数据库，避免访问生产连接。
最终方案：按用户明确需求，协作成员与行程成员完全独立，采用创建者 + 编辑/只读 ACL，邀请需接受；分享持链登录后确认加入。删除行程不删协作关系，移除账本成员保留 tombstone，避免其靠原分享链接立即重入。
发现并修复：原生 API.request 把 path 作为 URL 路径拼接，不能把 ?refresh=true 拼到 path；账本换算和筛选参数均改用 query 参数，否则问号可能被编码成路径字符。表单 select 用显式可访问名称，避免 option 文案混入控件名称导致读屏/自动化定位不稳定。
