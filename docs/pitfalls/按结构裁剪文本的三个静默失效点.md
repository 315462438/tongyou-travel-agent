# 按结构裁剪文本的三个静默失效点

2026-08-18　Phase 96（工具输出按结构裁剪）

写「按结构裁剪」的 reducer 时踩了三个坑。它们的共同特征是**不抛异常、日志干净、
产出看起来正常**，只是内容悄悄少了或串了。三个都是在**真实页面/真实浏览器快照**上
才暴露的——合成样本一个都测不出来。

## 坑 1：一条 chrome 规则把整个文档吃掉

规则是「class/id 命中 `nav|menu|sidebar|footer|toc|comment…` 就整块丢弃」。看着很安全，
直到遇上维基百科：

```html
<html class="vector-feature-toc-pinned-clientpref-1 vector-feature-...">
```

`-toc-` 命中了规则，于是**整个 `<html>` 被当成导航丢光**，产出为空字符串。

**根因**：根元素（`html`/`body`/`main`/`article`）的 class 是**页面级特性开关**，
跟「这一块是不是导航」毫无关系，不能拿容器规则去套。

**解法**：
1. 维护 `_NEVER_DROP_BY_ATTR = {"html", "body", "main", "article"}`，这些标签永不按属性丢弃；
2. 更重要的是加一道**过度裁剪检测**——裁剪结果若不足朴素提取的 15%，判定为"吃掉了正文"，
   自动退回朴素提取。

第 2 条才是真正的防线：规则清单永远列不全，但"裁完只剩一点点"这个信号是通用的。
它在真实数据上真的救过场——小红书网页版和携程景点页是 JS 空壳，正文全在脚本里，
检测正确触发并退回。

> **凡是"按规则删东西"的代码，都要有一个"删太多了"的自动检测。**
> 规则的白名单/黑名单会漏，比例检测不会。

## 坑 2：裁剪产物再裁一次就被吃光（幂等性）

a11y 快照的 reducer 逻辑是「只取引号里的 label，没有引号的行 = 纯结构节点，丢弃」。
对原始快照完全正确：

```
uid=6_9 link "返回首页" description="..."   → 返回首页
uid=6_13 listitem "" level="1"              → （丢弃）
```

但裁剪后的产物**已经没有引号了**（就是一行行纯文本）。再跑一遍 → 每一行都"没有引号"
→ 全被当成结构节点丢光，只剩两行 markdown 标题。真机数据实测 `reduce(reduce(x))` 只剩 2 行。

链路里会多次截断（Phase 90 立幂等约束就是为这个），所以这是会真实发生的。

**解法**：入口加一道"认不认得"的门——`looks_like_a11y()` 检测 `uid=`/`RootWebArea`，
不认得就**原样返回**。第二遍自然走这条路，幂等成立。

> **"认不得就别动"比"尽量处理"安全。** 误把已处理的产物再处理一遍，
> 是所有管道式文本处理的通用陷阱。

## 坑 3：相邻内联标签的文本被无分隔拼接

用 `HTMLParser` 逐个 `handle_data` 累加文本时，`清除<i>历史</i>记录` 会变成
`清除历史记录`——三个独立 UI 标签粘成一个词。

中文看不出问题（中文本来不用空格分词），但英文会把
`<span>Hotel</span><span>Booking</span>` 粘成 `HotelBooking`。

**解法**：跨内联标签边界时补空格，但**只在两侧都是 ASCII 字母数字时补**。
全补的话 `西<b>湖</b>` 会裂成 `西 湖`，同样是错的。

```python
if self._inline_boundary and self.parts:
    prev = self.parts[-1][-1:]
    nxt = data.lstrip()[:1]
    if prev.isascii() and prev.isalnum() and nxt.isascii() and nxt.isalnum():
        self.parts.append(" ")
```

**这个坑是被测试逼出来的**，而且过程很有意思：用例断言「裁剪产物里的每一段都能在朴素
提取里找到」，报出「裁剪产出了原文里没有的内容：'清除历史记录'」。第一反应是"reducer 在
编造内容"——查下来才发现是拼接，朴素提取用空格替换标签所以是「清除 历史 记录」。

修完测试也要跟着修：不变式的正确表述是**"不新增字符"**（比较时忽略空白），
而不是"逐字匹配"——块级边界把空格换成换行是结构标注，本来就该允许。

## 一般化

三个坑都指向同一件事：

> **文本裁剪的正确性没法靠读代码保证，只能靠真实样本。**

具体做法：
- 真实页面 + **真实浏览器快照**入库当 fixture（快照尤其重要，它复现不了——
  必须起 Chrome 导航再 `take_snapshot`，而页面每天在变）；
- 每个不变式配一条用例，尤其是「不变式被违反时不会报错」的那些（幂等、不吃正文、不编造）；
- 压缩率是**次要**指标。首要指标是"内容还在不在"。
