# 新连接 iPhone 配对成功仍需开发者模式

## 现象

新 USB 手机在 `devicectl list devices` 显示 available，配对成功后，读取应用列表仍报 CoreDeviceError 10005：Developer Mode is disabled。

## 原因

电脑配对、开发者模式和开发签名信任是不同状态。之前另一部手机的信任或开发者模式不适用于新手机；同一局域网还会显示旧手机，不能只凭 available 判断本次安装目标。

## 处理

按 transportType=wired 识别用户本次 USB 目标，完成配对后读取 developerModeStatus。disabled 时，由用户在「设置 → 隐私与安全性 → 开发者模式」开启并按系统提示重启、确认；工具不能代替手机上的系统确认。确认 enabled 后，再查询旧版本、为该 UDID 签名、安装并验证启动。

命令：`xcrun devicectl device info details --device <目标设备 ID> --json-output <结果文件>`。不修改局域网另一部手机、不卸载已有应用。

## 新设备签名与增量构建

开发者模式开启后，原缓存描述文件仍不包含新 UDID；命令行曾返回 `No Accounts`，但 Xcode 设置中有原个人开发账号。打开 Xcode 的 Apple Accounts，刷新原团队资料，在项目里选中新手机，Xcode 自动将其加入描述文件；无需使用朋友的 Apple ID。刷新后的 profile 包含两部手机，2026-10-31 01:44:41 UTC 到期。

第一次后续增量构建虽然 `BUILD SUCCEEDED`，但仅替换了 `embedded.mobileprovision` 和 `Assets.car`，未重新执行 CodeSign，严格验证报 sealed resource invalid。这种构建不能直接安装。应对本任务的隔离 DerivedData 执行 `clean build`，然后再校验版本、描述文件包含目标设备和 `codesign --verify --deep --strict`。
