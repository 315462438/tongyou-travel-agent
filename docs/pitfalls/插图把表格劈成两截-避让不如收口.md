# 踩坑：插图把表格劈成两截 —— 逐点「避让」防不住，要最后统一「收口」

**发现时间**：2026-08-04（评估集第一次干净运行就抓到）
**涉及文件**：`backend/app/agent/orchestrator.py`
**相关**：2026-07-30 修过同一个形态，这次是**复发**

## 现象

evals 的 `check_broken_table` 在多城攻略上报：

```
broken_table: 发现 2 处断裂的表格行：
  ['| 傍晚 17:00-18:30 | **江汉关博物馆**…', '| 晚上 18:00 起 | 开封府出来后…']
```

拉正文一看，Day 1 的行程表长这样：

```
12 | | 时段 | 地点与体验 | 交通与停留 | 参考花费（人均） |
13 | |------|------------|-----------|-----------------|
14 | | 上午/中午 | 各地乘动车抵达**汉口站** … |
15 | | 下午 13:30-15:00 | **黎黄陂路**老街漫步 … |
16 | | 下午 15:00-16:30 | **咸安坊** … |
17-19 | (空行)
20 | ![巴公房子](/travel/api/img?u=…)      ← 插图落在了表格中间
25 | ![咸安坊](/travel/api/img?u=…)
29 | | 傍晚 17:00-18:30 | **江汉关博物馆** … |   ← 孤儿行
30 | | 晚上 19:00 起 | **江汉路步行街** … |
```

表头和分隔行留在上半截，29/30 两行失去上下文 —— GFM 会把它们当**纯文本**渲染，
用户看到一串裸竖线。

## 原因

07-30 那次的修法是**在每个插入点做避让**：`_sub_placeholders_table_safe` 与终稿兜底 1
都会判断 `_is_table_line`，命中表格行就把图片推迟到「表格结束后」再插。

问题在于「表格结束」的判定是**连续性**的 —— 遇到第一个非表格行就认为表格结束了。
而**空行也是非表格行**。只要表格中间出现一个空行（模型自己写的，或上一个插入点留下的），
后半截行就不再被视作同一块，图片正好落进缝里，避让逻辑还以为自己插在了表外。

**逐点避让的通病**：每个插入点都只看得见自己那一次操作，看不见整体结果。
补丁越多，缝越多。

## 解决

不再往避让逻辑里加补丁，改成**最后统一收口**：`_rejoin_split_tables()` 在
`_embed_images` 的全部终稿返回路径上跑一遍，识别

> 表格块 → 空行/图片行/图注 → **没有分隔行的**表格行

这个形态，把中间的图片搬到整张表之后，续行并回表格块。

```python
is_orphan = (
    j < n and j > i and _is_table_line(lines[j])
    and not _TABLE_SEP.match(lines[j].lstrip())          # 自己不是分隔行
    and (j + 1 >= n or not _TABLE_SEP.match(lines[j + 1].lstrip()))  # 下一行也不是
)
```

第二行是 `|---|` 的才是**真的新表格**，不合并。

顺带修掉了另一个成因：模型自己在表格中间写空行 —— 这种情况插入点是无辜的，
逐点避让永远修不了，收口能修。

在真实翻车样本上验证：`broken_table` 2 处 → clean，三张图全部保留，
正文 8324 → 8312 字（只少了那几个空行）。

## 教训

1. **「每个写入点各自避让」是不可靠的模式。** 只要判定依赖上下文连续性，就一定有
   某个别的写入点先把连续性破坏掉。**最后统一收口**（对最终产物做一次结构修复）
   比在 N 个入口打补丁更稳，也更好测。
2. **07-30 修完没留表格回归测试**，所以这次静默复发。`tests/test_images.py` 里
   14 个测试没有一个碰表格。**修完 bug 必须把翻车样本本身钉成测试。**
3. **评估集第一次干净运行就抓到了它。** 这就是它存在的意义 —— 没有它，这个 bug 会
   一直在线上待到某个用户截图反馈。
