## 1. 系统总览

**17同游** 是个人旅行规划平台：用户用自然语言提需求，Agent 驱动真实 Chrome 浏览网页
（必应/携程/高德数据），生成带来源、带配图的攻略/酒店推荐/研究报告，可导出国风路线图海报。

**技术栈**

| 层 | 选型 |
| --- | --- |
| 前端 | React + TypeScript + Vite（Node 23），ChatGPT 式布局，轮询无 WebSocket |
| 后端 | FastAPI（Python 3.12）+ BackgroundTasks |
| 编排 | LangGraph（主流水线，反思循环 + checkpoint）+ deepagents（深度研究模式） |
| LLM | DeepSeek（OpenAI 兼容）：v4-pro 干重活（规划/抽取/生成），v4-flash 干轻活（分类/自检/记忆提炼/路由确认） |
| 浏览器 | chrome-devtools-mcp（stdio）→ CDP → snap Chromium；每用户独立实例+profile 池 |
| 数据 | PostgreSQL 16（业务表 + LangGraph checkpoint 表同库） |
| 外部 API | 高德地图 Web 服务（天气/POI/静态图，数字签名直连） |

## 3. 一条消息的生命周期

```
POST /api/chat/{cid}/messages          (Authorization: Bearer token → get_current_user)
  │  落库 user 消息
  ▼
BackgroundTasks → run_conversation_turn(cid, text, user_id, turn_id)   # 独立线程 + 独立事件循环
  │  _mark_inflight（登记在途 turn，崩溃续跑用）
  ▼
三路路由（Phase 22/23）：resolve_route(text, llm, deep_reasoning开关)
  ├── 开关开 → research（跳过分类；deepagents，见 4.2）
  └── 开关关 → v4-flash 单次分类（~1s；失败/未知一律 guide）
       ├── direct → run_direct_answer（无浏览器：记忆+近5轮 → 单次流式，17-26s，见 4.0）
       ├── 判为 research → direct 快速回答 + 提示卡「建议打开深度推理」（research 不自动触发）
       └── guide  → run_guide_graph（LangGraph 主流水线，见 4.1）
  │
  ▼  全程：progress 消息落库（前端轮询渲染进度气泡）；cancel.check 打点（停止按钮）
终稿 assistant 消息落库（meta: sources/reasoning/memories/poster…）
  │  旁路：记忆提炼（v4-flash 三元组归槽）
  ▼
前端 GET /api/chat/{cid}/messages 轮询（1.5s）→ running 由消息形态推断 → 渲染
```

`running` 判定：有流式 assistant → 运行中；有终稿 assistant 且无流式 → 完成（不能只看最后一条，
反思/海报会在终稿后追加消息——踩过坑）。

## 4. 三条处理链路

### 4.0 轻量直答（direct，Phase 22）

常识/建议/追问/闲聊类问题不需要实时网页数据，跳过整条采集链：
三元组记忆 + 近 `history_rounds` 轮历史 → 单次流式生成（v4-pro，max 2000 tokens）。
无浏览器、无 sources、无 checkpoint；流式占位/停止与 guide 同一套机制；回复后照常提炼记忆。
实测线上首字 6s / 全程 17s（此前同类问题走全量流水线 2-4 分钟）。
prompt 要求涉及时效信息（价格/房态/班次）时注明「可让我联网查询」。

### 4.1 主攻略流水线（LangGraph，Phase 2/3/14/16）

固定形态工作流，适合「单目的地 → 行程/酒店」：

```
parse ──▶ quick_take ──▶ collect ──▶ generate(流式) ──▶ critique ──┬─▶ finalize
 │           │                            (v4-flash │
 │           │                             默认放行) ├─▶ research 补搜 ─▶ generate（≤2轮）
 │           │                                      └─▶ rewrite 重排 ─▶ generate
 │           └── 高德实时数据 + 站点路由(hotel→携程) + 必应搜索抓取
 └── PreferenceNode（目的地/天数/偏好/意图）+ 记忆注入
```

- **快答先行**（2026-08-13，guide 版 Phase 71 机制）：`quick_take` 节点先建流式占位
  （顺序不变式），再用 v4-flash 发 150 字初步规划思路（`meta.preliminary`），
  占位由 generate 复用；apologize/停止必须就地终稿占位防 streaming 残留。
- **checkpoint**：`AsyncPostgresSaver`，thread_id = 用户消息 id；停止=协作式取消
  （`cancel.check` 在搜索/抓取/流式生成打点抛 `TurnCancelled`）；崩溃续跑=启动时
  `resume_inflight_turns()` 从 checkpoint 恢复（仅 10min 内）。
- **流式**：generate 先落 `meta.streaming=true` 的占位消息，每 ~0.5s 增量更新
  （`streaming_flush_interval_s`），前端 800ms 轮询 + 增量合并 + 打字机平滑渲染，终稿去标记。
- **配图**：来源带 `images[]` → 模型用 `[[img:名称]]` 占位 → `_embed_images` 替换+兜底插入，
  图走 `/api/img` 白名单代理（防 SSRF）。
- **多轮修改**：`decide_revision` 判定目的地不变且来源类型覆盖本轮意图 → 复用来源只重新生成。
- **登录墙**：命中时写 `meta.handoff` progress（前端登录卡片），headless 下截图直播扫码
  （`/api/chat/{cid}/handoff-screenshot`），登录成功重开目标页，超时回退必应。

### 4.2 深度研究模式（deepagents，Phase 21）

开放式问题（多城对比/预算测算/签证/帮我选）主流水线接不住（单目的地假设、产出模子固定、
搜索深度固定），路由到自主 agent：

```
create_deep_agent(DeepSeek v4-pro)
 ├── 主 agent 工具箱：web_search / open_page（浏览器）+ write_todos + task
 │      浏览器经 BrowserSession(actor)：专职 worker task 独占 ChromeMCP 生命周期，
 │      工具经 asyncio.Queue 提交（MCP stdio_client 是 task-affine 的，跨 task 进出
 │      会炸 anyio cancel scope 且泄漏池槽位——线上踩坑）
 └── subagent "api-researcher" 工具箱：amap_city_brief / amap_poi / fetch_url（纯 API）
        task 工具派生：fresh context、只见任务指令、跑完返回一份压缩报告即销毁
        → 上下文隔离（网页原文只留在子 agent 窗口）+ 资源硬隔离（工具箱里没有浏览器）
```

- **资源纪律写进 system_prompt（硬规则）**：天气/景点必须派高德子任务；web_search 全程 ≤3 次；
  URL 整批交子任务 fetch_url，open_page 只兜底。（软建议对弱模型无效——踩坑）
- 停止：工具内 `cancel.check` + `_invoke_with_cancel` 秒级看护双保险；整轮 600s 超时。
- 单轮无状态（不接 checkpoint）；产出带来源的 Markdown 研究报告。

#### 4.2.1 技能体系（deepagents Skills，Phase 26/27/27b）

`create_deep_agent(skills=[...])`：主 agent 挂内置 `/main/`（对比方法论/预算测算/签证
政策求证）+ 用户私有 `/user/`；`api-researcher` subagent 挂内置 `/researcher/`
（高德组合用法/网页抓取取舍）。技能正文以 SKILL.md 存在仓库（`app/agent/skills/`），
运行时经 `skills_loader.load_skill_files(user_id)` 读盘/查库一次转成 `FileData`，
经 `agent.ainvoke(files=...)` 种进默认 `StateBackend()`（ephemeral、per-invoke、
零新故障面——没有换成 `FilesystemBackend`，见踩坑索引）。

**主/子 agent 的 skills 各管各的，不会互相继承**：`skills` 参数只作用于挂它的那个
agent；自定义 subagent 不写 `skills` 就完全没有技能库，不会隐式拿到主 agent 那份。
唯一例外是 deepagents **自动挂载的内置 `general-purpose` subagent**——只要
`subagents` 列表里没有同名项，框架就会自动插入一个，且默认继承主 agent 的
`tools`（含浏览器！）和 `skills`，却用框架自带通用 prompt、不含项目自己的资源纪律。
本项目在 `subagents=[...]` 里显式声明了一个同名 `"general-purpose"` 条目
（`GENERAL_PURPOSE_PROMPT`）覆盖默认版本，把"浏览器全局共享、能不用就不用"这条纪律
也写了进去——见踩坑索引。

用户上传技能（`travel_user_skill` 表，`/api/skills` 增删查）**仅本人可见**：上传时用
deepagents 自带 frontmatter 解析器校验（复用 Phase 26 已验证过的解析路径）。支持
纯文本粘贴（单个 SKILL.md）或 zip 打包上传多文件（SKILL.md + references/scripts，
`POST /api/skills/upload`，`files_json` 列存 `{相对路径: 内容}`，zip 解析有
zip-slip 路径逃逸防护——见踩坑索引）。技能发现追踪不引入新 vendor——详细调用链复用
已有自托管 Langfuse（Phase 24），只额外从本轮 `read_file` 工具调用里提炼出
`meta.skills_used`（产品可见的轻量汇总）。

**代码执行**：曾评估给 agent 接 Cube Sandbox，排查服务器硬件后发现内存/CPU/KVM/磁盘
文件系统都够不到官方最低要求、安装还要换内核重启生产机，用户拍板不部署、代码已移除
（`task_plan-phase27-用户技能上传与cube沙箱执行.md`）。改用服务器已装的 **Docker**
做轻量沙箱（`app/tools/docker_sandbox.py::DockerSandboxBackend`，默认关，
`docker_sandbox_enabled`）：开启时 `backend` 是**单一** `DockerSandboxBackend`
（`FilesystemBackend(virtual_mode=True)` + `execute()` 起一次性加固容器
`--network=none --read-only --cap-drop=ALL --user nobody` 等），技能文件在轮初就
物理写进这个 per-turn host 临时目录（`_write_skill_files_to_dir`），不再用
`CompositeBackend` 包一层——最初的方案是三个路由（`/main/` `/researcher/` `/user/`）
共享一个 `StateBackend()` 实例，线上实测 `docker_sandbox_enabled=true` 时会让
`glob`/`ls` 聚合逻辑对路径二次拼前缀（`/main/main/xxx/SKILL.md` 这种错乱路径，还污染了
`meta.skills_used`），改成单一 backend 后没有多路由聚合，问题消失，见踩坑索引。
明确告知这是共享宿主内核的隔离，不是 VM 级边界，权衡见
`task_plan-phase27b-zip技能包与docker沙箱.md`。

**页面开关 + 产物展示（Phase 27c）**：沙箱能力生效需要**服务器开关**
（`docker_sandbox_enabled`，运维决定这台机器具不具备这个能力）**和每条消息一个的
`sandbox_enabled`**（仿「🧠 深度推理」胶囊，`SendMessageRequest` → `run_conversation_turn`
→ `run_deep_research` 原样穿透）同时为真才生效。沙箱镜像换成自定义的
`travel-sandbox:latest`（`backend/docker/sandbox/`，预装 python-pptx/python-docx/
openpyxl/reportlab/matplotlib 等——运行时 `--network=none` 装不上任何依赖，必须在构建期
就装好）。轮末 diff 沙箱临时目录跟"技能文件种子基线"，多出来的文件当产物拷进
`sandbox_artifacts_dir/{batch_key}/`（懒清理：写新产物前先扫一遍删过期的，
`sandbox_artifacts_ttl_min` 默认 30 分钟），元信息写进 `meta.artifacts`，前端
`SandboxArtifacts` 组件渲染下载链接（图片内联预览）。下载端点 `/api/sandbox-artifacts/
{batch_key}/{filename}` 沿用 `/api/img` 那套不鉴权+不可猜测 ID 的信任模型，另加显式
路径穿越校验。

### 4.3 手账海报（Phase 13/18）

攻略消息 →「🎨 生成手账海报」→ `poster.py` 后台：LLM 抽 `PosterData`（点位/路线名/
酒店/美食/特产/贴士）→ 高德限流并发补坐标+实景图（Semaphore(4)+CUQPS 退避）→

html2canvas 导出长图。高德静态图 marker 上限≈10 → 逐天出图。

## 5. 核心子系统

### 5.1 浏览器自动化栈（自下而上）

| 层 | 模块 | 职责 |
| --- | --- | --- |
| 浏览器池 | `tools/browser_pool.py` | 每 user_id 独立 Chrome+持久 profile（各自扫码、登录互不覆盖）；`acquire` 按需拉起/复用/LRU 驱逐/排队（on_wait 写「排队中」）；空闲 reaper；上限 2（内存约束） |
| MCP 连接 | `tools/mcp_client.py` | stdio 起 chrome-devtools-mcp（锁 0.6.0）连 CDP；45s 超时 + 三层自愈（重连→池模式重拉该用户 Chrome）；`isError` 必须抛异常 |
| 浏览器工具 | `tools/browser_tool.py` | snapshot 两步交互、礼貌限速、页面预算、必应搜索（evaluate_script 读 DOM） |
| 动作守卫 | `agent/action_guard.py` | 三层判定：动作分层（navigate/snapshot 永远放行）→ 元素判定 → 页面类型检测；所有 click/fill 必须过守卫 |
| 站点路由 | `agent/site_router.py` | 意图→站点（hotel→携程）；携程城市 ID 三级解析（静态表→DB 缓存→页面内直调建议接口）；登录墙 handoff |

### 5.2 LLM 层（`llm/client.py`）

- `parse()` 结构化抽取（Pydantic schema，重试）／`classify()` = parse 用 v4-flash／
  `generate_with_reasoning()` 返回正文+思考／流式生成。
- 不变式：封装不透传 temperature 等采样参数；结构化输出必须走 parse() 而非裸 prompt。

### 5.3 记忆系统（Phase 4/17/20）

- **三元组归槽**：每条记忆挂规范 `key`（口味/兴趣/节奏/预算/住宿/出行/常驻城市/忌口/同行/
  当前行程），**每 (user_id, key) 只留一条**——相同 key 覆盖、近义由 LLM 归同 key 合并、
  时间新者胜、`explicit`（亲述）权重 2.0 且粘性；「当前行程」单槽不堆积；上限 40 兜底剪枝。
- **历史会话引用**：只引标题命中当前目的地的旧会话，跳过停止/海报/流式/过短回复，摘录去 markdown。
- 每轮回复后旁路 v4-flash 提炼（add/update/delete 对照已有记忆）；`consolidate_memories`
  一键把存量脏记忆重写成规范三元组（前端「✨ 整理记忆」）。
- 注入点：需求解析 + 攻略生成；全量注入无向量库（个人量级）。

### 5.4 用户与鉴权（Phase 15）

- `TravelUser`/`TravelSession`（pbkdf2 密码、Bearer token，纯 stdlib）；所有业务路由过
  `get_current_user`；会话/记忆/站点登录/浏览器 profile 全部按 user_id 隔离。
- admin 引导账号拥有旧数据 + `/api/admin/users`。
- 例外：`/api/img`、`/api/staticmap`、handoff-screenshot **不鉴权**（<img> 带不了 header，
  cid 不可猜）。

### 5.5 高德工具（`tools/amap.py`）

httpx 直连 + 数字签名（字典序 k=v& + secret 取 MD5）；天气预报/POI/地理编码/静态地图；
CUQPS 限流退避重试；静态图经 `/api/staticmap` 后端代签（key 不进前端）。

### 5.6 目的地社交（Phase 81）

- `api/social_api.py` 提供目的地接力、公开主页与好友状态机；全部要求登录，响应按字段白名单组装；
- 好友和私密行程成员完全独立，成为好友不会获得会话、记忆或行程权限；
- 接力按目的地、旅行阶段和类型组织，现场情报 72 小时过期；反馈为每人每帖单选；
- 私密主页作者的接力正文和聚合统计同时隐藏；私密主页只有本人或已接受好友可见；
- 头像复用上传表，资料保存时校验上传归属；前端 `SocialHub` 懒加载，避免拉大首屏主包。
- Phase 82 交互层支持输入任意目的地；固定目的地仅为快捷建议。发布器用三种用户动作自动映射
  `phase/kind`，不把内部数据字段直接暴露成两套选择器。
- Phase 83 复用 onboarding 的近 30 天真实热问榜与高德封面，推荐卡先于搜索展示；顶部动态背景
  复用 React Bits Aurora，搜索框使用容器焦点效果并完整清除原生 input 外观。
- 社交界面统一可读字号基线：说明/时间/标签 ≥11px，按钮/筛选 ≥12px，正文 ≥14px；层级主要依赖
  字重、色彩和留白，不再依赖 7.5–10px 小字。
- Phase 84 的 `api/notification_api.py` 把好友申请、好友接受、接力反馈投影成按用户隔离的持久化
  通知；写入只 flush、跟随原业务事务 commit。稳定事件键负责更新/撤销，避免切换反馈制造重复提醒。
  前端铃铛把社交未读与平台公告合并，点击通知直达好友页或对应目的地接力站。

## 6. 数据模型（主要表）

## 8. 并发模型

- **每轮对话 = 独立线程 + 独立事件循环**（BackgroundTasks → 线程池 → `asyncio.run`），
  不同用户的 LLM 调用/生成天然并行。
- **浏览器是唯一串行点**：池模式下同用户串行（busy 语义）、不同用户并行 ≤2；
  排队时写「前面还有 N 个任务」提示。本地开发退化为进程级全局锁。
- DB 连接池 pool_size=5+overflow；单 uvicorn 进程（进程级锁才有效，勿加 --workers）。

## 9. 关键不变式

1. 所有 click/fill 必须过 Action Guard；navigate/snapshot 等只读动作永远放行。
2. MCP 工具返回 `isError` 必须抛异常，不能当正常结果。
3. LLM 封装不透传采样参数；结构化输出走 `parse()`。
4. MCP/anyio 资源 **task-affine**：跨 task 共享必须包 actor（专职 task 独占生命周期）。
5. `running` 判定看「流式/终稿消息形态」，不能看最后一条消息。
6. img/staticmap/handoff-screenshot 保持不鉴权；其余路由必须过 get_current_user。
7. 浏览器会话内不要调 `_expire_stale_logins`（可能重启 Chrome）；池模式不清 cookie。
8. 高德并发必须限流（Semaphore≤4 + CUQPS 退避）；静态图单张 ≤10 个 marker。
9. agent 的资源预算写硬规则（最多 N 次）不写软建议。
10. 通知写入必须与好友/接力业务同事务，并用稳定业务事件键去重；目标删除或动作撤销时同步清理。
