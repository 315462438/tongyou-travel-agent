注意这是共享正式数据，朋友的增删改都是实际业务操作，不是虚构沙箱。

每次安卓发布
1. 确定该次前端快照范围，检查 git diff；递增 versionCode，按需调整 versionName。
2. 跑 Android 单测、lint、浏览器契约测试、设备测试；确认 Web 回归通过。
3. 使用同一私有 release key 构建；不更换 key、不修改 applicationId。
4. package-release.py 校验包名、debuggable、签名、快照文件 hash。
5. 保留版本化 APK、release.json、signature.txt、SHA256SUMS、安装说明。
6. 对同签名 APK 做覆盖安装检查后再发给测试者；无需先卸载。

后端变更需保持已发布 iOS/Android 所用 API 兼容。若必须破坏兼容，先制定多版本迁移方案。
不要用统一的“当前 App 版本”字段代替三端独立版本记录。
签名密钥由开发者私有目录管理，说明见 android/README.txt；不得放入 release 分享目录。
