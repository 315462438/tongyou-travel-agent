# 17同游首页增长与视觉优化复盘

时间：2026-08-07  
线上地址：https://17tongyou.com/travel/

## 一、这轮优化要解决什么

平台的攻略生成、预算、海报和协同行程已经比较完整，但新用户进入首页后的第一感受仍然偏弱：

1. 首屏像普通后台表单，没有足够的旅行向往感；
2. 一度把“旅行预演、收藏整理、预算推荐”做成三个并列入口，用户需要先理解产品分类；
3. 合并入口后又保留了“自由提问”第二输入框，名义上是单入口，实际仍让用户犹豫；
4. 纯光效虽然醒目，但没有真实旅行内容，容易显得花哨；
5. 新增推荐卡后，低高度桌面视口里卡片全部落在首屏以下，用户不一定知道还有内容。

最终目标不是继续堆功能，而是让用户进入页面后能立刻完成两件事：**产生出发欲望，并敢于输入第一句话。**

---

## 二、最终产品结构

### 1. 首页只保留一个主入口

唯一输入框同时支持目的地、自然语言问题和攻略分享文本，系统在背后自动分流：

| 用户输入 | 自动处理 |
| --- | --- |
| 包含公开 HTTP(S) 链接 | 提取最多 5 条链接，进入收藏/攻略整理，并直接启用深度推理 |
| 主输入为空，但填写了出发地和预算 | 反推 3 个候选目的地，并给首选方案和费用口径 |
| “阿勒泰”“马来西亚”等纯短地名 | 生成旅行预演：逐日时间轴、交通、体力、预算、风险和备选 |
| “第一次去日本怎么准备？”等完整问题 | 原样交给后端 `direct / guide / research` 路由 |

关键点：**不再暴露三个 tab，也不再出现第二个自由提问 Composer。**用户只需要表达旅行念头，不需要理解平台内部能力。

### 2. 轻约束仍留在主输入下方

保留四个可选字段：出发地、天数、预算、节奏。它们只用于补充信息，不强制填写：

- 出发地可从用户“常驻城市”记忆中补空值，但不能覆盖用户已输入内容；
- 天数默认 3 天；
- 预算只接受数字；
- 节奏提供“松弛一点、张弛有度、尽量多玩、早上不要赶”。

### 3. 主输入下增加真实热门目的地图片卡

卡片不是写死的“成都示例”，而是平台近 30 天真实用户问得最多的目的地：

- 按 `travel_conversation.destination` 的会话次数排序；
- 排除 admin、evalbot、test 等内部账号；
- 多城目的地只取首城；
- “平潭岛 / 福建平潭岛”等包含关系保留更短、可读性更好的名称；
- 首屏最多展示 4 张；无数据时才回退杭州、平潭岛、武功山、武汉。

点击卡片只把目的地回填到唯一输入框，不立即发送。用户可以继续补充预算、天数和节奏，避免“误触即开跑”。

## 三、视觉规范

### 1. 标题

- 文案：**“想去哪儿，就从这里出发”**；
- 字体栈：`PingFang SC / Noto Sans CJK SC / Microsoft YaHei / system-ui`；
- 字重：800，保持中文粗黑的力量感；
- 使用深蓝—靛紫—玫紫多节点连续渐变；
- 9 秒缓慢往返移动，避免早期“左红右蓝”的硬断层；
- `prefers-reduced-motion` 下停止动画，固定在中间渐变位置。

副标题保持稳定灰色，不与标题一起变色，保证阅读层级。

### 2. 背景柔光

顶部采用局部蓝—紫—粉三点径向柔光，而不是覆盖半屏的高饱和 Aurora：

- 柔光只服务于标题和主输入区域；
- 10 秒极慢呼吸缩放；
- 页面主体仍然保持白色和充足留白；
- 减少动态效果模式下自动静止。

### 3. 主输入面板

- 常态即显示蓝紫描边，不依赖获得焦点才出现；
- 使用轻微外发光、柔和投影和顶部内高光；
- 背景接近纯白，仅在右上角保留极淡冷色径向层；
- 聚焦时只小幅增强边框和光圈，避免整个面板突然跳动；
- 压缩 textarea、约束栏和底栏的空白，让图片卡区域在低高度桌面首屏底部露出。

### 4. 热门目的地卡片

- 桌面端四列；移动端横向滚动并启用 scroll snap；
- 封面使用高德真实景点 POI 图片，经 `/api/img` 同源代理；
- 卡片展示 TOP 排名、目的地、轻描述和“带入规划”；
- 图片失败时显示四套低饱和品牌渐变和旅行 emoji，不出现破图；
- 悬浮只有 4px 上移和轻微图片放大；低动态模式全部关闭。

## 四、封面数据与稳定性设计

热门排名和图片获取拆成两条链路：

1. `/api/onboarding` 快速返回常驻城市、热门地名和历史标记；
2. `/api/onboarding/covers` 再异步为前 4 个目的地补图。

这样做是为了避免第三方图片 API 抖动拖慢整个首页。封面接口的约束：

- 最多接受 4 个清洗、去重后的地名；
- 高德请求并发上限为 2；
- 成功图片缓存 24 小时；
- 空结果缓存 1 小时，防止失败时反复打 API；
- 单个城市失败只返回空值，不影响其他城市；
- 前端始终有占位层，图片是增强项而不是首屏依赖。

## 五、几次迭代得到的结论

### 结论 1：功能分类不等于用户入口

旅行预演、收藏整理和预算推荐在内部确实是三种任务，但用户没有必要先选模式。入口应按“用户怎么表达”设计，分类留给系统。

### 结论 2：单入口不能残留第二个输入框

即使第二个输入框默认折叠，展开后仍会造成“应该在哪问”的选择成本。普通问题也必须由同一个 textarea 接住。

### 结论 3：吸引力主要来自内容，不是光效数量

大面积 Aurora、渐变标题、模式色和玻璃卡同时出现时会互相争夺注意力。真实目的地、实景图片和社会证明比继续叠加动画更有效。

### 结论 4：视觉元素要有固定角色

- 标题颜色波动负责品牌感；
- 背景柔光负责氛围；
- 输入框光边负责聚焦操作；
- 图片卡负责旅行向往和探索。

同一种效果不应在多个区域重复使用。

### 结论 5：首屏折叠线也是产品信息

推荐卡全部藏在首屏以下，相当于功能不存在。无需把所有卡片塞进首屏，但至少要露出区块标题或封面上沿，形成继续向下探索的提示。

## 六、技术落点

### 前端

- `frontend/src/pages/Home.tsx`：唯一入口、自动分流、封面加载、热门图片卡；
- `frontend/src/interaction.ts`：prompt builder、URL 提取、短地名识别、热门卡数据构造；
- `frontend/src/index.css`：标题渐变波动、局部柔光、输入框光边、卡片和移动端布局；
- `frontend/tests/interaction-utils.test.mjs`：分流和热门数据纯函数；
- `frontend/tests/visual-regressions.test.mjs`：单入口、卡片、光效、响应式和 reduced-motion 契约。

### 后端

- `backend/app/api/onboarding_api.py`：真实热门榜和封面批量接口；
- `backend/app/tools/amap.py`：目的地景点封面查询；
- `backend/app/api/img_api.py`：高德图片同源代理和域名白名单；
- `backend/tests/test_onboarding_api.py`：热门去重、内部账号排除、封面清洗、异常和缓存。

## 八、后续建议与衡量指标

后续不要再凭“好不好看”单点判断，建议至少观察一周：

| 指标 | 用途 |
| --- | --- |
| 注册后首次提问率 | 判断新首页是否真正降低开口门槛 |
| 热门卡曝光 → 点击率 | 判断图片卡是否产生探索欲 |
| 卡片点击 → 最终发送率 | 判断“回填而不立即发送”是否合理 |
| 各自动分流路径占比 | 判断链接整理、预算推荐和普通问答的真实需求结构 |
| 首次提问平均字数 | 判断用户是否更愿意自然表达，而不是只点模板 |
| 封面成功率与接口耗时 | 判断高德图片增强是否稳定 |
| 首轮生成中途退出率 | 与思考工作台、预计时长一起判断等待体验 |

下一阶段优先级建议：

1. 给卡片点击、回填和发送补埋点，建立真实转化漏斗；
2. 有足够样本后对“3 张大卡 vs 4 张小卡”做 A/B 测试；
3. 在平台热门基础上加入用户常驻城市、季节和历史偏好的轻量重排；
4. 保持唯一输入不变，不再新增平行入口；
5. 所有视觉调整继续遵守 reduced-motion 和移动端横滑契约。
