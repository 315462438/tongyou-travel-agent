# 多目的地/多方案对比

## 何时使用
用户的问题包含"哪个更好/更适合/选哪个/对比一下"这类比较意图，且涉及 2 个及以上候选
（城市、路线、季节、酒店档次等）。

## 对比维度（按需增删，不要全部堆上去）
根据用户提到的关切筛选，通常覆盖：
- **契合度**：与用户明确需求的匹配（亲子/蜜月/避暑/小众/美食……）
- **成本**：机票/住宿/日均花费的量级差异（不需要精确到个位数，量级对比即可）
- **气候适配**：出行时间段该地的天气是否合适（用高德天气数据核实，不要凭经验拍）
- **交通便利度**：往返 + 市内交通的方便程度
- **时间利用率**：给定天数下能否玩得不赶

## 输出结构
1. 开头一句话结论（不要卖关子，先说观点再展开）
2. **必须有对比表格**：行=维度，列=候选项，每格给结论性短语而非长句
3. 表格之后按维度展开 1-2 句说明，只展开用户可能追问的点
4. 结尾给明确建议（"更推荐 X，除非你更看重 Y 那选 Z"），不要各打五十大板

## 常见坑
- 只对比了用户提到的城市，漏掉用户暗示的隐含维度（比如提到"带娃"但没对比亲子设施）
- 表格维度和正文展开重复啰嗦——表格给结论，正文给理由，分工清楚
- 三个以上候选时表格会很宽：优先横向压缩用词，而不是砍维度
