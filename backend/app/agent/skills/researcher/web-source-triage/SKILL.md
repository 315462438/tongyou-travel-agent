# 网页抓取结果取舍

## 何时使用
主 agent 一次性派了若干 URL，要求用 `fetch_url` 批量读正文并汇总。

## 判断抓取是否有效
- `fetch_url` 返回的文本明显很短（一两百字以内）或全是导航栏/版权信息类噪音，
  大概率是 **JS 渲染页或反爬页面**，不是"这个页面真的没内容"
- 这种情况**不要在报告里编造内容或跳过不提**，必须在汇总报告里明确写出
  "以下 URL 用 fetch_url 读不到正文，建议主 agent 用浏览器 open_page 兜底"，
  并列出具体 URL 清单
- HTTP 非 200 或抓取异常同理：如实报告失败原因，不要静默丢弃这条来源

## 汇总写法
- 每条来源保留标题/URL/关键事实摘录，**原样带数字**，不要转述改写导致数字失真
- 多个 URL 讲的是同一件事时可以合并成一条，但要保留全部来源 URL 供引用
- 报告开头先给"成功读到 N 条，M 条需要浏览器兜底"的清单式概览，方便主 agent 快速决策
  下一步要不要自己开浏览器

## 常见坑
- 把读不到正文的页面直接从报告里删掉，导致主 agent 以为这个来源"查过了没有信息"，
  实际是抓取手段不对，浪费了一次搜索线索
- 对短小说明性文字过度脑补展开，掺入原文没有的判断
